# 发布溯源与标签策略

> 最后更新：2026-10-21
> 适用分支：`beta/0.6.0`

## 一、为什么需要这份规则

历史远端状态曾经出现：

- 本地分支领先远端 72 个提交；
- `beta.11` 至 `beta.23` 的多个 tag 全部指向同一个旧提交；
- Release 资产可以下载，但 tag 无法复现对应源码。

因此，tag 不能只代表“曾经上传过某个安装包”，必须同时满足：

1. tag 指向的提交可 checkout；
2. 该提交的 `app/package.json` 版本与 tag 一致；
3. tag 对应提交已存在于远端默认分支；
4. Release 的安装包 SHA-256 写入说明；
5. 自动化脚本在发布前主动拒绝脏工作区、未推送提交和错误 tag。

## 二、beta.24 之后的正确规则

从 `v0.6.0-beta.24` 开始：

- tag 使用 annotated tag；
- tag 指向“该版本最后一次修改 `app/package.json` 的有效提交”；
- 发布前必须把分支和 tag 都推送；
- GitHub Release 必须绑定该 tag；
- `beta.yml` 中的安装包路径必须与 GitHub 资产名一致。

## 三、历史 tag 处理

`v0.6.0-beta.5` 至 `v0.6.0-beta.7`、`v0.6.0-beta.11` 至 `v0.6.0-beta.23` 的远端旧 tag 保留为历史证据，不静默强推覆盖。它们被标记为 **legacy tags**，不应用于源码复现。

从 beta.24 起使用准确 tag。`v0.6.0-beta.40` 是当前可复现基线。

## 四、远端当前落地状态

| 项 | 当前事实 |
| --- | --- |
| 本地 CI 实现提交 | `ab19a3404e100ff3f9a82666b4ff5aa08aa39d84` |
| beta.40 发布源码 | `762724c84addcd999a86c0385aefbd7db7a37f84` |
| CI 实现内容 tree | `6bac070abf53e8862319595c9c6d93dce731e9f2` |
| 实时分支 head | 用 `gh api repos/Bill-H9986/jco/git/ref/heads/beta/0.6.0` 查询 |
| beta.40 tag object | `9013693076cfae1f99e3839c38184f40be7e521f` |
| Release | <https://github.com/Bill-H9986/jco/releases/tag/v0.6.0-beta.40> |

提交对象不同是 GitHub token 对 workflow 文件更新权限不完整导致的兼容 wrapper：先同步源码，再用 API 恢复 `quality.yml` 和 `release.yml`。两边 tree 相同，表示文件内容一致，不代表提交 SHA 相同。

当前本机直连 `github.com` 的 Git 协议会被连接重置。恢复顺序：

1. 下载 Release 中的 `jco-full-history.bundle`，`git clone` 本地 bundle；
2. 或用 `J.Co-0.6.0-beta.40-source.zip` 核对只读源码；
3. 线上小改动用 GitHub API；
4. 常规构建 / 发布用 GitHub Actions；
5. 网络恢复后再 `git fetch origin`，把本地分支和远端 wrapper 正常合并，不伪造同一 SHA。

根目录 `release-feed/beta.yml` 属于 **AtomGit 专用通道**，停在最后一次实际 AtomGit 镜像 `beta.10`。GitHub 通道的 `beta.yml` 是 Release 资产，当前为 `beta.40`。

## 五、发布前门禁

```powershell
Set-Location app
node scripts/verify-release-provenance.mjs `
  --tag v0.6.0-beta.40 `
  --require-origin
npm run gate
npm run release:github
```

`release:github` 会再次执行发布溯源检查，不允许：

- 工作区有未提交改动；
- tag 不存在或 tag 不指向 HEAD；
- tag 版本与 `package.json` 不一致；
- HEAD 不在远端 branch 上；
- 缺少安装包、blockmap 或更新通道 yml。

## 六、回滚

- 上一版本安装包与哈希：见 `app/CHANGELOG.md` 和本地回滚说明。
- 源码回滚：checkout 准确的 beta tag。
- 用户数据：先备份 `%APPDATA%\J.Co`，安装版回滚不清空用户数据。
- 若 tag 与 package version 不一致，先修 tag 规则，不发布。
