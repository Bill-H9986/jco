# 知识库企业规模与飞书接入方案

- 日期：2026-10-19
- 状态：方案冻结，待 W9 施工
- 关联：W8-01 业务档案 + AI 总管自动记忆

## 一、先纠正一个边界

当前代码里的“100 条”不是企业知识库上限，而是 **提示词直注入的临时预算**。它现在同时限制了存储和界面，这是不对的：

- 企业可能有数万篇产品资料、SOP、平台规则、历史运营记录；
- 模型一次不可能读完，也不应该读完；
- 正确做法是“全量存储 + 检索 Top-K + 提示词预算”，不是“只存 100 条”。

## 二、目标架构

```text
飞书文档 / 本地文件 / 任务结果
        │ 增量同步、权限、删除事件
        ▼
KnowledgeRepository（本地 SQLite / JSONL 兼容层）
        │ 分块、去重、来源、ACL、软删除
        ▼
Retriever（FTS5 trigram / 中文 bigram / 可选向量）
        │ 每次任务只取相关 Top-K
        ▼
PromptBuilder（8k 上下文预算）
```

### 1. 存储

- 知识条目不再塞进 `brand-profile.json`；品牌档案只保留行业、业务、产品、受众等轻量字段。
- 独立 `knowledge` 存储，字段至少包含：`id`、`workspaceId`、`title`、`content`、`tags`、`source`、`sourceTaskId`、`checksum`、`createdAt`、`updatedAt`、`deletedAt`。
- 本地优先使用 SQLite（FTS5 trigram 对中文子串检索可用）；没有原生模块时保留 JSONL 兼容实现。
- 写入去重、软删除、备份、迁移；用户删除后不再进入检索。

### 2. 检索

- 文档按段落/语义块切分，单块建议 500–1000 字；
- 中文先做 bigram/trigram 倒排，后续可加 embedding 混合排序；
- 每次聊天/任务按当前目标取 Top-K（默认 8–12 块），再受 8000 字提示词预算约束；
- 结果带来源、更新时间、可信度；外部资料明确标记为“资料”，不是指令。

### 3. 飞书连接器

飞书适合做**外部知识源**，不适合被当成唯一数据库：

- 通过飞书应用凭证和只读权限同步文档、知识库、云空间目录；
- 保存增量游标，处理新增、修改、删除、权限变更；
- 企业版按 `workspaceId` 隔离，不把一个客户的知识注入另一个客户；
- 飞书不可用或接口限流时，本地索引仍可检索；
- 只把命中块送入模型，不把整个企业文档库塞进提示词。

### 4. AOCI 式语义索引（重点）

你提到的抖音视频对应的是 AOCI / AOCI-CODE。它的关键方法不是“把原文压成很小的文件”，而是给每个代码/文档对象建立一条紧凑的 **FRAS 语义认知**：

- **F**：它负责什么；
- **R**：理解或修改它时还必须关注什么；
- **A**：它对外提供哪些接口、字段或可观察契约；
- **S**：不能破坏的约束、例外和边界。

这套方法可以借鉴到知识库，但边界必须说清楚：

- **索引可以很小**：一篇文章/一个知识块只保留标题、摘要、主题、强关联、来源 ID、权限和内容哈希；
- **原文不能凭空消失**：要准确回答引用、数字、条款，仍要保留原文或按需从飞书/本地读取对应块；
- **飞书在线模式**：本地只存索引和热缓存，原文按需拉取，磁盘占用最小；
- **离线模式**：保留全文压缩包 + 索引，体积比纯索引大，但不牺牲准确性；
- **推荐混合模式**：本地索引常驻，常用原文缓存，冷门原文回源飞书。

因此“用极少空间存大量内容”可以实现为：**小索引 + 远程原文 + 按需检索**，而不是把几十 GB 文档压成几 MB 还保证原文可回读。J.Co 不直接打包 AOCI 二进制（其许可证对竞争性商业产品有限制），只实现同类的自有 FRAS 索引和治理规则。

## 三、W9 施工拆分

| ID | 层 | 工作单元 | 依赖 | 验收 |
|---|---|---|---|---|
| W9-01 | Data/UI | 知识全量存储 + 分页/搜索 + 移除 100 条硬上限 | W8-01 | 1 万条导入不丢；列表分页；删除/恢复；JSON 兼容迁移 |
| W9-02 | Kernel/Data | 中文检索 Top-K + 提示词预算 | W9-01 | 相关条目命中；提示词不超预算；无关条目不注入 |
| W9-03 | Connector | 飞书文档/知识库只读增量同步 | W9-01 | 新增/修改/删除/权限/游标；断网不影响本地检索 |
| W9-04 | Security/Ops | 企业空间隔离、ACL、审计、保留期、导出/彻底删除 | W9-02/03 | 跨空间不可见；操作可审计；删除可证明 |

## 四、结论

飞书可以接，但应该是“连接器 + 本地索引”，不是把飞书当提示词库。先做 W9-01/W9-02，把存储、FRAS 索引和检索分开；飞书连接器需要用户提供飞书应用凭证和权限清单后再做 W9-03。
