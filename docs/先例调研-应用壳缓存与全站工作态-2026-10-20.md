# 先例调研：应用壳缓存、固定页头与全站工作态

> 日期：2026-10-20
> 触发问题：切页明显加载卡顿、返回页面丢失输入和进行中的工作、页头随内容滚走、开关和焦点规格不统一。

## 一、找什么

1. 单页应用外壳如何避免每次切页都重新加载子文档。
2. 内容滚动时，页头如何稳定停在视口顶部。
3. 隐藏页面和后台任务分别应该由谁保存状态。
4. 同一份共享草稿层如何在不侵入业务数据的前提下，恢复普通输入。

## 二、查到的资料

| 资料 | 关键事实 | 对本项目的意义 |
|---|---|---|
| [MDN: iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) | iframe 会创建独立的 browsing context，并在其中嵌入另一份文档。 | 直接修改 `src` 会换掉整份子文档，页面脚本、DOM、输入和滚动位置都会重新初始化。 |
| [MDN: postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) | `postMessage` 是窗口之间传递消息的标准接口。 | 复用总管 iframe 后，用页内消息切换会话，不再用查询参数重载整页。 |
| [MDN: position](https://developer.mozilla.org/en-US/docs/Web/CSS/position) | `sticky` 相对最近的滚动祖先和滚动容器计算偏移。 | 页头应放在 `.scroll` 内设置 `top: 0`，不能把滚动容器写错或让祖先裁剪它。 |
| [MDN: Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API) | 文档隐藏后浏览器可能节流计时器；页面可见性由 `visibilitychange` 和 `document.hidden` 暴露。 | 页面缓存只解决 DOM 和视图状态，长时间生成仍应由主进程任务承担。 |
| [Electron: webContents](https://www.electronjs.org/docs/latest/api/web-contents) | Electron 提供 `did-finish-load`、`isLoading()`、`backgroundThrottling` 等生命周期与节流控制能力。 | 不能把“隐藏 iframe 仍能跑页面内长任务”当成可靠承诺，后台生成继续走 Beta.25 已有的 `media-jobs`。 |

## 三、采用的方案

### 1. iframe 页面缓存

- 应用壳按页面路径缓存子文档，活动页只保留一个 `#jcoFrame` 标识；缓存页保留 DOM、输入、滚动和页面内事件。
- 上限 16 份，覆盖当前 15 个稳定页面；超出后才按最近使用顺序淘汰，首页与总管不优先淘汰。
- 非活动页用 `visibility: hidden` 隐藏，让其继续保留布局与文档状态，同时不接收指针事件。
- 只有第一次访问显示加载遮罩；复访直接切换可见页，不重新加载字体、脚本和页面资源。

### 2. 总管页内导航

- 总管 iframe 只加载一次。
- 首页发送、侧栏新会话、会话路由都通过 `postMessage` 调用总管页已有的 `newChat()` / `switchChat()`，避免同一页面产生多份缓存和未发送草稿丢失。

### 3. 固定页头

- 共享样式只改 `设计原型/assets/jco-ui.css`。
- `.wrap > .page-head` 与 `.page > .page-head` 使用 `position: sticky; top: 0`。
- 用负外边距抵消页面顶部内边距，再用内边距补回标题位置，保证标题初始坐标仍为 `x=32, y=36`。
- 页头底部内边距替代原外边距，滚动时背景覆盖标题下方区域，正文不会从缝隙中透出。

### 4. 全站普通草稿

- 在已有的共享 `jco-shell.js` 中增加一层轻量草稿保存，不新增第二套业务数据存储。
- 只保存内容区普通文本框、搜索框、数字、URL 等输入，以及当前滚动容器位置。
- 排除密码、文件、隐藏字段、只读/禁用字段；保存上限 200KB，7 天过期。
- 只填充页面加载后仍为空的字段，避免覆盖页面从真数据层恢复的值。

## 四、没有采用的做法

- **不把全部页面改写成 React Router**：改动面过大，现有 15 页已经可运行，缓存 iframe 能用更小风险解决切页重载。
- **不依赖浏览器 bfcache**：Electron 的 iframe 导航控制不在业务代码手里，无法保证命中。
- **不把页面内长任务继续留在隐藏 DOM**：可见性变化可能触发浏览器节流；媒体生成继续由主进程任务负责。
- **不使用 `display: none` 缓存**：会丢失元素布局尺寸，也会让现有坐标与视觉测试失去意义。
- **不为每个页面复制一套页头、开关或草稿代码**：统一进入 `jco-ui.css` 与 `jco-shell.js`，避免再次出现逐页补丁。
