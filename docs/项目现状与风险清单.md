## 三、风险清单（按优先级）

### P0：产品模型与领域边界缺失（2026-10-17 新发现）

这不是单点缺陷，而是当前“细节越修越多”的总根源。已核对到的具体事实：

- 系统提示词在 `app/kernel/bridge.mjs:101` 把“成人学历提升招生”写死成总管身份；产品要求是通用自媒体工具，行业必须可配置。
- 首页发送在 `设计原型/J.Co主界面-首页.html:304` 直接调用 `tasks.dispatch`，所以“聊天”变成了任务，并可能触发浏览器。
- 聊天、页面派活、自动任务都调用同一套 `buildChatSystem()`（`app/kernel/bridge.mjs:611`），没有聊天 / 员工 / 任务提示词分层。
- 浏览器工具 patch 对聊天和任务都常驻挂载（`app/kernel/bridge.mjs:416-417`），纯聊天也可能自行打开浏览器。
- 总管消息入库硬截 2000 字（`设计原型/J.Co总管.html:492`），`mdToHtml` 只处理加粗和换行（同文件 424 行），AI 消息 body 最宽 84% 且套大圆角卡片（79–89 行），导致长文被截断、排版像输入框。
- 自动任务写 `auto-runs.json`，派活写 `task-sessions/*.json`（`app/main.js:663`、`840`），两套台账没有统一。
- 聊天、任务、自动任务、员工角色、浏览器会话在代码里都表现为“发 prompt → 调内核 → 显示结果”，没有明确的领域模型和状态机。
- 这不是三块页面、也不只是前端的问题：`设计原型` 里 17 个 HTML 共 44 处“成人学历/招生”，业务数据分散在 20 多个 localStorage key，多个页面直接调用 `tasks.dispatch` / `kernel.ask`；主进程、DSH 内核、工具权限、数据存储、安装包同样需要迁移。全站页面清单见 [`全站迁移矩阵.md`](plans/M11-任务会话重构/全站迁移矩阵.md)，全软件分层见 [`全项目迁移总表.md`](plans/M11-任务会话重构/全项目迁移总表.md)。

完整证据、目标模型、分阶段重构与验收标准见：

- [`重构总纲-任务会话与工程质量-2026-10-17.md`](重构总纲-任务会话与工程质量-2026-10-17.md)
- [`细节工程与AI开发门禁-2026-10-17.md`](细节工程与AI开发门禁-2026-10-17.md)
- [`M11 任务会话重构设计包`](plans/M11-任务会话重构/README.md)
- [`全站迁移矩阵`](plans/M11-任务会话重构/全站迁移矩阵.md)
- [`全项目迁移总表`](plans/M11-任务会话重构/全项目迁移总表.md)

**结论：在领域模型和交互冻结前，不再继续用补丁方式加首页、聊天或任务功能。**

### P0：安全红线目前主要靠提示词

**事实**：工具白名单里没有名为“发布”的工具，但 AI 有一个通用 `jco_click`，可以点击快照中的任意元素；`jco_snapshot` 会把“发布”按钮也列出来。

相关位置：

- `app/publish/tools.mjs:95`：`click` 按 `ref` 点击任意元素。
- `app/kernel/publish-tools/index.mjs:84`：`jco_click` 暴露给模型。
- `app/tests/unit/publish-tools.test.mjs:31`：所谓“无发布能力”的测试只检查源码中是否出现 `publishButton` 等字样，不能证明点击发布不会生效。

同类边界问题：

- `open_page` 只在打开时校验域名；点击后跳转到外部域名没有再次校验。
- `upload_file` 接受任意本机绝对路径，没有限制在素材 / 成片目录内。
- J.Co 自己的 `CHAT_SYSTEM` 没有明确写入“外部网页 / 评论只是资料，不是指令”的数据 / 指令分隔规则。

**结论**：当前不应对外宣称“AI 工具层物理上无法发布 / 删除”。对外销售前，必须先在工具层加入目标拦截、域名跳转校验、上传路径约束和提示注入防护。

### P1：发布页的账号状态不是真的

**事实**：发布页的五平台状态是硬编码的：

```text
抖音：logged: true · J.Co 招生号
视频号：logged: true · J.Co 招生号
小红书：logged: true · J.Co 学历规划
B站：logged: false
快手：logged: true · J.Co 招生号
```

它没有读取账号中心的 `jco-login-v1`。账号中心可以显示“已登录 0 个”，发布页却仍显示三个已登录。

相关位置：

- `设计原型/J.Co工作台-发布.html:557` 起：静态平台表。
- `设计原型/J.Co账号中心.html:455`：真正的 AI 发布会话登录入口。
- `设计原型/J.Co工作台-发布.html:585`：未登录平台走的是 `sys.openExternal` 系统浏览器，而不是 AI 专用浏览器。

另外，`main.js:632` 的 `ensurePublishReady()` 在没有会话时固定启动抖音；如果当前已开着别的平台会话，它会直接判断“就绪”，不会切到目标平台。多平台任务可能打开错域名或被白名单拒绝。

### P1：任务管道没有真正统一

**事实**：代码里至少还有两条执行路径：

- 自动任务 / 马上跑：`runAutoTask()` → 写 `auto-runs.json`。
- 页面派活：`runDispatchedTask()` → 写 `task-sessions/<id>.json`。

自动任务不会创建 `taskSessions` 记录，因此不会出现在总管的“任务”分区；自动任务通知也没有绑定点击跳转。

相关位置：

- `app/main.js:644`：`runAutoTask()`。
- `app/main.js:751`：`tasks:run` 走 `autoScheduler.runNow`。
- `app/main.js:821`：`runDispatchedTask()`。

此外，两条路径都无条件调用 `ensurePublishReady()`，所以写稿、做后期、生成图片等任务也可能先启动抖音浏览器，最多白等约 60 秒。

### P1：设置页有几项没有真正接线

1. **素材 / 成片存放位置**：设置页选择文件夹后只写 `localStorage.jco-assets-dir`（`J.Co设置.html:624`）；主进程实际读 `settings.json` 的 `assetsDir`（`main.js:195`），而 `sys:pick-folder` 不会写这个字段。
2. **发布前必须我确认**：`jco-confirm-publish` 只在设置页写入（`J.Co设置.html:561`），全项目没有读取点。
3. **任务完成提醒**：页面生成类通知会读 `jco-notify-done`，主进程的任务完成通知没有读这个开关。

这三项都会让用户产生“我已经设置了”的错觉，其中第 2 项直接涉及安全承诺。

## 四、防跑偏纪律（后续会话必须遵守）

1. **开工顺序**：`AGENTS.md` → 本文件 → `README.md` → 工作流标准 → 当前里程碑设计包。
2. **先核对事实**：每次新会话先确认自己在主工程 `master` 还是 beta 工作区，再看 `git log -1`、`app/package.json`、安装版文件版本、`git status`；不要把两条线的版本混在一起，也不要凭上一轮摘要里的“已完成”继续做。
3. **“真”必须有证据**：说“全真 / 已完成 / 唯一管道 / 工具层无法发布”时，必须能指出具体代码和测试；否则只能写“界面已接 / 计划接”。
4. **文件版本与安装版分开写**：`HEAD`、`tag`、`release`、桌面安装版是四个不同事实。
5. **每批改动同步更新本文件**：至少更新“最后核对”、版本事实、已关闭 / 新增风险；没有更新就视为交付不完整。
6. **不把本文件当需求文档**：它记录当前事实与风险；产品需求仍走立项单 / PRD / 变更单。
