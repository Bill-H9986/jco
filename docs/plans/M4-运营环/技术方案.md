# M4 运营环 · 技术方案

> 状态：已拍板（随 PRD 冻结）｜设计冻结包 2/4

## 一、架构：全量复用发布链路

```
运营页（马上跑 / 取评论 / 就这么发）
   → 启动发布会话（复用，平台=抖音）+ 任务卡（复用 handoff 模式）
   → AI：会话服务（复用）→ 浏览器工具（复用 8 个）读页面
   → 新增：数据提交工具 2 个（save_report / save_comments）
        → 会话服务写入本机数据文件（userData/publish/data/*.json）
   → 运营页读取展示（新 IPC：publish:data:get）
   → 「就这么发」：跳总管 + 任务卡（复用）→ AI 执行回复
```

## 二、新增项（差异点全清单）

| # | 新增 | 说明 |
|---|---|---|
| 1 | 工具面 +2（共 10）：`save_report` / `save_comments` | 数据提交类（非页面操作）；tools.mjs 增 `DATA_TOOLS` 声明；安全评审：只写本机文件，无外部副作用 |
| 2 | 数据文件：`<userData>/publish/data/report-latest.json` / `comments-latest.json` | 会话服务写（确定性、覆盖式） |
| 3 | 会话服务参数 `--data-dir` | 主进程传入 |
| 4 | 主进程 IPC：`publish:data:get` | 读两文件返回给运营页 |
| 5 | 运营页改造（下轮 UI 施工） | 战报区/评论区/线索区接真数据；「马上跑」「取评论」「就这么发」入口 |
| 6 | 任务卡模板 ×2（战报 / 取评论） | 与发布任务卡同模式（handoff 自动发送） |
| 7 | 系统提示词操作要点 +⑥ | 运营任务的存数纪律（读完就存、点头才发） |

## 三、数据流

```
AI 读页面 → 调 jco_save_report({views, fans, comments}, note)
 → 会话服务 POST /tool → 写 report-latest.json
 → 运营页（window.jco.publish.data.get）→ 渲染战报
```

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 平台数据页/评论页结构差异 | 沿用"知识补档"流程（首次实战后补平台档案） |
| 读取触发风控 | 默认每天 1 次（手动触发）；行为等同用户本人查看 |
| 评论回复误发 | 红线：点头才发；发送前 AI 再对一遍文案 |
| 数据文件被外部改动 | 只读展示；数据来源单一（会话服务写） |
