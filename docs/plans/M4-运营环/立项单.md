# 里程碑立项单：M4 运营环（看数据 / 回评论 / 引流）

（按《工作流标准》附录 A 模板填写 · **草案，待产品负责人拍板**）

- **提出日期**：2026-10-16
- **一句话目标**：让"看数据 → 回评论 → 引流"三件事像发布一样真跑起来——AI 干、人拍板。
- **为什么做（用户价值）**：五环中发布已通，运营环是日常耗时第二大的部分（回评论、看数据、找线索）；机制与发布同构，复用成本低、见效快。
- **做什么（范围草案 · 三块）**：
  - **A. 今日战报（看数据）**：AI 读取创作者中心数据页 → 写入本地数据层 → 运营页展示**真数据**；触发 v1 = 手动"马上跑"（定时更新放 v1.1，与「自动任务」页联动）。
  - **B. 评论要你过目（回评论）**：AI 拉取评论 → 挑选重点 → 拟好回复稿 → 运营页确认 → **人点头后回复**（红线照定稿文案）。
  - **C. 私域线索（引流）**：v1 只做**识别与登记**（从评论中提取意向线索 → 列表）；**不自动私信**。
- **明确不做（划界）**：
  - 不自动私信 / 不主动私聊（合规风险）；
  - 不爬取他人账号（对标拆解属"选题环"，另立项）；
  - 不一次上全部平台——同发布路线：先抖音跑通，其余随登录推进；
  - 不改运营页既定视觉与交互（只把演示数据换成真数据 + 加必要入口）。
- **验收标准（能演示 / 能测）**：
  1. 点"马上跑" → 运营页战报变为**今天的真实数据**（不再是演示数）；
  2. 评论区出现**真评论** + AI 拟稿；点"就这么发" → 平台侧**真实回复成功**；
  3. 线索区出现从评论识别出的意向线索。
- **依赖与风险**：
  - 依赖：各平台登录（首次由用户完成）；M2 发布机制（已具备）；平台评论/数据页知识随首次实战补档（同发布流程）。
  - 风险：平台评论管理页结构差异大（用知识补档消化）；数据读取频率需克制（防触发风控，默认每天 1 次）。
