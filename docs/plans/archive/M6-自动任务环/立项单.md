# 里程碑立项单：M6 自动任务环（到点自己干活）

（按《工作流标准》附录 A 模板填写 · 草案）

- **提出日期**：2026-10-16
- **一句话目标**：让「自动任务」页从演示变真——**到点任务自己开跑**（AI 真执行），跑完给通知、留记录；作品发布仍然用户亲手点。
- **为什么做（用户价值）**：这是用户初衷"AI 代替人做反复固定的事"的最直接兑现。现在的员工得用户喊才动；做完后：早上自己取战报、到点自己扫评论拟稿、每周自己出周报。页面文案早已宣过此目标（"到点自动执行"）。
- **做什么（范围草案 · v1）**：
  - **A. 任务结构化**：任务表从"展示字符串"升为"结构化时间"（每天/早上/傍晚/每周 → 具体钟点，任务卡显示具体时间）；老数据自动迁移；
  - **B. 到点执行（调度器）**：应用内调度器（每分钟心跳）到点自动"跑一遍任务"= AI 真执行（复用发布/运营链：自动确保发布会话就绪 → 任务卡 → 干活）；同一任务同一天只跑一次；**应用启动时补跑最近一次错过的**（抄内核规范："每个重复任务只补发最近一次错过的发生时点"，补跑窗口 24h/周任务 72h）；
  - **C. 跑完的交代**：系统通知（"跑完了，结果概要"）+ 任务卡显示"上次执行"（时间 + 成败）；执行日志留档；
  - **D. 团队页联动**：自动任务干活时，团队页汇报区显示"自动任务「X」正在忙：动作"（不点员工卡，v1 取舍见技术方案）。
- **明确不做（划界）**：
  - 不接内核调度器（**SDK 模式不可用**，调研结论见笔记）；不引入系统计划任务（Windows Task Scheduler）；
  - **不自动点发布**（红线不变：发布按钮永远用户亲手点——自动任务会把一切准备好、停在发布前）；
  - 不动「自动任务」页定稿视觉（只在任务卡加"上次执行"一行小字 + 时间显示具体钟点）；
  - 不做自定义钟点选择器（表单维持 4 档频率，钟点用产品默认值；自定义时间进 backlog）；
  - 失败不自动重试（如实记录，用户手动"马上跑"）。
- **验收标准（能演示 / 能测）**：
  1. 建一个任务（比如"每晚 18:30 扫一遍评论拟稿"）→ 到点**自动开跑**（无需任何点击），跑完弹系统通知、任务卡出现"上次执行 18:30 ✓"；
  2. 到点没开应用 → 应用启动后**自动补跑最近一次错过的**（只补最近一次）；
  3. 自动任务干到涉及发布/回复时**一律停下等用户**（平台侧无任何发布/回复发生）；
  4. 同一任务同一天不重复跑；暂停的任务不跑；
  5. 两道 UI 门 + 全量门禁（单测 / E2E）全绿。
- **依赖与风险**：
  - 依赖：M2 发布会话机制、M4 任务卡文本、M5 的活动事件通道（团队页联动白拿）；
  - 风险：应用关闭期间不执行（桌面应用常态，v1 明确接受）；执行时长超 bridge 3 分钟回合保护（记录为"没跑完"，用户手动再跑）；浏览器会话启动失败（如实记录，任务不静默装成功）。
