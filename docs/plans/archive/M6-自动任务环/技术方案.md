# M6 自动任务环 · 技术方案

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 2/4｜依据：先例调研笔记（抄 dsh-schedule 语义、不抄其实现）

## 一、A 块：任务结构化

```js
// 任务（localStorage jco-tasks-v1 为准；页面编辑）
{
  id: 't2', name: '晚间发布检查', desc: '到点提醒你确认今晚的发布',
  when: '每天 19:20',          // 展示文案（迁移后由 schedule 生成）
  icon: 'ti-bell', on: true,
  schedule: { kind: 'daily', time: '19:20' }          // 或 { kind:'weekly', weekday:1, time:'10:00' }
}
```

- **四档频率 → 默认钟点**（拍板默认值）：每天一次=09:00、每天早上=08:30、每天傍晚=18:30、每周一次=周一 10:00；
- **迁移**：老任务（只有展示字符串 when）按 `每天 HH:mm` / `每周一 HH:mm` 解析成 schedule；解析失败 → `daily 09:00`（不丢任务）；
- `when` 文案由 schedule 生成（"每天 09:00" / "每天早上 08:30" / "每天傍晚 18:30" / "每周一 10:00"），与定稿演示数据同款格式。

## 二、B 块：调度器（应用主进程）

### 2.1 判定纯函数（可单测）——`app/kernel/auto-schedule.mjs`

```js
// 返回应跑的"计划时刻"（毫秒）或 null。语义抄 dsh-schedule：
// "每个重复任务只补发最近一次错过的发生时点"。
shouldRun(task, now, lastRunAt) →
  recentDue = 最近一个 <= now 的计划时刻（按 kind 计算：今天/今天之前最近一次）
  若 recentDue === null → null
  若 recentDue <= (lastRunAt || 0) → null（已跑过这一次）
  若 now - recentDue > 补跑窗口（daily 24h / weekly 72h）→ null（太久了，跳过并记"跳过"）
  否则返回 recentDue
```

- 一把覆盖三种场景：**到点跑**（now 刚过计划时刻）、**启动补跑**（now 晚于计划时刻但在窗口内、未跑过）、**去重**（lastRunAt 已覆盖该时刻）；
- 周任务：`weekday`（ISO 周一=1）最近的匹配日；本地系统时区（v1 取舍，不引时区库）；
- 边界必须单测：00:00 跨天、每周跨周、恰好等于计划时刻、晚 1 秒 / 晚 25 小时。

### 2.2 心跳与执行——`app/main.js`（+ 启动接线）

```
startAutoScheduler()   // app ready 后启动
  每 60 秒 tick：
    读 kernel/auto-tasks.json（mtime 变了才重读；文件缺失=无任务）
    读 kernel/auto-runs.json（内存缓存）
    for task（on 且不在 running 集合）:
      due = shouldRun(task, now, runs[task.id]?.lastRunAt)
      if (due) runTask(task, due)

runTask(task, due)：
  1) 标记 running（防重入）
  2) ensurePublishSession()：启动发布会话并轮询就绪（≤60 秒）；
     失败不阻塞——照常发任务（AI 若用不了浏览器会如实说，我们不装成功）
  3) prompt = 「现在就跑一遍」任务卡（与「马上跑」同款）+ 自动纪律尾注（见 §四）
  4) result = await bridge.ask(prompt, null, { sessionId: 'jco-chat-auto-' + task.id,
        onActivity: (act) => 广播 kernel:activity（附 auto:true, taskName） })
  5) runs[task.id] = { lastRunAt: Date.now(), dueAt: due, ok: result.ok,
        summary: 摘要（成功=AI 最后回复前 80 字；失败=错误） }
     写 kernel/auto-runs.json；系统通知（成功/失败两种文案）
  6) 清 running
```

- **串行**：`bridge.ask` 自带队列——用户在聊天时自动任务排队等它说完，互不打断；
- **回合保护**：bridge 3 分钟无响应会重置内核并报错——自动任务记录为"没跑完"，用户可手动「马上跑」；
- **重入保护**：`running` 集合（内存）；应用重启后靠 lastRunAt 去重；
- **广播**：自动任务不走 `kernel:ask` IPC，调度器自己把 `onActivity` 事件广播到所有窗口（附 `auto:true`、`taskName`），团队页据此显示"自动任务「X」正在忙"。

## 三、C 块：执行记录与通知

- `kernel/auto-runs.json`：`{ "runs": { "<taskId>": { lastRunAt, dueAt, ok, summary } } }`；
- 页面读法：新增 IPC `tasks:runs:get`（页面加载时拉一次；每次进页刷新）；
- 通知：`new Notification({ title, body })`（主进程，与 sys:notify 同款能力）——
  成功：`「<任务名>」跑完了` + summary；失败：`「<任务名>」这轮没跑成` + 原因；
- 任务卡显示："上次执行 18:30 ✓ / ✗"（读 runs；没有记录则不显示）。

## 四、自动任务纪律尾注（固定文本，逐字进 prompt）

```
（自动任务纪律：这是定时触发的任务，用户正在别处忙。准备工作照做；
但任何"点发布""发送回复"之类不可逆的动作一律停下——准备好后等用户来确认。
做完把结果说清楚：干了什么、结果如何、接下来等用户做什么。）
```

## 五、D 块：团队页联动（M5 通道白拿）

- `staffActivity` 收到 `act.auto === true` 的事件：汇报区显示
  `自动任务「<taskName>」正在忙：<动作>`；`turn/end` 后恢复原句；
- **取舍（v1）**：不点亮具体员工卡——"任务名 + 动作"信息量大于工位猜测（错点工位=张冠李戴）；
  将来给任务加"归哪个员工"字段再亮卡（backlog）。

## 七、风险与降级预案

| 风险 | 预案 |
|---|---|
| 应用关着 = 不执行 | v1 明确接受；设置页"开机启动/托盘常驻"可让用户保持常驻；文档写清 |
| 浏览器会话起不来 | 照常发任务；AI 用不了工具会如实说；记录失败原因，不静默 |
| 任务跑超过 3 分钟回合保护 | 记"没跑完"；用户手动「马上跑」；v1 不自动重试 |
| 时钟回拨 / 跨天边界 | 判定纯函数单测覆盖边界；lastRunAt 去重不依赖单调时钟 |
| 凌晨任务弹浏览器打扰 | 时间由用户设定（默认钟点全在白天）；v1 不静默拦截（如实执行） |
| 文件写入失败（打包环境） | auto-tasks.json / auto-runs.json 走 toUnpacked 路径（与 skills.json 同款，M3 实测可写） |
