## 一、需求基线（重要：不用凭空设计）

「自动任务」页（`设计原型\J.Co自动任务.html`，已定稿）本身就是需求定义：

| 定稿元素 | 含义（需求） |
|---|---|
| 页头（"任务存在本机，随时能停。**到点自动执行**会在内核调度接管后开跑；现在每个任务都能「马上跑」，等于先把活跑顺"） | **"到点自动执行"就是这个页面存在的意义**；"马上跑"是过渡形态 |
| 任务卡：名称 + 运行中/已暂停徽章 + desc + 时间（"每天 09:12"）+「马上跑」+ 开关 | 任务 = **名称 + 干什么 + 什么时候跑**；时间展示到具体钟点 |
| 新建表单：名称 / 四档频率（每天一次·每天早上·每天傍晚·每周一次）/ 要干的活 | 频率语义已定；**钟点由产品给默认值**（表单不含时间选择器） |
| 演示任务四例（对标雷达 / 晚间发布检查 / 评论自动跟进 / 每周数据周报） | 心智模型：运营类 + 提醒类 + 汇总类；其中"晚间发布检查"= 到点**提醒**用户确认发布（发布动作仍人做） |
| 「马上跑」已是真机制（handoff 任务卡 → 总管 → AI 执行） | 自动执行 = **同一个动作去掉"人点"这一步**，机制全部复用 |

## 二、业界/内核先例

### 1. DSH 内核自带调度器 `@deepseek-ai/dsh-schedule`（重点考察，结论：抄语义、不抄实现）

- 能力（官方中文文档）：一次性（after/at）、固定间隔（every）、**按每日/按每周/cron 本地钟表时间**触发；宿主级持久化；**到点把"提醒"作为后续消息投递回原会话**（宿主会恢复冷会话）；"宿主重启后任务仍然可用，**每个重复任务只补发最近一次错过的发生时点**"；Agent 还有 `schedule_create/list/update/delete` 四个工具（AI 能自己建提醒）。
- **关键限制（原文）**："Schedule **无法在 headless 或仅 SDK 的组合中单独挂载**：投递需要 Host 的 Web Session controller 和 Session 持久化后端"——**我们的架构正是"仅 SDK"**（Electron 主进程内嵌 SDK client），**用不了**。
- **抄什么**：
  - **时间语义与规范**：本地钟表时间、显式时区、`HH:mm:ss`、每周的 ISO 星期集合（周一=1）、**补发只补最近一次错过的**（我们采用同款语义）；
  - **数据模型**：任务 = 时间规则 + 标题 + 指令（我们的任务表与其对齐：name=title、desc=指令、schedule=规则）；
  - **工具面命名**（将来若我们给 AI 开放"自己建任务"能力，沿用 create/list/update/delete 的形态）。
- **不抄什么**：不试图挂载该插件（SDK 不可用，连"实验 bundle"也要求完整 Host）；不引入其存储层（我们用 `auto-tasks.json` 文件 + localStorage 单源同步，与技能库同款）。
  - **记录教训**（与"会话续聊"同源）：内核 rc 版对"仅 SDK"模式有多处能力折叠（resume、schedule），凡"内核有、SDK 没有"的功能要先查 SDK 侧可用性再立项。

### 2. 我们自己的既有机制（主要复用地基）

- **执行**：`bridge.ask`（串行队列 + 3 分钟回合保护 + 活动事件）——自动任务 = 主进程代替用户说一句话；
- **浏览器**：M2 发布会话（`publish.session.start` + 就绪轮询），自动执行前"先开机"；
- **任务卡文本**：M4 的"取战报 / 取评论"任务卡（含"只读""不要替我回复"纪律语），自动任务直接复用其措辞风格 + 追加自动纪律尾注；
- **可见性**：M5 的 `kernel:activity` 事件通道（团队页"在忙"白拿，自动执行时汇报区显示任务名）；
- **通知**：`sys:notify`（系统通知，已真实现）。

### 3. 划界（不引入的先例）

- **Windows 任务计划 / 系统级调度**：需要安装期写系统任务、越出应用边界、卸载残留——**不引入**；v1 明确"应用关着=不执行"（开机启动/托盘常驻已有，用户可自行开启保持常驻）。
- **Node 侧 cron 库**（node-cron 等）：我们只需要"每分钟查一次任务表"的心跳，几十行自研（可单测），**不引入依赖**（防供应链面）。

## 三、结论

| 事项 | 决定 |
|---|---|
| 调度实现 | **自研主进程心跳调度器**（每分钟 tick + 结构化任务表）；时间语义按 dsh-schedule 规范（本地钟表时间、只补最近一次错过） |
| 执行方式 | 复用 `bridge.ask`：先确保发布会话就绪 → 发任务卡（用户文案 + 自动纪律尾注）→ 等待完成 → 记录 + 通知 |
| 数据 | 任务表 localStorage 单源（页面编辑）→ IPC 同步到 `kernel/auto-tasks.json`（调度器只读）；执行记录写 `kernel/auto-runs.json`（页面只读展示） |
| 红线 | 自动任务**不点发布、不点发送**；一切停在"等你"；补跑只补最近一次 |
| 不引入 | dsh-schedule 插件、系统计划任务、cron 第三方库 |
