# M6 自动任务环 · 产品需求（PRD）

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 1/4

## 一、背景与问题

「自动任务」页定稿时写下一句承诺："任务存在本机，随时能停。**到点自动执行**会在内核调度接管后开跑。"——现状是：调度不存在（内核调度在 SDK 模式不可用，见调研笔记），任务只是"存着的卡片"，每个任务要人点「马上跑」。**页面的核心价值（到点自己干）是空的。**

## 二、用户流程（目标态）

1. 用户在「自动任务」建一个任务："评论自动跟进 / 每天傍晚 18:30 / 扫一遍评论，拟好回复等我放行"；
2. **到 18:30，应用开着——任务自己开跑**：AI 打开创作者中心 → 读评论 → 拟稿 → 存进运营页；全程无需点击；
3. 跑完弹**系统通知**："「评论自动跟进」跑完了：8 条评论稿等你过目"；任务卡上出现"上次执行 18:30 ✓"；
4. 用户回来看运营页：真评论 + 拟好的稿；点头才发（红线照旧）；
5. 18:30 时应用没开 → 用户 20:00 打开应用 → **自动补跑最近一次错过的**（只补一次，不回溯更早）；更早的错过如实记"跳过"；
6. 任何任务干到"点发布 / 点发送"的最后一步 → **一律停下等你**；平台侧不会有任何发布或回复发生。

## 三、界面变化清单（只动这些）

| 页面 | 变化 | 不动 |
|---|---|---|
| 自动任务页 | 页头文案改真（"到点它自己跑…"）；任务卡 when 显示具体钟点；任务卡加"上次执行"小字；新建任务落结构化时间 | 布局、四档频率按钮、任务卡结构、开关交互 |
| 管家团队页 | 自动任务干活时，汇报区显示"自动任务「X」正在忙：动作" | 员工卡（自动任务不占卡，见技术方案取舍） |
| 其他 | 无 | 全部 |

## 四、红线

1. **不自动点发布、不自动发回复**——一切不可逆动作停在"等你"；
2. **只补最近一次错过的**（抄内核规范）；同一天不重复跑；暂停的任务绝不跑；
3. **不装成功**：跑不动（浏览器起不来 / 模型没答上来）就如实记录 + 通知里说实话；
4. 应用关着不执行（v1 明确；开机启动/托盘常驻可让用户自行保持常驻）。

## 五、验收标准（能演示 / 能测）

1. 建任务 → 到点自动跑（无需点击）→ 通知 + "上次执行"记录；
2. 错过 → 启动补跑（只补最近一次）；
3. 发布/回复类动作一律停住（平台侧无动作）；
4. 同任务同日不重复；暂停不跑；
5. 两道 UI 门 + 全量门禁绿。
