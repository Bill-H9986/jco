# M5 AI 员工体系 · 技术方案

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 2/4｜依据：先例调研笔记（Anthropic Agent Skills / MCP Progress / DSH 事件协议）

## 一、A 块：员工实时状态

### 1.1 数据流（从头到尾）

```
内核子进程（DSH）发出 session.event: tool/call、tool/result、turn/start、turn/end
   ↓  onNotification（bridge.mjs 已挂，现只解析文本增量）
activityOf(notification)   ← 新增解析器（纯函数，可单测）
   ↓  options.onActivity(ev)（ask 的第 4 路回调，带 sessionId 包装）
ipcMain（main.js kernel:ask）→ 广播所有窗口：webContents.send('kernel:activity', ev)
   ↓  preload.cjs：kernel.onActivity(cb)
页面（管家团队 / 总管）实时渲染
```

查询不落地、不持久化：**活动事件只活在内存里**，页面刷新后由活动日志（`jco-log-v1`）兜底显示"今日产出"。

### 1.2 事件形状（接口契约核心）

```js
// 归一化后的活动事件（主进程 → 渲染层）
{
  kind: 'tool' | 'turn',        // 工具活动 | 回合边界
  phase: 'call' | 'result' | 'start' | 'end',
  session: 'jco-chat-cxxx',     // 内核会话 id（渲染层剥前缀得前端会话 id）
  tool: 'jco_open_page',        // tool 事件才有
  isError: false,               // result 事件才有
  t: 1730000000000              // 毫秒时间戳
}
```

### 1.3 解析器（bridge.mjs）

新增纯函数模块 `app/kernel/activity.mjs`（bridge 引入它；独立成模块是为了单测零副作用——bridge 加载时会写 patch 文件，不适合直接被单测 import）：

- `tool/call` → `{ kind:'tool', phase:'call', tool: data.name }`（不转发 arguments，防敏感参数外泄到界面层；界面层不需要）；
- `tool/result` → `{ kind:'tool', phase:'result', tool: 由 callId 对齐（会话内维护 callId→name 小映射），isError: !!data.error }`；
- `turn/start` → `{ kind:'turn', phase:'start' }`；`turn/end` → `{ kind:'turn', phase:'end' }`。

`ask()` 里透传：`options.onActivity` 存在时逐步回调，事件补 `session` 字段（当时 ask 用的会话 id），并用 try/catch 包裹（单个回调失败不影响整轮，与 onDelta 同款纪律）。

### 1.4 归属规则（渲染层）

1. **会话标签**：发布页 / 运营页派活跳总管前，写 `sessionStorage['jco-handoff-staff']`（`publish` / `ops`）；总管页消费 handoff 时把它写进当前会话对象（`jco-chats-v1` 的 `chat.staff`），随后清除标记；
2. 团队页收到 activity → 从 `session` 剥出前端会话 id → 在 `jco-chats-v1` 找 `chat.staff` → 映射员工卡（publish→发布、ops→运营）；
3. **无标签会话**（普通聊天）用工具：不点员工卡，只在团队页汇报区 / 总管页显示"我正在干活：<动作>"；
4. `turn/start` 时：有标签会话直接点亮对应员工卡（文案"正在准备…"，等 tool/call 来了更新）；
5. `turn/end` 时：清除该会话的在忙状态，卡片回落（有产出 / 空闲，按活动日志重渲染）；
6. **兜底**：同一会话 3 分钟无任何事件 → 自动清除在忙状态（内核卡死/重启时防"假在忙"，宁可少显示不可卡死）。

### 1.5 动作文案映射（渲染层，界面文案与工具名解耦）

| 工具 | 文案 |
|---|---|
| jco_open_page | 正在打开平台页面 |

## 二、B 块：技能库真联动

### 2.1 单一事实源（技能表 v1）

新增 `设计原型/assets/jco-skills.js`，暴露 `window.JCO_SKILLS_DEFAULTS`（16 项 = 技能库 12 项 ∪ 做视频页 8 项，去重 4 项同名）：

```js
{
  id: 's1', name: '爆款复刻',
  desc: '拆爆款的结构、换成你的内容，照着跑',   // 技能库卡文案（原样）
  kind: 'video', icon: 'ti-flame', on: true,    // 技能库字段（原样）
  scenes: ['make-video'],                       // 出现场景：做视频页技能排
  entry: '做视频页 →「爆款复刻」',               // AI 指路文案
  action: { fill: '帮我复刻这条爆款视频，链接：', method: 't2v', toast: '（原样搬入）' }  // 做视频页点击行为
}
```

合并与迁移规则（技能库页加载时）：

1. 读 `jco-skills-v1`（老数据 12 项）；按 id 合并共享表——**已存在的项以用户存的为准**（on/自定义不动），新技能（做视频页独有 4 项）按共享表默认补入；
2. 合并结果写回 `jco-skills-v1`；每次进技能库页（及每次启停操作后）通过 IPC 同步给内核侧（见 2.3），保证内核永远跟界面一致；
3. `on` 默认值对齐修正：`一镜到底` 默认改 `true`（与做视频页"默认显示它"的定稿事实对齐；存量用户以本机存值为准），记录为计划内变化。

### 2.2 做视频页联动（兑现页脚承诺）

`J.Co工作台-做视频.html` 的技能排（`#skills`）改为：

```
显示 = 共享表中 scenes 含 'make-video' 且（合并后）on === true 的技能
```

- 点击行为不变（沿用 `action` 里的 fill/method/toast/type/duration 字段走原 `onSkill` 逻辑）；
- 无任何本地存储时（新机）→ 全默认 → 显示 8 个，与定稿一致；
- 用户停用某技能 → 下次打开做视频页少一个按钮；**已做好的东西（草稿、成片）一律不动**（页脚承诺）。

### 2.3 AI 知情（轻注入，渐进式披露第一层）

- 新增 IPC `skills:sync`：技能库页把合并后的数组发给主进程 → 主进程写 `kernel/skills.json`（打包适配走 `toUnpacked`，与 model-config.json 同款路径策略，防 asar 只读）；
- `bridge.mjs`：`CHAT_SYSTEM` 常量升级为 `buildChatSystem()`（每次 ask 时读一次 skills.json，文件很小），在末尾拼【技能库】段：

```
【你的技能库】（用户在技能库里启用的手艺；如实说，不夸大）：
- 爆款复刻：拆爆款的结构、换成你的内容（入口：做视频页 →「爆款复刻」）
- 评论回复官：评论先拟稿，用户点头才发（入口：运营页 →「取评论」）
- 长视频拆条：一条长视频拆成 5 条短视频（还没接入，先别答应用户）
…
这些技能的执行入口在各自页面（点按钮真跑）；你在聊天里不能直接替用户执行——用户想在聊天里用某技能时，如实告诉他去哪个页面点哪个入口。没启用的手艺不要提。
```

- 注入规则：只注入启用（`on:true`）的技能；`entry` 里标注"（还没接入）"的技能，AI 被问起时如实说没接上（诚实红线）。

### 2.4 技能库页

- `DEFAULTS` 改为读共享表 + 2.1 的合并迁移；渲染与交互不变；
- 每次启停 / 进页时调用 `window.jco.skills.sync(items)`（桌面应用内才调，浏览器直开跳过）；失败静默（下次再同步），不打断用户。

## 四、风险与降级预案

| 风险 | 预案 |
|---|---|
| 事件连发导致渲染抖动 | 渲染层节流（≥120ms 合并刷新）；同时最多一个"当前动作"文案 |
| 内核重启 / 事件断流 | 3 分钟静默自动回落；turn/end 为主信号 |
| 会话标签丢失（老会话） | 无标签 → 不点员工卡（总管区兜底），不猜 |
| skills.json 与界面漂移 | 技能库页每次加载自动同步一遍（界面为准，文件是从属） |
| 打包环境写入失败 | skills.json 走 toUnpacked 路径（与 model-config.json 同一机制，M3 已实测可写） |
| 老数据合并出错 | 合并规则"已存在以用户为准、新项补默认"，单测覆盖；错误时退回共享表默认 |
