# M5 AI 员工体系 · E2E 验收用例清单

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 4/4（先写"会失败"的，施工以变绿为目标）

## A 级 · 全自动（进 gate）

| # | 场景 | 断言 |
|---|---|---|
| A1 | 活动事件解析（单测） | `tool/call` → `{kind:'tool',phase:'call',tool}`；`tool/result` 能对齐工具名与 isError；`turn/start`/`turn/end` 正确；无关事件 → null；**不含 arguments 字段** |
| A2 | 技能表结构（单测） | 16 项；id 唯一；`scenes` 合法；`make-video` 场景恰 8 项；每项 `name/desc/entry/on` 齐备；`action` 字段仅 make-video 项携带 |
| A3 | 技能合并迁移（单测） | 老 12 项（含用户改过的 on）→ 合并后 16 项且**用户值保留**；s13–s16 默认补入；无存储 → 全默认；损坏数据 → 退回共享表默认 |
| A4 | 技能注入段（单测） | 只含 `on:true` 项；含固定尾注（逐字）；全 off → 技能段整体省略；entry 原文进段 |
| A5 | 团队页在忙渲染（E2E） | mock `onActivity`：带 `chat.staff='publish'` 会话的 `tool/call` → 发布卡「在忙」+ 文案；`turn/end` → 回落「有产出/空闲」；无标签会话 → 员工卡不动 |
| A6 | 做视频页联动（E2E） | 停用 s4 → 技能排无「一镜到底」；启用 → 恢复；无存储（新机）→ 恰 8 个按钮 |
| A7 | 技能库页（E2E） | 老 12 项存储 → 渲染 16 张卡、计数「共 16 个」；启停后 localStorage 与（可用时）同步调用更新 |
| A8 | 演示模式不坏 | 浏览器直开（无 window.jco）团队页 / 技能库页 / 做视频页：无 JS 报错、静态演示保留 |

## B 级 · 半自动（本机脚本）

| # | 场景 | 断言 |
|---|---|---|
| B1 | 内核事件探针（真机） | 真跑一次带工具调用的会话 → onNotification 收到 `tool/call`（`qa-m5-probe.cjs`；Agnes 限流时临时走官方兜底路由，跑完恢复） |
| B2 | skills:sync IPC | 调用后 `kernel/skills.json` 存在、结构合法、内容与传入一致 |
| B3 | ask 的 onActivity 透传（真机） | `bridge.ask(text, onDelta, {sessionId, onActivity})` 真收到事件且 `session` 字段正确 |

## C 级 · 人工验收（真机，产品负责人）

| # | 场景 | 通过标准 |
|---|---|---|
| C1 | 发布 / 运营会话进行中开团队页 | 对应员工卡**实时**「在忙」+ 人话动作（如"正在打开平台页面"），跟着动作更新 |
| C2 | 回合结束 | 5 秒内回落「有产出」+「今天干了 N 件」 |
| C3 | 技能停用 / 启用 | 技能库点「收起来」→ 做视频页少对应按钮；点「启用」→ 回来；已做好的稿子 / 成片不动 |
| C4 | 问 AI 技能 | 只报启用的；每个技能给"去哪个页面点哪个入口"的指路；**无一句"我在聊天里直接给你做"** |
