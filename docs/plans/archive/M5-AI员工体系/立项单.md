# 里程碑立项单：M5 AI 员工体系（员工干活可见 / 技能库真联动）

（按《工作流标准》附录 A 模板填写 · 草案，待产品负责人拍板）

- **提出日期**：2026-10-16
- **一句话目标**：让"AI 员工"真正活起来——干活时看得见**谁在忙、在忙什么**；会的手艺由**技能库说了算**，AI 自己也清楚。
- **为什么做（用户价值）**：发布（M2）与运营（M4）都已是"AI 真操作"，但过程是黑盒：员工页只有干完活后的记录，干活中的状态看不见；技能库的开关是"摆设"（只影响技能库页自己）。补上这两处，用户才能"看得见 AI 在上班"，技能库才名副其实。
- **做什么（范围草案 · 两块）**：
  - **A. 员工实时状态（团队页）**：AI 干活时（发布 / 运营 / 聊天里用工具），对应员工卡实时显示「在忙」+「正在：打开抖音创作者中心」这类人话动作；一回合结束自动回落（有产出 / 空闲）。归属规则：发布会话 → 发布员工，运营会话 → 运营员工；普通聊天不占员工卡（汇报区显示）。
  - **B. 技能库真化 v1（两件事，不做执行器）**：
    1. **真联动**：技能库"启用 / 停用"成为全站单一事实源——做视频页的技能排按启用状态显示（兑现技能库页脚已宣："启用的技能会出现在创作页的技能格"）；停用只影响入口，不动已做好的东西。
    2. **AI 知情**：启用的技能清单（名 + 描述 + 入口在哪）注入 AI 系统提示词，AI 被问"你会什么"只报启用的、并如实指路（"去发布页点…"），**绝不吹牛说"我在聊天里直接给你做"**。
- **明确不做（划界）**：
  - 不做"每个技能的执行器"（各技能真执行是后续逐个立项：创作环等）；
  - 不给聊天链路新增画图 / 出视频工具（M5 范围外）；
  - 不动技能库页与团队页的定稿视觉（只接真数据、加动态状态）；
  - 不做通知推送 / 跨窗口多实例。
- **验收标准（能演示 / 能测）**：
  1. 发布（或运营）会话进行中，打开团队页 → 对应员工卡**实时**显示「在忙」与当前动作（如"正在打开抖音创作者中心"）；回合结束 5 秒内回落为「有产出 / 空闲」；
  2. 技能库停用「一镜到底」→ 做视频页技能排里它消失；重新启用 → 回来（停用不影响已做好的东西）;
  3. 聊天问 AI"你有哪些技能"→ 只报启用的，按"入口在哪"如实说；
  4. 两道 UI 门 + 全量门禁（tsc / biome / vitest / E2E）全绿。
- **依赖与风险**：
  - 依赖：DSH 内核 `tool/call`、`tool/result` 事件（已确认在通知流里，施工第一步先探针验证）；M2 发布会话机制；M4 运营链。
  - 风险：工具事件高速连发（渲染层节流）；事件丢失（30 秒静默自动回落，绝不卡死）；技能数据分两处存（localStorage 为准、每次进技能库页自动同步内核，防漂移）。
