## 一、需求基线（定稿 UI 本身就是需求）

| 定稿元素 | 含义 | 处理 |
|---|---|---|
| 顶部横幅"你盯的 4 个对标账号…帮你拆解好了" | **做不到且越线的承诺**（需爬取他人账号） | **改造**：换成真文案（AI 出题/评论挖题/贴爆款拆） |
| "我的对标账号"区 + "账号与对标"弹层 | 假账号 + 假保存；核心叙事踩红线 | **删除**（负资产） |
| 爆款卡（标题/为什么火/学它什么/你的版本 + 展开拆解） | 拆解框架是**好框架**，但数据是假来源 | **保留框架**，来源改为"**你贴的**爆款"（真人投喂，合规） |
| "其他灵感"三 tab（全网热点/AI 推荐/我的收藏） | 机制可行 | 改为 **4 tab**：AI 热点 / AI 推荐 / **评论挖题** / 我的收藏（收藏真存） |
| 底部"我有想拍的……让 AI 定方向" | 已是真 AI 调用 | 保留 + 结果持久化（不丢） |

## 二、业界先例（关键结论：对标拆解类产品都靠爬取，我们不走）

1. **对标拆解类工具**（蝉妈妈、新榜、灰豚等）：核心能力是**大规模爬取平台数据**做榜单/拆解——**合规风险与维护成本都极高**；我们此前已在 M4 调研中明确"不爬取他人账号"（红线）。
2. **AI 选题类工具**：普遍是"给赛道+人设 → 生成选题列表"（ChatGPT/Claude 提示词工程即可）；**共同做法 = 结构化输出**（每行一条，便于解析）——我们采用同款（`题目|为什么` 行格式 / 固定 5 行拆解格式）。
3. **用户投喂式拆解**（少数增长工具的模式）：让用户**自己粘贴**爆款文案，工具只做结构分析——**合规且零抓取**——我们采用（"你贴我拆"）。
4. **评论挖题**：社群运营类工具的通行玩法（"高频问题 → 内容选题"）；我们有现成数据（M4 取回的评论），**结构最顺**。
5. 时间感知：让模型带上"今天是 X 月 X 日"再出热点题（实测有效——AI 出了"10月18日成考开考在即"这种节点题）。

## 三、抄什么 / 不抄什么

| 事项 | 决定 |
|---|---|
| 抄 | 结构化行输出（易解析）、用户投喂拆解（合规）、高频问题变选题、带日期的热点生成、结果本地持久化 |
| 不抄 | 任何爬取/榜单一键搬运（红线）；对标账号自动监控（做不到且危险） |
| 出处 | 对标工具形态为公开产品常识；合规判断依据项目《AI安全与数据安全规范》与 M4 调研结论 |
