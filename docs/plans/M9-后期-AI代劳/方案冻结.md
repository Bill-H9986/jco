# M9 后期页 · AI 代劳方案（2026-10-17 冻结）

> 产品负责人原话：「只用简单加点字幕、配个音乐等！全程得由 AI 执行！人为可以干预，
> 比如用户想做成什么样，但是不会动手！就由 AI 代劳！这也是整个软件存在的意义。」

## 一、产品定义

后期页 = **AI 剪辑间**：用户只说"想做成什么样"（加字幕 / 配个音乐 / 剪掉开头…），
AI 自己动手处理成片，产出新文件；用户看结果、继续提要求。**没有时间轴、没有手动剪辑**。

**做什么（v1）**
- 字幕：按用户给的文字（或视频分镜台词）烧录进画面
- 配乐：用户选一首音乐文件，AI 混入（音量压低、淡入淡出、循环到片长）
- 裁剪：剪掉开头/结尾一段
- 拼接：把多条成片接成一条
- 产物：自动落到成片目录（素材库），可在预览里看、可继续改、可直接拿去发布

**不做什么**：多轨时间轴、转场特效、调色、逐帧精修（这些是"人动手"的路，与产品方向相反）

**红线**：只操作成片目录内的文件；永不覆盖原件（每次产出新文件）；发布按钮仍人点。

## 二、交互（页面改造方向，外观沿用现有体系）

1. 左栏「手头成片」：列出本机已出的成片（真实，可选中预览）
2. 主区：选中成片的预览 + 「跟 AI 说怎么改」输入框 + 快捷指令（加字幕 / 配音乐 / 剪掉开头 / 拼接）
3. 发送 = 派活进唯一任务管道（`tasks:dispatch`，staff=`post`）→ 总管任务视图实时看 AI 干活（过程行）
4. 完成后页面刷新「最近产出」，点开即预览；不满意继续对 AI 说

## 三、技术方案

- **引擎**：ffmpeg（`@ffmpeg-installer/ffmpeg`，61.5MB，npm 镜像分发；已核实 subtitles / amix /
  concat / afade / volume / drawtext 六个滤镜全部可用）
- **工具集**：`kernel/edit-tools/index.mjs`（新插件，机制同 publish-tools）——六个工具：
  `jco_list_assets`（列成片）、`jco_probe_video`（时长/分辨率/有无音轨）、
  `jco_add_subtitles`（文字→SRT→烧录；v1 时间按句均分）、`jco_add_music`（混音）、
  `jco_trim`（裁剪）、`jco_concat`（拼接）
- **注入**：`kernel/edit-tools.patch.yml`（bridge 启动时生成；pluginUrl + assetsDir + ffmpeg 路径，
  来源 `kernel/edit-tools.json`，由 main.js 启动时写；该文件不进安装包）
- **安全**：全部路径 resolve 后必须落在成片目录内；spawn 参数数组（不拼 shell）；输出新文件
- **产物登记**：新 IPC `sys:list-assets`（页面读成片目录列表）→ 后期页/做视频页共用

## 四、验收

- 工具单测（SRT 生成、路径守卫、命令构建）
- E2E：后期页结构（成片列表/指令输入/派活）+ `sys:list-assets` 可用
- 真机：ffmpeg 生成测试素材 → 真派活"加字幕+配音乐" → 产物存在且时长正确、可播放
- 双门 + 门禁全绿 + 打包装机（ffmpeg 进 asarUnpack）

## 五、先例依据

- ffmpeg 官方滤镜文档：subtitles（libass 烧录字幕，业界标准做法）、amix（多音轨混合）、
  concat（多段拼接）、afade（淡入淡出）——本机二进制已逐项核实可用（2018 静态构建 N-92722）
- 字幕时间轴 v1 用"按句均分"（无 ASR 时的诚实近似）；v1.1 可接语音识别或让 AI 按节奏估算
