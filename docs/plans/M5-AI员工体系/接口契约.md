# M5 AI 员工体系 · 接口契约

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 3/4

## 一、IPC 清单

| 通道 | 方向 | 载荷 | 返回 | 说明 |
|---|---|---|---|---|
| `kernel:activity` | 主进程 → 渲染（广播所有窗口） | 活动事件（见 §2） | — | 后台推送，无需订阅请求 |
| `skills:sync` | 渲染 → 主进程（invoke） | `{ items: 技能数组 }` | `{ ok, error? }` | 写 `kernel/skills.json`（内核侧注入用） |

## 二、活动事件（kernel:activity）

```js
{
  kind: 'tool' | 'turn',
  phase: 'call' | 'result' | 'start' | 'end',
  session: 'jco-chat-cxxxxxxxx',   // 内核会话 id（前端会话 id 前缀 'jco-chat-'）
  tool: 'jco_open_page',           // kind==='tool' 时才有；其余省略
  isError: false,                  // 仅 phase==='result' 时给出
  t: 1730000000000
}
```

- `session` 必填；渲染层剥离 `jco-chat-` 前缀得到前端会话 id（如 `c1a2b3`），用于归属查询；
- 事件不幂等、不补发；渲染层必须容忍乱序重放（同会话新事件覆盖旧状态即可）；
- 解析来源（内核侧）：`session.event` 的 `tool/call`（取 `data.name`）、`tool/result`（`data.error` 判失败，`callId` 对齐工具名）、`turn/start`、`turn/end`；**不转发 `arguments`**（防参数细节泄漏到界面层）。

## 三、preload API（window.jco 新增项）

```js
window.jco.kernel.onActivity(cb)     // cb(活动事件)；页面加载即订阅；无副作用
window.jco.skills.sync(items)        // -> Promise<{ ok }>；把技能数组同步给内核侧
```

契约纪律：与既有 API 同款——回调异常不扩散、浏览器直开（无 window.jco）时页面保留演示态。

## 四、技能表（单一事实源）

文件：`设计原型/assets/jco-skills.js`，暴露 `window.JCO_SKILLS_DEFAULTS`（数组，16 项）。

字段：

```js
{
  id: 's1',                  // 稳定 id（合并迁移的钥匙，永不变）
  name: '爆款复刻',
  desc: '拆爆款的结构、换成你的内容，照着跑',  // 技能库卡描述 + 注入 AI 的说明
  kind: 'video',             // 技能库分类：video | graphic | social | data
  icon: 'ti-flame',          // Tabler 图标
  on: true,                  // 出厂默认是否启用
  scenes: ['make-video'],    // 出现场景（做视频页技能排）；空数组=只出现在技能库
  entry: '做视频页 →「爆款复刻」',  // AI 指路文案；没接入的写 '（还没接入，先别答应用户）'
  action: { ... }            // 仅 make-video 场景：做视频页按钮点击行为（fill/method/toast/type/duration，原样搬入）
}
```

### 合并 / 迁移规则

1. 技能库页加载：`本地存(jco-skills-v1) ⋈ 共享表`——按 `id` 对齐；**本地已有项以本地为准**（`on` 等），共享表新项（s13–s16）按默认补入；结果回写本地；
2. 每次进页与每次启停后：`skills.sync(合并结果)`；
3. 做视频页加载：读 `jco-skills-v1`（没有则按共享表全默认），过滤 `scenes 含 'make-video' && on === true` 渲染技能排，`action` 原样映射到原 `onSkill` 逻辑；
4. 任何一侧解析失败 → 退回共享表默认（宁可回到出厂，不留半态）。

## 五、skills.json（内核侧）

```json
{ "items": [ { "id": "s1", "name": "爆款复刻", "desc": "…", "on": true, "entry": "做视频页 →「爆款复刻」" }, … ] }
```

- 位置：`kernel/skills.json`（打包适配 `toUnpacked`，与 model-config.json 同款）；
- bridge 每次 ask 时读一次；缺失/损坏 → 注入段为空（技能段整体省略，AI 照常说"技能库还没设置"类兜底可以不给——直接不提技能）。

## 六、CHAT_SYSTEM 注入段（松契约）

- 追加在系统提示词末尾（`buildChatSystem()`）；
- 只含 `on:true` 的技能；每条一行：`- 名称：描述（入口：…）`；
- 固定尾注（纪律，逐字）：

```
这些技能的执行入口在各自页面（点按钮真跑）；你在聊天里不能直接替用户执行——用户想在聊天里用某技能时，如实告诉他去哪个页面点哪个入口。没启用的手艺不要提。
```

## 七、会话标签（handoff-staff）

| 键 | 位置 | 值 | 写入方 | 消费方 |
|---|---|---|---|---|
| `jco-handoff-staff` | sessionStorage | `'publish'` / `'ops'` | 发布页 / 运营页派活时 | 总管页（消费即写入 `chat.staff` 并清除） |
| `chat.staff` | localStorage `jco-chats-v1` 的会话对象 | 同上 | 总管页 | 管家团队页（归属查询） |

归属映射（团队页）：`publish → 发布员工卡`、`ops → 运营员工卡`、无标签 → 不占员工卡。
