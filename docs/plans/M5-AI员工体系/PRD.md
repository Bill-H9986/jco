# M5 AI 员工体系 · 产品需求（PRD）

> 状态：**设计冻结**（2026-10-16）｜设计冻结包 1/4

## 一、背景与问题

五环里发布（M2）与运营（M4）已经是"AI 真操作"，但两处没接上：

1. **干活过程看不见**：AI 在总管页干活（打开页面、看页面、填内容），用户只能看到聊天区的打字；回到团队页，员工卡只有"干完活后的记录"——`在忙` 是静态演示状态，从不真亮。
2. **技能库是摆设**：技能库页 12 个技能的开关真存了，但没有任何真实后果——做视频页的技能排是另一套硬编码（8 个），跟技能库无关；AI 也不知道用户启用了什么。

## 二、用户流程（目标态）

### A. 员工实时状态

1. 用户在发布页点「让 AI 发到抖音」→ 任务派给 AI → 跳总管页开干；
2. **此时切到团队页**：发布员工卡亮起「在忙」（绿点呼吸），一行活文案："正在：打开抖音创作者中心"→"正在：看页面元素"→"正在：上传视频"……实时跟着动作走；
3. AI 干完这一轮（停在发布前等确认）：员工卡回落——「有产出」+ 今天干了 N 件（活动日志照旧）；
4. 运营任务（马上跑 / 取评论）→ 同理点亮运营员工卡；
5. 普通聊天里 AI 顺手用了浏览器工具：不点员工卡（避免张冠李戴），只在总管汇报区显示"我正在干活"；**没有任何会话在干活时，一切照旧（静态记录态）**。

### B. 技能库真联动

1. 用户在技能库停用「一镜到底」→ 做视频页技能排里它**消失**（重新启用即回来）；已做好的东西不受影响（页脚承诺）；
2. 用户问总管 AI"你有哪些技能 / 你会不会 XX"→ AI 按启用的清单如实回答，并说清**入口在哪**（"去做视频页点「爆款复刻」"）；停用的不报；
3. 红线：AI **不许**说"我在聊天里直接给你做"（聊天链路没有这些执行工具）——只做入口指路。

## 三、界面变化清单（只动这些）

| 页面 | 变化 | 不动 |
|---|---|---|
| 管家团队页 | 员工卡接实时状态（在忙/动作文案）；汇报区在忙时改文案 | 卡片布局、四态徽章样式、等你拍板区 |
| 做视频页 | 技能排数据源改为技能库（启用才出现） | 技能点击行为（填提示词）、其余全部 |
| 技能库页 | 数据源升为全站共享 + 每次进页同步内核 | 卡片视觉、开关交互、页脚文案 |
| 发布页 / 运营页 | 派活时给任务打"员工标签"（看不见的内部标记） | 所有可见界面 |
| 总管页 | 消费任务卡时记录会话员工归属 | 聊天界面 |

## 四、红线

1. **诚实**：AI 只报启用的技能，且按"入口指路"说，不吹牛、不装会做；
2. **不占错工位**：普通聊天不点员工卡；事件丢失 30 秒自动回落，宁可少显示不可卡死；
3. **停用不破坏**：停用技能只影响入口显示，已有的稿子、视频、记录一律不动；
4. **不新增外部导入**：技能清单由软件内置（防恶意技能面，呼应 Agent Skills 安全警示）。

## 五、验收标准（能演示 / 能测）

1. 发布会话进行中开团队页：发布卡实时「在忙」+ 动作文案；回合结束 5 秒内回落「有产出 / 空闲」；
2. 运营会话同理点亮运营卡；
3. 技能库停用「一镜到底」→ 做视频页技能排少一个；启用 → 回来；
4. 问 AI"你有哪些技能"→ 只报启用的 + 入口指路（无"我直接做"式吹牛）；
5. 两道 UI 门（preflight 0 违规 + 逐元素比对零意外差异）+ 全量门禁绿。
