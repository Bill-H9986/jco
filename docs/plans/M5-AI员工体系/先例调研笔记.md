# 先例调研笔记 · M5 AI 员工体系（员工干活可见 / 技能库真联动）

> 按《工作流标准》v1.2 §2.2 执行：先例调研 → 立项 → 设计｜日期：2026-10-16

## 一、需求基线（重要：不用凭空设计）

两块需求都已在定稿 UI 里有明确语义：

| 定稿元素 | 含义（需求） |
|---|---|
| 团队页员工卡（`.s-badge` 有「在忙 / 空闲 / 在等你 / 已排期」四态、`.s-live` 动态文案、`.s-time` 时间戳） | 员工状态**本来就是为"实时"设计的**，现在是静态演示——要接真状态 |
| 团队页总管汇报（`.b-say`："7 个员工今天合计干了 N 件活"） | 汇报应是"活的状态"，在忙时要说在忙 |
| 技能库页脚（"**启用的技能会出现在「创作」页的技能格里**；停用只影响入口，不会动你已经做好的东西"） | 技能库 = **入口开关**，且停用语义（不动已做好的）已写死 |
| 技能库页副题（"把一次的活儿，变成随时能叫的手艺"） | 技能 = AI 的**可调用手艺清单** |
| 用户既往指示 | "AI 做事前先要知道自己该干什么"（AI 知情）；"干好干漂亮、不该管的别管"（划界）；"不许盲盒、不吹牛"（诚实红线） |

## 二、业界先例

### 1. Agent Skills：Anthropic 官方技能体系（2025-10-16 工程博客；2025-12-18 升为跨平台开放标准）

- **技能 = 目录 + `SKILL.md`**（YAML frontmatter：`name` + `description`）；启动时**只把 name + description 预装进系统提示词**；
- 核心设计原则 **渐进式披露（Progressive Disclosure）**：第一层（元数据）→ 第二层（任务相关时读全文）→ 第三层（正文引用的附属文件，按需）；
- 技能可内置脚本（确定性操作交给代码）；建议**边干边迭代**：让 AI 把成功经验写回技能；
- **安全警示（原文）**：技能 = 给 AI 的新能力；恶意技能可窃数据、乱行动；只从可信来源装、装前审计。
- **我们的取舍**：抄"元数据轻注入"（各技能只占一两行）和"边干边学"（活动日志已记录，将来回流进技能描述）；"SKILL.md 目录 + 附属文件"三层结构 v1 不需要（我们的技能数量少、场景固定，全部描述可以压进一行）；**技能来源安全**这条直接接下（见下 §3，技能清单由我们内置，不允许外部导入——防"恶意技能"面）。

### 2. Claude Code Skills 扩展（官方文档 code.claude.com/docs/en/skills）

- Claude Code 遵循同一开放标准，并扩展了：**调用权控制**（你调 / AI 自调）、**技能内预授权工具**（Pre-approve tools for a skill）、**动态上下文注入**、**子代理执行**；
- "当 CLAUDE.md 的一段变成流程而不是事实时，抽成技能"；技能正文**用到才加载**。
- **我们的取舍**：抄"内容生命周期"思路（技能从描述开始、随实战长正文——写进将来迭代）；"子代理执行 / 预授权"暂不引入（我们的工具面已收口，技能尚无执行器，M5 不做）。

### 3. MCP Progress 通知（Model Context Protocol 规范 2025-06-18 · Utilities/Progress）

- 长任务活动上报的**协议级先例**：`notifications/progress`（progressToken 配对 + 可选 total + **人类可读 message** 字段），规范原文示例即"Reticulating splines..."；
- **我们的取舍**：抄"进度事件 = 人类可读短句"这个形态，但**不引入 MCP**——DSH 内核通知流里已有 `tool/call`、`tool/result` 事件（自带工具名与参数、精确到回合/步骤），直接转发即可，"正在：打开抖音…"的文案由界面层映射生成。

### 4. DSH 内核事件协议（本项目内核 `@deepseek-ai/dsh-session` 类型定义）

- `tool/call {turn, step, callId, name, arguments}` / `tool/result {turn, step, message, error?}` / `turn/end {reason}`；
- 桥接层（`app/kernel/bridge.mjs`）已挂 `onNotification`，目前只解析文本增量——**补一个解析器就能拿到每次工具调用**，这就是"员工在忙"的现成数据源（无需新造轮子）。

### 5. 未找到对口先例的部分（如实记录）

- "AI 员工状态面板"没有可直接照抄的开源项目（各家 agent 产品多为聊天内联展示，不是独立员工页）；我们按已定稿的团队页四态徽章自建，机制复用上面 3、4；
- "技能启用 ↔ 页面入口联动"没有外部先例，按技能库页脚已宣的语义实现。

## 三、结论（抄什么、怎么适配、不抄什么）

| 事项 | 决定 |
|---|---|
| 实时状态数据源 | **抄 DSH 事件协议**：bridge 解析 `tool/call` / `tool/result` / `turn/end` → 主进程广播 → 团队页渲染；不上 MCP、不引监控框架 |
| 动作文案形态 | **抄 MCP Progress**：人类可读短句（"正在打开抖音创作者中心"），不暴露工具名 |
| 技能清单注入 | **抄 Agent Skills 渐进式披露第一层**：只注入"名 + 描述 + 入口"，一两行一个技能；正文与执行细节不注入 |
| 技能数据来源 | 全站**单一事实源**（技能库页为准），进页自动同步内核，防两处漂移；**不允许外部导入技能**（安全面，呼应 Agent Skills 安全警示） |
| 不抄 | MCP 协议、SKILL.md 目录结构 v1、子代理执行、预授权工具（都属"技能执行器"问题，另立项） |
