## 二、根因（老实说）

1. **迭代顺序使然**：从"真能干活"的环先做（发布→运营→员工→自动任务），演示页排在后面——方向没错，但**中场的"新旧并存期"没有被管理**（没有台账、没有标记、没有说清）；
2. **每页独立建造的历史**：设计定稿期先做前端（每页自成一体），真化时按页打补丁，没做过"全站一次收口"；
3. **我的汇报失误**：历轮汇报都在说"做好的那半边"，没有主动把"还有 5 页是演示态"摆到台面上——报喜没报忧。

## 三、统一方案（三层收口）

### 3.1 唯一执行管道（"让 AI 干活"只剩下一个引擎）——本批立即做

- **定义**：任何"让 AI 干活"（手动 or 定时）统一走 **TaskRunner**：任务 = 独立会话 + 事件流（团队页可见）+ 执行记录 + 系统通知；**同一份代码路径**，只是触发者不同（人点 / 到点）；
- **本批先统一**：自动任务「马上跑」从"跳总管"改为"直跑"（与到点完全同路）；
- **下一步（排期）**：发布页/运营页派活也迁到 TaskRunner；"在场围观"成为它的一个展示窗（跳/嵌到任务会话），会话记录进聊天列表可回看——**一套引擎、两种呈现**。

### 3.2 演示标记（让"还没接上"藏不住）

- 凡 🔴/🟡 页面：页面顶部加一条**淡色提示条**（例："这块还没接上——当前是演示数据；接上后这里就是真的"），真化完成后摘除；
- 纪律化：**新页面开发期默认挂标记，摘标记 = 真化的验收动作**（谁摘谁举证）；
- 目的：用户任何时候都能一眼分清"真/演示"，同时把"欠账"显性化——不再出现"看起来像真的其实假的"。

### 3.3 收口台账 + 逐页排期

- 台账（`台账.md`）：页面 × 状态 × 所属环 × 验收方式，**每次动页面必须同步更新**（不更新 = 本次改动不算完成）；
- 排期建议（按使用频率，逐页走完整流程：调研 → 冻结 → 施工 → 双层验收）：
  1. **选题**（创作动线的起点）→ 2. **创作/文案**（写稿）→ 3. **做视频**（补全半真）→ 4. **素材** → 5. **后期** → 6. **账号中心** → 7. 首页/其余收尾；
- 每页收口标准：**要么挂着演示标记，要么全真**——不再落地"半真不标记"的中间态。

### 3.4 纪律（写进 AGENTS.md / 工作流标准，防再混用）

1. 干活机制**只许走 TaskRunner**，不许新开旁路；
2. 共享优先：**禁止新增页面私有拷贝**（每页内联 JS 只减不增，新逻辑一律进 assets/共享模块）；
3. 演示区块**必须打标记**；数据/机制迁移必须"老数据自动升级"（已有先例：任务/技能迁移）；
4. 台账不更新 = 改动不算完成（守门员 + 台账双对账）。

## 四、本批动作（不等排期的部分）

1. ✅ 自动任务「马上跑」统一为直跑（TaskRunner，与到点同路）——**本批完成**；
2. 演示标记条：样式/文案已设计（3.2），等你点头后落在 5 个演示页（外观是产品决策，一句话即可开工）；
3. 台账文件建立——**本批完成**。

## 五、给"敢不敢保证"的答案

不靠嘴保证，靠四件结构性的事：
1. **债可见**：台账 + 演示标记——假的部分永远不会再假装是真的；
2. **机制收敛**：唯一执行管道——同一件事不会再有第二条代码路；
3. **门禁兜底**：每页收口必须过单测/E2E/两道 UI 门（已有体系）；
4. **历史证据**：会话续聊、工具静默消失这两个隐患都是查出来并补了回归测试的——同样的方法会用在收口上。
