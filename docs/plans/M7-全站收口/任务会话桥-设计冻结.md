# M7 主干 · 任务会话桥（设计冻结）

> 目的：把「跳总管聊天」与「后台直跑」两套统一成**一个引擎、一种会话、一处记录**；
> 旧机制**用完即拆**（不是长期并存）。本文件是施工蓝图；配套《台账》记进度。

## 一、终局定义（"一个软件一套"长什么样——可检查）

| 维度 | 终局（唯一） | 检查方式 |
|---|---|---|
| 干活引擎 | **TaskRunner**（手动/定时/派活全走它） | 代码里除 TaskRunner 外无第二执行路径 |
| 会话 | **任务会话**（`jco-chat-task-<id>`，可回看/有状态/有记录） | 干活产生的会话全部可在总管回看 |
| 记录 | **任务台账**（kernel/task-sessions/ + auto-runs 合一） | 干过的活在一处查得到 |
| 页面 | **零演示页**（演示标记清零） | 全站无 `.demo-note` |
| 旧物 | **删光**：`jco-handoff` 代码路径、`jco-chat-auto-` 前缀、活动日志里的"干活记录"职责 | `rg "jco-handoff"` 等 grep 为空 |

**过渡期纪律**：施工期间允许的"两套"= 欠账清单上的条目，**只减不增**；每迁一个入口，删一段旧代码。

## 二、任务会话桥设计（核心）

### 2.1 概念

**任务 = 一次让 AI 干的活**（不管谁触发）：自动任务到点、用户点「马上跑」、发布页派活、运营页取评论……
每个任务 = 一个**任务会话**（`jco-chat-task-<taskId>`）+ 一条**任务台账记录**（状态/结果/消息）。
「跳总管看 AI 干活」不再是"把任务塞进用户聊天"，而是**总管打开这个任务会话**（观察窗）——一套会话，两种到达方式（自动/手动）。

### 2.2 数据流

```
触发（到点 / 马上跑 / 派活）
   → TaskRunner.launch（唯一引擎，已建成）
   → bridge.ask(会话 jco-chat-task-<id>，staff 标签)
   → onNotification 累积消息（用户卡 + assistant 增量）
   → 落盘 kernel/task-sessions/<id>.json（消息 + 状态 running/done/failed + 摘要）
   → 广播 kernel:task 事件（taskId、phase、summary）
   → 总管页/通知 呈现
```

### 2.3 接口契约（新增）

| 通道 | 方向 | 载荷 | 返回 | 说明 |
|---|---|---|---|---|
| `tasks:dispatch` | 渲染 → 主 | `{ name, prompt, staff? }` | `{ ok, taskId }` | **派活**（替代 handoff）：建任务并开跑 |
| `tasks:sessions` | 渲染 → 主 | — | `{ tasks: [{ id, name, staff, state, startedAt, summary }] }` | 任务列表（总管"任务"分区） |
| `tasks:session:get` | 渲染 → 主 | `{ id }` | `{ task: { …, messages } }` | 单任务完整消息（回看） |
| `kernel:task`（事件） | 主 → 渲染 | `{ taskId, phase: 'start'/'done'/'fail', summary? }` | — | 状态变化推送 |

**任务台账格式** `kernel/task-sessions/<taskId>.json`：

```json
{ "id": "t-abc", "name": "发抖音", "staff": "publish", "state": "done",
  "startedAt": 0, "endedAt": 0, "summary": "……",
  "messages": [ { "role": "user", "text": "任务卡…", "t": 0 },
                { "role": "assistant", "text": "……", "t": 0 } ] }
```

（自动任务的执行记录 `auto-runs.json` 保留为"调度视野"的摘要层；任务台账是统一的消息层——两文件、各司其职，页面只展示一处。）

### 2.4 总管页形态

- 左侧会话列表新增**「任务」分区**（跑着 / 最近完成，按时间倒序；来源含自动任务与派活）；
- 点任务 → 右侧渲染任务会话（消息流 + 状态徽章：跑着/完成/没跑成）；
- 系统通知点击 → 打开对应任务会话（v1 通知不可点，跳转进下一步）；
- **日常聊天**（jco-chats-v1）与**任务会话**彻底分开：聊天不再被派活污染。

### 2.5 迁移批次与旧物退休

| 批次 | 迁移 | 退休（同批删除） | 验收 |
|---|---|---|---|
| 批 1 | 发布页「让 AI 发到平台」→ `tasks:dispatch` + 跳任务会话 | 发布页的 `jco-handoff` 写入 | E2E + 真机 + grep |
| 批 2 | 运营页「马上跑 / 取评论 / 发出去」→ 同上 | 运营页 handoff | 同上 |
| 批 3 | 首页入口卡片 → 同上 | 首页 handoff | 同上 |
| 批 4 | 自动任务会话前缀 `jco-chat-auto-` → `jco-chat-task-`；活动日志"干活记录"职责收编 | `consumeOpenChat` 的 handoff 分支、旧前缀、jco-handoff 全部代码 | `rg "jco-handoff|jco-chat-auto-"` 为空 |
| 批 5 | 总管页老会话兼容清理 | — | 回归全绿 |

每批都必须：单测/E2E 更新（红先绿后）+ 两道 UI 门 + 台账更新 + **删除代码的 grep 证据**贴进验收记录。

## 三、E2E 用例（随批施工，先写会失败的）

| # | 场景 | 断言 |
|---|---|---|
| B1 | 发布页派活 | 点击 → 不写 jco-handoff；`tasks:dispatch` 收到；页面跳总管并打开"任务会话"（标题=任务名，状态"跑着"） |
| B2 | 任务会话实时 | 执行中：消息流追加 + 状态"跑着"；结束：状态"完成/没跑成" + 摘要 + 通知 |
| B3 | 任务列表 | 总管"任务"分区列出最近任务（含自动任务的历史） |
| B4 | 回看 | 重启应用后点旧任务 → 完整消息与结果还在（落盘） |
| B5 | 旧物清零 | `rg "jco-handoff"` 无生产命中（仅测试可留迁移断言） |

## 四、风险与降级

| 风险 | 预案 |
|---|---|
| 任务会话与聊天分区带来的界面复杂度 | 分区默认折叠；数量上限（最近 20 条）+ "看全部"进后续 |
| 消息累积的性能（长任务几百条） | 增量批量落盘（≤1 次/秒）；渲染复用 M0 的"批量插入 + 80 条上限"纪律 |
| 迁移中断（批间状态） | 每批独立可发布：批 N 完成前，旧入口照常可用（旧代码不动）；批 N 的迁移与删除必须同批完成 |
| 用户已在用的旧会话数据 | 只影响"以后的新活"；旧聊天与旧记录不迁移、不破坏 |
