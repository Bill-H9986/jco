# 变更单 CR-001：发布工作流改为「AI 实时操作」形态

（按《J.Co 软件开发工作流标准》附录 C 模板 · 留痕执行）

- **日期**：2026-10-16
- **来源**：产品负责人直接指示（原话："我要的工作流不是脚本！！！而是 AI 实实在在的在操作！！！是可以随时跟进变化的！不是像脚本一成不变的！！！"）
- **对象**：M1 发布工作流设计包（已冻结版）

## 变更内容（四件事）

1. **驱动方式**：从"写死的步骤流水线（脚本驱动）"改为 **"AI 实时操作浏览器"**——AI 看页面真实状态 → 决策 → 执行 → 再看，逐步推进到目标；
2. **适应变化**：页面改版、弹窗挡路、意外提示 → 由 AI 实看实处理（**不再依赖固定选择器**；选择器仅作辅助加速提示）；
3. **随时跟进**：用户在会话里随时插话（"标题改一下""封面也设上""先别传了"）→ AI 在**同一浏览器会话**里继续操作；
4. **平台差异**：从"每平台适配包（选择器 + 流程代码）"转为 **"每平台【平台要点卡】（给 AI 读的说明书）+ 通用浏览器工具集"**。

## 原因

产品定位要求（"AI 实实在在在干"）；脚本形态不适应页面变化、不可对话跟进、易碎。

## 影响评估

**保留复用**（已完工部分不浪费）：

- 浏览器会话与登录态管理（本机持久、按平台隔离）
- 进程隔离与 stdio 协议（主进程 ↔ 子进程）
- 错误如实上报契约、状态机与错误码表
- 发布红线设计（**永不自动点发布**）
- 平台规则卡（字数等硬约束，供 AI 引用）
- 元素地图（本文档同目录）——AI 的"地形情报"

**方向调整**：

- 原"适配层选择器流水线"降级为**辅助能力**（快速通道提示）；
- 原设计中的"v2：收编进内核工具面"**提前为当前主线**（ADR-0001 随之修订）；
- 确定性发消息流程 → **AI 操作循环**（看 → 想 → 做 → 核对）。

**新增设计（下一步）**：

- **浏览器工具集**：打开页面 / 抓页面快照（可交互元素+结构）/ 点击 / 输入 / 上传文件 / 滚动 / 截图 / 清障；
- **AI 操作循环**：每次操作前取最新页面快照（不依赖缓存状态），操作后核对结果；
- **与 DSH 内核的挂接**：发布员工 = 内核工具面按角色挂载（正式启用"员工"机制）。

**设计包修订**：

- 技术方案 → v1.1（新增《AI 操作架构》章节，替代"确定性流水线"定位）；
- 接口契约 → 增补工具面定义（AI 可调用的原子操作清单）。
