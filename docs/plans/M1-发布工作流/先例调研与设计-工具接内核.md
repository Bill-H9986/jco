## 一、先例调研结论

### 1. DSH 本身就是答案（本地官方文档与源码，全部可照抄）

> 出处：`app/node_modules/@deepseek-ai/dsh*` 的 README 与源码（官方，同版本 rc.2）

**工具定义有官方 API**（形态照抄 dsh-tool-jobs）：

```js
import { defineTool } from '@deepseek-ai/dsh-tools'
export const name = '...'; export const inject = []; export const Config = ...
export function apply(ctx, config) {
  ctx.tools.register(defineTool({
    name: 'tool_name',
    description: '面向模型的说明',
    parameters: { /* 类型化 schema */ },
    output: { schema, render },
    async execute(args, exec) { /* ... */ },
  }))
}
```

- **注册即生效**：工具 schema 自动进入系统提示词，模型即可调用；
- 插件 = 一个 ESM 包（`{ name, inject, Config, apply }` 导出），本地已有 20+ 个官方样本可抄。

**挂载方式 = patch 行**（我们已在用的机制）：

```yaml
- insert:
    - id: jco-publish-tools
      name: '<插件包名或路径>'
      config: { /* 原样传给 apply 的第二个参数 */ }
```

- bridge.mjs 已通过 `patches: [jco-chat.patch.yml, dynamic-model.patch.yml]` 给内核传 patch——发布工具只需再挂一行。

### 2. Anthropic 官方《工具设计指南》（Appendix 2, Building Effective Agents）

> 出处：anthropic.com/engineering/building-effective-agents（原文已抓取留档）

- 把工具当 **ACI（Agent-Computer Interface）** 来设计——投入给 HCI 同等用心（"像给团队初级工程师写 docstring"）；
- 好工具定义包含：**用法示例、边界情况、输入格式要求、与其他工具的分界**；
- **Poka-yoke（防呆）**：让参数"想犯错都难"（官方案例：SWE-bench 里把相对路径改为强制绝对路径，模型立刻零错）；
- 给模型**思考余地**（别逼它边写边数行数）。

### 3. 应用（对我们 8 个工具的改进方向）

| 官方建议 | 我们的落实 |
|---|---|
| 防呆 | `click / type_text` 只收"快照里的 ref 编号"（不收坐标/选择器，想点错都难）；`open_page` 强制域名白名单 |
| 描述含用法与分界 | 每个工具描述写明"什么时候用我、例子、边界"（中文） |
| 输出可读 | `snapshot` 输出模型易读的编号清单，ref 与 click 参数一一对应 |

## 二、设计（架构方案）

### 核心难点

工具 handler 运行在**内核进程**里；浏览器会话在 **app 侧**（登录态、进程管理都在那边）。两者需要一条简单可靠的通道。

### 方案：内核里放"瘦代理"插件，app 侧起"会话服务"，回环 HTTP 相连

```text
[内核进程 DSH]
  └─ jco-publish-tools 插件（8 个工具，瘦代理）
        · handler：POST http://127.0.0.1:<port>/tool { name, args }
        · endpoint/token：每次调用时读 app\kernel\publish-session.json（动态取址，不重启内核）
              ↕ 本机回环 HTTP（Bearer token 鉴权）
[app 侧 · 发布会话服务  publish/session-server.mjs]（主进程按需启停）
        · 常驻浏览器会话（复用引擎同款启动配置 / 登录态目录）
        · POST /tool → 调用 tools.mjs 的 8 个实现 → 返回结构化结果
        · GET /health；无活跃会话时明确报"请先启动发布会话"
```

### 设计决策（为什么这么定）

1. **HTTP 回环**：跨进程最简单可靠的通道（不依赖 SDK 的双向调用机制，避免未知协议风险）；只绑 127.0.0.1 + 每次启动随机 token（防本机其他程序乱调）；
2. **endpoint 动态读文件**：内核**不需**为会话启停而重启（插件静态挂载、动态取址）——少重启、更稳定；
3. **工具常驻可见**：没会话时调用 → 返回"还没有活跃发布会话，请先启动"（说人话，AI 会转告用户）；
4. **登录态与凭据不出 app 侧**：内核插件只转发工具名与参数，不接触任何凭据。

### 安全评审清单对照（每个新 AI 能力过八问）

| 问题 | 回答 |
|---|---|
| 接触隐私数据？ | 插件不接触（凭据/登录态都在 app 侧会话服务内） |
| 读取不可信内容？ | 工具结果（页面快照）会进 AI 上下文——已按"资料≠指令"标记（提示词安全铁律） |
| 能对外通信？ | 仅 127.0.0.1 回环，不对公网 |
| 有不可逆动作？ | 工具集内没有发布/删除/支付类能力（有测试守着） |
| 记日志？ | 会话服务记录每次工具调用（动作/参数/结果摘要） |
| 出错停下？ | 工具失败 → 结构化错误返回（AI 如实转告，不硬闯） |
| 数据出本机？ | 否 |
| 新增风险面？ | 回环端口 + token（本机内防护）；工具面白名单（与安全规范一致） |

### 施工计划（下一步）

1. **最小插件实验**：写 hello 工具插件 → 验证挂载方式（patch 行用本地路径 or `dsh plugin add` 安装）→ dump-config 确认
2. **会话服务**：`publish/session-server.mjs`（起浏览器 + /tool 端点 + 日志 + token）
3. **正式插件**：8 个工具（描述按 Anthropic 指南写：用法/分界/例子/防呆）
4. **接线**：主进程启停会话服务；bridge 补第三个 patch
5. **真机联调**：聊天里说"打开抖音发布页"→ AI 调用 `open_page` → 真实执行——"AI 的手"第一次上岗
