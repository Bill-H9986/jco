## 一、架构总览（v1：确定性流水线，独立于内核工具面）

**一条工作流，所有平台共用；各平台差异全部收进"适配包"。**

```
┌─ 渲染层（J.Co工作台-发布.html 增量：入口按钮 + 状态条 + 平台选择）
│     ↕ IPC（preload 暴露 publish.*，载荷带 platform 字段）
├─ 主进程 · 发布引擎（app/src/publish-engine.ts → 编译进 dist，由 main.js 加载）
│     · 任务单例 / 子进程生命周期 / 状态机 / 错误翻译（平台无关）
│     ↕ stdio 行 JSON（每行一个事件，平台无关协议）
└─ 引擎子进程（app/publish/engine.mjs）
      · Playwright 驱动系统 Edge（持久化上下文，按平台分 profile）
      · 加载平台适配包：app/publish/platforms/<平台>/
      │     ├─ adapter.mjs   页面操作（打开 / 登录检测 / 上传 / 填写 / 就绪）
      │     ├─ selectors.mjs 选择器集中一处（平台改版只改这里）
      │     └─ rules.json    平台规则卡（标题字数 / 话题数量 / 视频规格）
      └──→ 平台发布页
```

### 引擎 / 适配层边界（什么写一次、什么每平台写）

| 层 | 内容 | 频次 |
|---|---|---|
| 引擎（通用） | 浏览器启动与 profile 管理、状态机、协议、超时、错误翻译、任务单例 | **写一次** |
| 界面（通用） | 入口按钮、状态条、停止、记录（只多显示一个平台名） | **写一次** |
| 契约（通用） | IPC / 事件 / 错误码 / 数据结构（带 platform 字段） | **写一次** |
| **适配包（每平台）** | 打开页 / 登录检测 / 上传 / 填写 / 就绪判定 + 选择器 + 规则卡 | **每平台一个小包** |
| 测试 | A/B 级用例逐平台参数化；C 级真站验收逐平台执行 | 复用 + 逐平台验收 |

## 二、关键决策记录（ADR-0001）

**v1 发布助手不进 DSH 内核工具面。**

- 理由 ①：v1 流程是确定性动作（打开 → 上传 → 填写 → 停），不需要模型自主决策；
- 理由 ②：内核工具面挂载涉及插件开发与权限面（jchat 工具面刚收口，避免反复）；
- 理由 ③：浏览器自动化与内核解耦，出错面最小，符合"最小可用"纪律；
- v2 收编路径已预留：助手可作为工具挂进内核（按员工角色挂载），模型自主调用"发到抖音"。
- 详见 `docs/adr/0001-发布助手v1独立于内核工具面.md`。
- 通用引擎 + 适配层决策：详见 `docs/adr/0002-通用发布工作流与平台适配层.md`。

## 三、组件设计

### 3.1 渲染层（发布页增量）

- 新增：「发到抖音」主按钮；发布助手状态条（阶段文字 + 细进度 + 「停止」）
- 走 UI Kit 零件；改完过 preflight + 视觉守门员（两道门）

### 3.2 主进程模块（新代码走 TypeScript 通道）

- 位置：`app/src/publish-douyin.ts`（M0 建立的首块业务 TS 代码，编译到 `app/dist/`）
- 职责：
  - 任务单例（同平台同时刻只允许一个任务）
  - 启动/停止子进程（带超时兜底，复用内核桥的"最终期限"经验）
  - 状态机维护 + 事件转发（IPC → 渲染层）
  - 错误翻译（错误码 → 用户文案）

### 3.3 发布引擎子进程 + 平台适配包

- **引擎（通用）**：`app/publish/engine.mjs`——浏览器启动 / 持久化 profile / 状态机驱动 / stdin-stdout 协议 / 截图诊断
- **适配包（每平台一个小目录）**：`app/publish/platforms/<平台>/`
  - `adapter.mjs`：实现统一适配接口（open / detectLogin / uploadVideo / fillMeta / waitForReady——见《接口契约》第二节）
  - `selectors.mjs`：该平台选择器集中一处（平台改版只改这里）
  - `rules.json`：平台规则卡（标题字数 / 话题数量 / 视频规格）——供文案生成与界面提示读取
  - 首个：`platforms/douyin/`
- 浏览器：Playwright `chromium.launchPersistentContext(profileDir, { channel: 'msedge', headless: false })`
  - profileDir：`%userData%\publish\<平台>\profile`（本机持久登录态，各平台互不干扰）
  - 不下载 Playwright 自带浏览器（用系统 Edge，体积零增长）
- 流程状态机（平台无关）：
  `launching → opening → login_check → (awaiting_login) → uploading → filling → ready → closed`
- **代码级红线**：适配接口不提供"点击发布"的能力函数（无方法可调用）

## 四、关键技术点

1. **登录检测**：进入发布页后，出现上传控件 = 已登录；出现扫码框/跳登录 = 未登录（实现时以真实页面实测为准）
2. **视频上传**：定位 `input[type=file]` → `setInputFiles(视频绝对路径)` → 等待上传完成信号（进度消失/资源渲染出现）
3. **标题与话题**：抖音"作品描述"为富文本输入区；写入格式 `标题文案 #话题1 #话题2`（话题逐个键入并等待候选，实现时实测确定）
4. **等待上限**：登录等待 10 分钟；上传 5 分钟；每步失败给明确错误（不无限转圈）
5. **可停止**：主进程终止子进程 + 子进程 finally 关闭浏览器上下文
6. **单例锁**：任务运行中再次 start → 直接返回"已有任务进行中"

## 五、风险与降级预案

| 风险 | 预案 |
|---|---|
| 抖音页面结构改版（选择器失效） | 适配层集中管理；报 `PAGE_CHANGED`"抖音页面变了，等我更新适配"；降级：只开页面、用户手动 |
| 出现验证码 / 风控 | 暂停自动化、如实提示（**绝不绕过**）；用户手动处理 |
| 上传大文件慢 | 进度可见 + 上限 5 分钟 + 可重试 |
| 本机无 Edge | 报 `BROWSER_MISSING`："请先安装 Microsoft Edge" |
| 多任务冲突 | 单例锁 |
| 打包版路径问题 | 子进程脚本与 profile 路径全部走"打包/开发"双分支（吸取 M0 经验） |
