# 抖音发布页 · 元素地图（侦察档案）

> 侦察时间：2026-10-16 · 登录态实测（截图与原始数据在本轮工作区 `work/recon-*`）
> 用途：发布工作流设计的**唯一页面依据**——每个元素"是什么、要不要碰、怎么碰"。
> 来源：产品负责人指示"先把整个发布页面有哪些元素摸清楚再说"。

## 一、页面结构总览

抖音发布分**两个页面阶段**：

1. **上传选择页**（`creator.douyin.com/creator-micro/content/upload`）
2. **发布编辑页**（上传完成后自动进入）——所有信息在此填写

发布编辑页的版面（实测）：

```
┌─ 基础信息
│   ├─ 标题输入框（独立，与描述分离）
│   ├─ 作品描述框（含 #话题 / @好友，字数 0/1000）
│   ├─ 官方活动（活动卡片 ×N）
│   ├─ 设置封面（横封面 4:3 / 竖封面 3:4 / AI 推荐封面）
│   ├─ 添加合集
│   └─ 自主声明
├─ 扩展信息
│   ├─ 添加标签：位置（地点关键词输入）
│   └─ 关联热点（热点词输入）
├─ 发布设置
│   ├─ 谁可以看：公开 ✓ / 好友可见 / 仅自己可见
│   ├─ 保存权限：允许 ✓ / 不允许
│   └─ 发布时间：立即发布 ✓ / 定时发布
└─ 底部操作区：发布 ｜ 暂存离开（附提示"点击发布后…等待上传发布完成"）

右侧：手机样机预览（预览视频 / 预览封面·标题）、添加音乐、重新上传、发文助手（检测建议）
```

## 二、元素全清单与工作流策略

策略图例（2026-10-16 修正——产品负责人纠正：发布流程的每一步都是"该管的"）：
✅ **发布本职步骤**（AI 按任务卡执行；任务卡未指定时主动处理——给候选/询问，不许绕过不做）｜
🎛️ **按任务卡与判断**（用户要求时执行；"要不要"的判断也是 AI 的工作，该提醒就提醒）｜
🧹 清障（挡路提示自动清掉）｜ 🔒 红线（发布按钮及一切不可逆动作，永不自动）

> **重要修正说明**：此前把"封面 / 合集 / 声明 / 位置"等标为"默认不碰"是**错误的归类**。它们**属于发布工作本身**：
> "发布这件活"= 视频 + 标题 + 话题 + **封面** +（按需）声明 / 合集 / 位置等全套步骤，**少一件都不算干完**。
> "不该管"只指**任务之外的事**；发布流程里每一步都是"该管的"，差别只在"怎么落实"（直接执行，或给候选让用户拍板）。

### 上传选择页

| 元素 | 形式 | 策略 |
|---|---|---|
| 「上传视频」选择区 | button + `input[type=file]` | ✅ 工作流入口（选文件） |
| 顶部导航（首页 / AI 分身 / 随变 / 世界书 / AI 工坊） | 按钮组 | 🎛️ 非发布步骤（不主动碰） |

### 基础信息区

| 元素 | 形式 | 说明 | 策略 |
|---|---|---|---|
| **标题框** | input（占位"填写作品标题，为作品获得更多流量"） | **独立标题**（与描述分离，实测确认） | ✅ AI 填（来自 J.Co 发布页的标题） |
| **作品描述框** | contenteditable（0/1000） | 简介文字；话题写在这里 | ✅ AI 填（话题以 # 形式写入） |
| #添加话题 | 触发话题联想面板 | 键入 # 弹出候选 | ✅（AI 键入并确认） |
| @好友 | 触发面板 | | 🎛️（任务卡要求时） |
| 官方活动卡片 | 卡片（带热度值） | 参加官方活动 | 🎛️（任务卡要求时） |
| 设置封面：横封面 4:3 | 「选择封面」卡片 → 弹窗 | 上传图/选帧 | ✅ **发布本职步骤**——AI 必须处理（打开弹窗、准备候选）；用哪张由用户拍板 / 任务卡指定 |
| 设置封面：竖封面 3:4 | 同上 | | ✅ 同上（平台建议双封面） |
| AI 智能推荐封面 | 生成中… | 平台生成 | 🎛️（生成后可作候选参考） |
| 添加合集 | 下拉（合集 / 请选择合集） | 归入合集 | 🎛️+判断（账号有合适合集时按任务卡归入；没有则跳过并在汇报里提一句） |
| 自主声明 | 下拉 | 内容声明 | 🎛️+判断（内容需要声明时主动提醒用户定） |

## 二·补 · "一次完整发布"的岗位职责清单（AI 该办的全套，一件不少）

> 这就是"发布员工"的完整职责——**每一步都是"该管的"**；"不该管"仅指任务之外的事（改用户设置、动无关资料等）。

1. 传视频（本职）
2. 填标题（本职）
3. 写描述 / 话题（本职）
4. **设封面：横 4:3 + 竖 3:4**（本职：打开弹窗、准备候选——用视频帧或任务卡给的图片；用哪张由用户拍板）——**【此前遗漏，重点补齐】**
5. 自主声明（按需：内容需要时主动提醒用户定）
6. 合集（按需：账号有合适合集时按任务卡归入）
7. 位置 / 热点 / 官方活动（按需：任务卡要求时）
8. 发布设置（可见范围 / 保存权限 / 发布时间——默认值正确则不动，任务卡指定则改）
9. 全程核对（快照 / 截图确认填对）
10. 停在发布前交接（发布永远由用户亲手点）

### 底部与右侧

| 元素 | 形式 | 策略 |
|---|---|---|
| **发布** | 主按钮 | 🔒 **永不自动点击**（发布动作永远由用户亲手完成） |
| 暂存离开 | 次按钮（存草稿退出） | ⏭️（"取消流程"时可用来留草稿——后续细化） |
| 手机样机预览 | 面板（预览视频 / 预览封面·标题） | ⏭️ |
| 添加音乐 | 按钮 | ⏭️（后续可选） |
| 重新上传 | 按钮 | ⏭️ |
| 发文助手 | 右下角检测面板（如"横/竖双封面缺失"建议） | ⏭️（只读参考） |

### 提示与气泡（清障对象）

| 元素 | 行为 | 策略 |
|---|---|---|
| 「上传成功」toast | 自动消失 | 🧹 无需处理 |
| 「视频预览功能」气泡 +「我知道了」 | 挡在表单右上 | 🧹 AI 点"我知道了"清掉 |
| 浏览器「了解你的位置」权限弹窗 | 浏览器原生弹窗 | 🧹 AI 选"拒绝"（发布不需要位置权限） |

## 三、对上一版实现的重要修正（已核实）

1. **标题与描述是分开的两个框**——上一版把"标题+话题"整体写进了描述框；修正为：**标题 → 标题框；话题 → 描述框**。
2. 描述框上限 **1000 字**（界面上写明）；标题上限以平台实际提示为准（校准步骤实测）。
3. 封面有**横 / 竖两套**（AI 推荐与发文助手都提示"建议双封面"）——**属于发布本职步骤**（AI 必须处理；用哪张给用户候选拍板）。

## 五、封面弹窗 · 侦察结果（2026-10-16 实测，纳入本职步骤）

**结构**（横封面 4:3 编辑视图）：

- 顶部 Tab：**「设置横封面」/「设置竖封面」**（两个视图切换；横不过瘾可直接"设置竖封面"）
- 左侧工具列：AI封面 / 模板 / 贴纸 / 标题 / 文字 / 滤镜（含「AI生成封面」按钮）
- 中央：视频画面预览（带 4:3 裁剪框）+ 下方**时间轴帧选择条**（拖动换帧）
- **「上传封面」**：本地上传封面图入口（+ 黑块）
- 右侧：手机样机预览 + "横封面预览（4:3）"
- 底部：封面检测 / **「完成」** / **「设置竖封面」**；右上 **×**（ESC 同样可关）
- 平台提示："设置两张封面将获得更多曝光和推荐"（双封面是建议动作）

**操作路径（AI 的）**：

1. 点"选择封面"卡 → 弹窗出现
2. 选图（三选一）：任务卡给了封面图 → 「上传封面」+ 文件对话框（upload_file 工具已支持此模式）；
   没给图 → **默认帧直接用**（不拖时间轴，直接「完成」）或点「AI生成封面」等生成后采用；
3. 「完成」→ 横封面设定 →（建议）「设置竖封面」→ 同样操作 → 完成
4. 关闭：× 或 ESC

> 说明：已具备的工具集（click/type/upload/snapshot/scroll/wait/screenshot）可覆盖上述路径；
> 拖动时间轴换帧暂不作为 v1 依赖项（默认帧 + 上传封面图已满足本职）。
