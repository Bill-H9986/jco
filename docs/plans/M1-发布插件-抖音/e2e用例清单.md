# M1 发布插件（抖音）· E2E 验收用例清单

> 状态：**待拍板**（拍板后冻结）｜制定日期：2026-10-16
> 设计冻结包 · 第 4/4 件 —— 先写"此刻会失败"的用例，施工即以变绿为目标。

## A 级 · 全自动（进 gate）

| # | 场景 | 断言 |
|---|---|---|
| A1 | 发布页存在「发到抖音」入口 | 按钮存在、可用、走 UI Kit 样式 |
| A2 | 点击后进入启动态（演示模式） | 状态条出现"正在启动发布助手…"；演示模式不启动真进程 |
| A3 | 停止操作 | 点击「停止」→ 状态复位 `idle` |
| A4 | 助手单例 | 任务进行中重复 start → 返回 `BUSY`（"已有任务进行中"），不产生第二个任务 |
| A5 | 错误码 → 文案映射（单测级） | 7 个错误码全部有 friendly 文案，无遗漏 |
| A6 | 红线检查（代码级） | 适配层源码中不存在"发布按钮"操作能力（静态断言） |
| A7 | 状态机单测 | 状态转移合法（非法转移被拒绝）：launching→opening→…→ready |

## B 级 · 半自动（本机有 Edge；可跑到登录检测为止）

| # | 场景 | 断言 |
|---|---|---|
| B1 | 助手启动 → Edge 打开抖音发布页 | 子进程启动成功；日志含 opened；页面标题属于抖音域名 |
| B2 | 未登录 → 状态事件序列 | 收到 `awaiting_login`（或已登录时直接进入后续状态） |
| B3 | 停止 → 浏览器关闭 | 无残留浏览器子进程；脚本退出码 0 |

## C 级 · 人工验收（真站全流程，产品负责人执行）

| # | 场景 | 通过标准 |
|---|---|---|
| C1 | 首次：扫码登录 | 登录完成后**自动继续**，无需二次操作 |
| C2 | 上传 + 填写 | 视频出现在抖音上传区并上传完毕；标题与话题出现在作品描述框 |
| C3 | 停在发布前 | **页面无任何自动发布动作**；由用户亲手点"发布" |
| C4 | 记录 | 应用内可见"已交接"发布记录（时间 / 标题 / 文件） |
| C5 | 二次使用 | 登录态保留（不再要求扫码） |

## 数据与清理

- 测试 profile 目录独立（`--jco-test` 模式走临时目录）
- 真站测试产生的草稿由用户自行处理（不做自动清理，避免误删）
- 验收证据留档：截图存 `release/`（随封版材料）
