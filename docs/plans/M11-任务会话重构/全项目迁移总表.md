# M11 全项目迁移总表

- 日期：2026-10-17
- 范围：整个 J.Co 软件与项目，不只是前端页面。
- 关联：
  - `全站迁移矩阵.md`（页面层）
  - `技术方案.md`（架构与模块）
  - `接口契约.md`（IPC/工具/数据）
  - `验收用例.md`（功能与细节）

## 一、结论

M11 的完成标准不是“页面看起来统一”，而是：

```text
用户界面
  + 主进程
  + 领域模型
  + DSH 内核
  + 提示词与工具权限
  + 浏览器会话
  + ffmpeg/媒体处理
  + 数据存储与迁移
  + IPC/安全边界
  + 安装/升级/回滚
  + 测试/日志/文档
```

全部达到同一套契约和验收标准。

任何一层单独做完都不算交付。

## 二、全项目分层总表

|---|---|---|---|---|---|

| **主进程 / 生命周期** | `main.js`：窗口、托盘、主题、通知、单实例、测试模式 | 业务逻辑继续堆在 main.js；测试/生产混合 | 只做装配与生命周期；业务下沉 Application | Wave 0–1 | main 体积/职责检查 + 安装版冒烟 |

| **数据 / 存储** | localStorage + 多份 JSON | 双写、分叉、截断、迁移丢失 | Repository + 单一 store + schemaVersion + 原子写 + 备份 | Wave 0–4 | 迁移/回读/恢复测试 |
| **IPC / preload** | `window.jco` 多组 API，部分页面直接调用 | 契约不清、错误不可读、旧 API 分叉 | 受控 API、错误码、兼容层、契约测试 | Wave 0–1 | 契约测试 + 旧 API 兼容测试 |
| **安全 / 审批** | 提示词红线 + 部分工具限制 | 通用 click 可点发布；上传路径未限；提示注入 | 工具最小权限、域名跳转校验、路径白名单、Approval 门、审计 | Wave 1–4 | 安全评审 + 对抗测试 |
| **安装 / 升级 / 回滚** | electron-builder + asarUnpack；未签名 | 缺依赖、旧版本残留、升级/卸载不干净 | 固定打包清单、安装版冒烟、版本/升级/卸载/回滚脚本 | Wave 5 | 安装/升级/卸载/回滚实测 |
| **测试 / 质量门禁** | typecheck/lint/unit/E2E/audit | 结构断言多、真实链路少、无视觉回归 | 单元/契约/集成/E2E/视觉/安装/真内核/真浏览器/真 ffmpeg | Wave 0–5 | 全部门禁 + 证据 |

## 三、依赖关系

```text
Renderer（页面/组件）
   │ 只能通过 preload
   ▼
IPC 契约
   │
   ▼
Application（用例层）
   ├─ Domain（Conversation / Task / TaskRun / Approval）
   ├─ Kernel（HarnessPool / PromptBuilder）
   ├─ BrowserSession（仅任务需要）
   ├─ EditTools（仅后期任务）
   └─ Store（单一事实源）
          │
          ▼
安装包（main + preload + kernel + tools + ffmpeg + assets）
```

关键规则：

- Renderer 不能绕过 IPC 直接读写文件/启动浏览器/拼 prompt；
- Application 不能依赖 Electron 细节；
- Domain 不能依赖 DSH/文件系统/浏览器；
- 所有副作用必须可追踪到 TaskEvent；
- 所有危险动作必须经过 Approval；
- 所有页面和工具必须通过同一套契约测试。

## 四、全项目不可妥协的十条

1. **一个事实源**：会话、任务、草稿、素材、发布记录、设置逐步迁到统一 store。
2. **一个任务台账**：自动任务、页面派活、聊天任务卡共用 TaskService。
3. **一个提示词源**：Base + BrandProfile + Role + TaskCard + Skills，不在页面里写行业身份。
4. **一个工具权限模型**：聊天/发布/运营/后期各自白名单，不共享全量工具。
5. **一个审批模型**：发布、删除、支付、登录等不可逆/敏感动作统一 Approval。
6. **一个兼容层**：旧 localStorage 只读，旧 API 有 deprecation 期限，不双写。
7. **一个安装包真相**：安装版必须与源码、tag、CHANGELOG 对齐；打包后真机冒烟。
8. **一个测试体系**：单元/契约/集成/E2E/视觉/安装/真内核/真浏览器/真 ffmpeg。
9. **一个细节门禁**：D0–D4，没有截图/回归/证据不算完成。
10. **一个完成定义**：全站矩阵 + 全项目分层总表全部 `verified`，才叫交付。

## 五、波次与全项目范围

### Wave 0：地基与兼容

- Domain / Application / Repository；
- TaskStateMachine；
- JsonStore + 迁移；
- IPC 契约 + preload；
- HarnessPool + PromptBuilder；
- 旧 API 兼容层；
- 全项目扫描门禁。

### Wave 1：核心闭环

- 应用壳、首页、聊天、任务详情；
- 主进程职责收口；
- 任务状态机 + Approval；
- 纯聊天不启动浏览器；
- 消息组件 + 视觉回归；
- 安装版冒烟第一轮。

### Wave 2：内容生产链

- 选题、素材、创作、做视频、后期；
- Artifact / 草稿 / 素材 / 稿件 / 成片；
- ffmpeg 工具超时、取消、路径守卫；
- 跨页旅程：选题 → 创作 → 做视频 → 后期。

### Wave 3：发布与运营链

- 发布、运营、账号中心；
- BrowserSession 生命周期；
- 平台适配层；
- 发布 Approval、评论回复 Approval；
- 真浏览器登录/发布冒烟（发布按钮仍人点）。

### Wave 4：系统与支撑

- 设置、自动任务、技能库、管家团队、设计系统；
- BrandProfile 全站生效；
- 自动任务统一台账；
- 员工状态来自 TaskEvent；
- 可观测性与诊断。

### Wave 5：全项目验收

- 16 个现有页面 + 新任务详情全部 `verified`；
- 全项目分层总表全部 `verified`；
- 单元/契约/集成/E2E/视觉；
- 安装/升级/卸载/回滚；
- 真内核/真浏览器/真 ffmpeg；
- 安全审查；
- 文档与发布说明；
- 产品负责人普通用户视角验收。

## 六、全项目完成定义

必须同时满足：

- [ ] 页面：16 个现有页面 + 新任务详情全部 `verified`；
- [ ] 数据：旧数据迁移成功，读写只走统一 store，消息不截断；
- [ ] 任务：自动任务/派活/聊天任务卡同一台账；
- [ ] 提示词：聊天/员工/任务分层，行业由 BrandProfile 提供；
- [ ] 工具：聊天无浏览器/编辑工具，发布/运营/后期各自白名单；
- [ ] 审批：发布/删除/支付/登录有统一 Approval；
- [ ] 内核：真实内核可启动、可取消、可超时、可恢复；
- [ ] 浏览器：只在任务中启动，能登录、能操作、能停在发布前；
- [ ] ffmpeg：超时/取消/路径守卫/新文件输出；
- [ ] 安装包：安装、升级、卸载、回滚、真机冒烟；
- [ ] 测试：单元/契约/集成/E2E/视觉/真机全部有证据；
- [ ] 安全：工具权限、上传限制、域名校验、提示注入防护；
- [ ] 日志：任务时间线、错误码、诊断导出；
- [ ] 文档：需求、ADR、迁移矩阵、运行手册、发布说明同步；
- [ ] 产品负责人：普通用户视角走完全流程。
