# 证据：创作素材选择、壳缓存与媒体参数（0.6.0-beta.29）

> 日期：2026-10-20
> 范围：创作页素材选择、应用壳 iframe 缓存、视频清晰度参数、后台任务取消进度、E2E 测试隔离。

## 一、先红后绿

### 1. 应用壳缓存错页

新增 `tests/e2e/m18-create-picker-shell.spec.mjs`，使用真实应用壳：

1. 进入创作页；
2. 点击「素材」打开 `?pick=1`；
3. 不确认，切到首页；
4. 再回创作页。

第一次运行失败：回创作页时找不到 `#agentHint`。根因是应用壳缓存命中只看页面 key，没有校验 iframe 当前 URL；创作 iframe 已经自行跳成素材选择页，却被当成创作页直接激活。

修复：

- `J.Co应用壳.html` 增加 `frameMatchesTarget()`；
- 缓存命中前校验 URL，不一致就丢弃旧 iframe；
- 页面路由保留查询串，侧栏高亮只取文件名；
- 创作页素材选择改走父级 `__jcoGo`，不再让内容 iframe 自己跳走。

### 2. 缓存创作页收不到已选素材

第二次运行失败：已经回到创作页，但 `#pickedBar` 仍然隐藏。根因是创作页被应用壳缓存复用，不会重新执行初始化 IIFE，素材页写入的 `sessionStorage` 没有消费者。

修复：

- 创作页把素材恢复逻辑提取为 `consumePickedMaterials()`；
- 素材页确认后向父级应用壳发送 `__jcoPickerReturn`；
- 应用壳切回目标页后向该页发送 `__jcoPickedMaterials`；
- 每次打开选择页带新的 `pickSession`，避免复用旧 pick-mode 选择。

### 3. 视频清晰度参数与取消进度

新增/扩展 `tests/unit/media-jobs.test.mjs`：

- 旧草稿传 `res: '1080P'`，后台任务必须归一化为 `720P` 后再调用视频模型；
- 两段视频取消在第一段生成中，完成 1/2 后进度必须是 50%，不能写成 100%。

修复：

- `media-jobs.cjs` 增加视频支持清晰度白名单 `720P`；
- 出片调用使用 `normalizeVideoRes(job.params.res)`，不再写死；
- 取消收口按已完成段数计算真实进度；
- 做视频页 `draftToStore` / `normalizeLoadedDraft` 同步归一化旧草稿。

### 4. E2E 数据隔离

全量门禁第一次运行发现 `m9-material` 读到 M18 留下的素材，空库断言失败。处理：

- M18 在 `finally` 清空测试素材；
- M9 空库用例在开始时自己准备空库，不依赖前序测试清理顺序；
- `main.js` 把 `--jco-test` 的 `app.setPath('userData')` 移到所有发布会话/素材目录/设置初始化之前。

- 4K 图片仍按 `size=4K + aspect_ratio` 下发，但没有消耗真实额度跑 4K。
- 真实平台扫码登录、最终发布、真实浏览器/ffmpeg 专项仍属于发布前人工确认或独立专项。
