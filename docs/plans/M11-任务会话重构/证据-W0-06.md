## 3. 失败可见性

- 不传 `--baseline` 直接运行 `node scripts/check-all.mjs`，退出码为 1，逐条打印当前违规；
- 新增违规不在基线内 → gate 退出 1（单元测试验证 `filterBaseline` 的 fresh 分支）；
- `--update-baseline` 默认拒绝吸收新增违规，必须显式 `--force`；这是防止“把新问题写进基线”的闸门；
- `--strict` 忽略全部基线，用于 Wave 5 最终验收；
- 迁移进度与视觉基准在非严格模式下只报告，不会用“0/17”把日常 gate 卡死；W5 用 `--strict` 要求全部达标。
