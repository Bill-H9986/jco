# W1-05 证据：真实内核接线 + 纯聊天无浏览器

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标 E2E

```powershell
cd app
npx playwright test tests/e2e/m11-kernel-wiring.spec.mjs
```

结果：`1 passed`。

覆盖：

- 应用内真实内核聊天回复非空；
- 纯聊天前后 BrowserSession 都不是 active；
- 纯聊天不创建 Task；
- “帮我写一条短文案”生成任务卡；
- 确认后进入独立任务详情，审批后由真实内核执行；
- 任务最终状态 `done`，时间线出现“任务执行完成”，任务带 assistant 消息。

## 2. 实现

- `main.js` 新增 `runWorkTask()`：审批通过后按任务类型选择 writer / publisher / editor / operator profile；
- 用 `buildTaskPrompt()` 生成任务提示词，用户内容只发一次；
- 内核活动转成任务 `tool_call` 事件，工具参数不进入界面；
- 执行结果写回同一 work-task 状态机；
- 总管页在 busy 时禁用发送，避免“点击发送但没发出去”的静默失败；
- 真实聊天链路保持 chat profile，无浏览器工具。

## 3. 既有契约

- P-01～P-04：`kernel-layer.test.mjs` 9 条、真实内核冒烟、无行业写死；
- R-02：应用内真实内核返回文本；
- R-03：纯聊天不启动 BrowserSession；
- Agent Eval K-05 / K-06 / K-07 已覆盖 chat/publisher/预算。

## 5. 已知边界（不虚报）

- 发布任务的真实浏览器全链路仍在 W3-01/W3-04；
- ffmpeg 真实任务执行仍在 W2-05；
- 任务卡自动提案仍是本地意图识别，尚未由模型直接返回结构化 TaskCard；
- 自动任务仍走现有 `bridge.ask`，不是独立 Application 服务；
- W1-05 验证的是真实内核聊天 + 内容任务执行，不是多平台发布成功。
