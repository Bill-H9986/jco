# M11 接口契约：IPC、事件与错误码

- 日期：2026-10-17
- 状态：设计冻结中
- 原则：Renderer 只通过 `window.jco` 受控 API 访问主进程；不直接读写文件、不直接启动浏览器、不直接拼 prompt。

## 一、Renderer API 总览

```ts
window.jco.conversations = {
  create(input): Promise<Conversation>
  list(): Promise<ConversationSummary[]>
  get(id): Promise<ConversationDetail>
  send(input): Promise<SendResult>
  rename(input): Promise<{ ok: true }>
  remove(input): Promise<{ ok: true }>
  share(input): Promise<{ text: string }>
}

window.jco.tasks = {
  create(input): Promise<Task>
  list(): Promise<TaskSummary[]>
  get(id): Promise<TaskDetail>
  confirm(input): Promise<Task>
  cancel(input): Promise<Task>
  retry(input): Promise<Task>
  events(input): Promise<TaskEvent[]>
}

window.jco.automations = {
  list(): Promise<Automation[]>
  sync(items): Promise<{ ok: true; count: number }>
  runNow(id): Promise<{ ok: true; taskId: string }>
}

window.jco.brand = {
  get(): Promise<BrandProfile>
  save(profile): Promise<BrandProfile>
}

window.jco.approvals = {
  resolve(input): Promise<{ ok: true }>
}

window.jco.events = {
  onConversationMessage(cb): void
  onConversationDelta(cb): void
  onTaskEvent(cb): void
  onTaskState(cb): void
  onApprovalRequested(cb): void
}
```

旧 API（`kernel.ask`、`tasks.dispatch`、`tasks.sessions`、`tasks.session`）在迁移期保留为兼容层，标记 deprecated，Phase 1 完成后移除。

## 二、Conversation

### 2.1 `conversation:create`

请求：

```ts
{
  title?: string
  initialMessage?: string
  source?: 'home' | 'sidebar' | 'task' | 'other'
}
```

响应：

```ts
{
  id: string
  title: string
  messages: Message[]
  createdAt: number
  updatedAt: number
}
```

规则：

- 没有 `initialMessage` 时，允许创建一个空会话；
- 全库最多保留一个空会话；
- `initialMessage` 存在时，服务端先创建会话，再走 `conversation:send`；
- 不创建任务，不启动浏览器。

### 2.2 `conversation:send`

请求：

```ts
{
  conversationId: string
  text: string
  clientMessageId?: string
}
```

响应：

```ts
{
  ok: true
  messageId: string
  conversationId: string
}
```

规则：

- 先持久化用户消息，再调用内核；
- 用户消息不能因为模型失败而丢失；
- 助手消息流式写入，完成后落最终文本；
- 失败时保留错误消息，提供重试；
- 发送只使用 `chat` profile，不含浏览器/编辑工具；
- 不允许在这里调用 `tasks.dispatch`。

### 2.3 `conversation:list`

响应：

```ts
Array<{
  id: string
  title: string
  lastMessage: string
  messageCount: number
  updatedAt: number
}>
```

规则：

- 按 `updatedAt` 倒序；
- 不返回完整消息；
- 空会话最多一个。

### 2.4 `conversation:get`

响应：

```ts
{
  id: string
  title: string
  messages: Array<Message>
  createdAt: number
  updatedAt: number
}
```

规则：

- 历史消息完整返回，允许分页参数后续扩展；
- 不在读取时截断内容；
- 不混入任务事件。

### 2.5 `conversation:rename`

请求：

```ts
{ id: string; title: string }
```

规则：

- 标题去首尾空格，最多 60 字符；
- 空标题拒绝；
- 不改变消息内容。

### 2.6 `conversation:remove`

请求：

```ts
{ id: string }
```

规则：

- 删除会话和消息；
- 不删除由该会话创建的任务；
- 若删除的是当前会话，返回下一个可用会话 id；
- 至少保留一个空会话或创建新的空会话。

### 2.7 `conversation:share`

请求：

```ts
{ id: string }
```

响应：

```ts
{ text: string }
```

规则：

- 输出纯文本；
- 不带密钥、内部路径、工具参数；
- 由 Renderer 调用剪贴板。

## 三、Task

### 3.1 `task:create`

请求：

```ts
{
  title: string
  goal: string
  type: 'content' | 'publish' | 'operate' | 'edit' | 'research' | 'custom'
  ownerRole: string
  inputs: Array<{ kind: string; ref: string; label?: string }>
  constraints: string[]
  deliverables: string[]
  approvalPolicy: {
    requirePublishApproval: boolean
    requireDeleteApproval: boolean
    requirePaymentApproval: boolean
    requireFinalApproval: boolean
  }
  sourceConversationId?: string
  sourceAutomationId?: string
  parentTaskId?: string
}
```

响应：`Task`

规则：

- `title`、`goal`、`deliverables` 不能为空；
- `approvalPolicy` 对发布/删除/支付必须为 `true`；
- 创建后状态为 `draft`；
- 不直接执行；
- `sourceConversationId` 只用于追溯，不把任务塞回聊天流。

### 3.2 `task:confirm`

请求：

```ts
{ id: string }
```

规则：

- 只有 `pending_confirm` 可确认；
- 确认后 `queued`，由 TaskRunner 启动；
- 确认动作写入 TaskEvent；
- 确认不是“自动执行”的替代品，危险动作仍需后续 Approval。

### 3.3 `task:cancel`

请求：

```ts
{ id: string; reason?: string }
```

规则：

- `draft` / `pending_confirm` / `queued` / `running` / `waiting_user` 可取消；
- `done` / `cancelled` 不可再取消；
- 取消后不再产生新副作用；
- 写入 TaskEvent。

### 3.4 `task:retry`

请求：

```ts
{ id: string }
```

规则：

- 只有 `failed` 可重试；
- 创建新的 TaskRun，不覆盖旧 Run；
- 旧错误保留；
- 重试不绕过审批策略。

### 3.5 `task:get`

响应：

```ts
{
  task: Task
  runs: TaskRun[]
  events: TaskEvent[]
  artifacts: Artifact[]
  approvals: Approval[]
}
```

规则：

- 任务详情只读聚合；
- 事件按时间正序；
- 不返回密钥/token/完整工具参数。

### 3.6 `task:list`

响应：

```ts
Array<{
  id: string
  title: string
  type: string
  ownerRole: string
  status: TaskStatus
  updatedAt: number
  source: 'manual' | 'conversation' | 'automation'
}>
```

规则：

- 自动任务产生的任务必须出现在这里；
- 按 `updatedAt` 倒序；
- 状态徽标由 Renderer 映射。

### 3.7 `task:events`

响应：`TaskEvent[]`

规则：

- 只追加；
- 可按 `after` 游标增量拉取；
- `summary` 面向用户，`data` 供诊断。

## 四、Approval

### 4.1 `approval:resolve`

请求：

```ts
{
  approvalId: string
  decision: 'approved' | 'rejected'
  note?: string
}
```

规则：

- 只有 `pending` 可处理；
- `approved` 后任务从 `waiting_user` 回到 `running`；
- `rejected` 后任务进入 `cancelled`；
- 发布/删除/支付类审批必须由用户主动点击，不能由 AI 代点；
- 写入 TaskEvent。

## 五、Automation

### 5.1 `automation:sync`

请求：

```ts
{
  items: Array<Automation>
}
```

规则：

- 只同步计划模板；
- 不直接执行；
- 与任务台账分离。

### 5.2 `automation:runNow`

请求：

```ts
{ id: string }
```

响应：

```ts
{ ok: true; taskId: string }
```

规则：

- 创建 Task，不另写一份执行记录；
- 与到点执行走同一 TaskService；
- 同一 Automation 同一时刻防重入。

### 6.2 `conversation:delta`

```

```

## 七、错误码

```ts
type JcoErrorCode =
  | 'INVALID_INPUT'
  | 'NOT_FOUND'
  | 'INVALID_STATE'
  | 'APPROVAL_REQUIRED'
  | 'TOOL_NOT_ALLOWED'
  | 'BROWSER_UNAVAILABLE'
  | 'KERNEL_TIMEOUT'
  | 'KERNEL_ERROR'
  | 'STORE_WRITE_FAILED'
  | 'MIGRATION_FAILED'
  | 'INTERNAL_ERROR'
```

响应统一：

```ts
{
  ok: false
  error: {
    code: JcoErrorCode
    message: string
    retryable: boolean
    detail?: string
  }
}
```

规则：

- 用户可见消息必须是人话；
- `detail` 只放诊断信息，不含密钥；
- Renderer 不按字符串猜错误类型，只认 `code`。

## 八、工具权限矩阵

| Profile | 浏览器工具 | ffmpeg 工具 | 文件写入 | 说明 |
|---|---:|---:|---:|---|
| `chat` | 否 | 否 | 否 | 只聊天/规划/任务卡 |
| `task:publisher` | 是 | 否 | 受控上传 | 发布前必须 Approval |
| `task:operator` | 是 | 否 | 受控报告 | 只读数据/评论草稿 |
| `task:editor` | 否 | 是 | 成片目录 | 不覆盖原件 |
| `task:writer` | 否 | 否 | 否 | 纯文本产出 |

必须新增契约测试：

- chat profile 的工具列表不包含 `jco_open_page`、`jco_click`、`jco_upload_file`、`jco_add_subtitles` 等；
- publisher profile 不包含 shell/任意文件工具；
- editor profile 不包含浏览器发布工具；
- 任何 profile 都不能绕过 Approval 直接发布/删除/支付。

## 九、持久化不变量

- 消息完整保存，读取与写入内容一致；
- TaskEvent 只追加；
- TaskRun 不覆盖历史；
- Automation 不产生第二套执行记录；
- 删除会话不级联删除任务；
- 删除任务不删除用户文件，只删除关联；
- 迁移幂等，失败不覆盖旧数据。
