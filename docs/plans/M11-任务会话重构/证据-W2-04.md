# W2-04 证据：做视频页迁移

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标 E2E

```powershell
cd app
npx playwright test tests/e2e/m11-drafts-store.spec.mjs
```

结果：`1 passed`。

覆盖：

- 旧 `jco-drafts-v1` 首次进入时迁入统一 `drafts.json`；
- 视频草稿的 3 段分镜、2 段已出片仍可打开、整片分段连播；
- 图片草稿的图片板仍可打开；
- “按我说的改”写入统一草稿层，旧 localStorage 不再新增双写；
- BrandProfile（健身 / 上班族 / 直接）进入分镜与图片方案提示词；
- 刷新后草稿仍由统一层恢复。

## 2. 实现

- 主进程新增 `drafts.json`：草稿数组、字段规范化、原子写；
- 草稿字段保留分镜、图片、分段视频、修改要求、创建/更新时间；
- “生成中”恢复为“待检查”，“出片中”恢复为“失败可重试”，不伪装进度；
- `drafts:get/save/migrate` IPC 与 preload 受控 API；
- 做视频页启动先渲染旧草稿，再异步 hydrate；统一层非空时按 id 合并旧草稿；
- 所有草稿保存点（生成完成、出片完成、换画面、修改要求、通过）统一走 `drafts.json`；
- 旧版大图（无落盘路径且超过 300KB）继续拒绝写入，避免撑爆 JSON；
- 做视频页的修改要求、分镜状态和成片状态不再只存在 localStorage；
- 修复既有 `m9-video` 对旧 `jco-drafts-v1` 的断言，改为验证统一草稿层。

## 4. 已知边界（不虚报）

- 本 E2E 没有真实调用模型生成分镜/出图/出片，避免烧接口额度；它验证的是迁移后的真实展示、播放入口和保存链路；
- 草稿是 Artifact 风格的记录（含 id、类型、分镜、图片、成片路径、时间），还没有绑定 TaskEvent/Task 完整模型；
- 图片/视频文件仍放在受控素材目录，草稿只保存路径；没有自动清理孤立文件；
- 做视频页仍是旧 iframe 结构，组件级原生化留到后续。
