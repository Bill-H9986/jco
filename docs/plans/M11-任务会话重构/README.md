## 范围说明

M11 **不是只做首页/聊天/任务三块**。M11 的目标是把整个项目迁移到同一套会话、任务、数据、提示词和组件架构；只是施工按波次推进，避免一次性大爆炸重写。

| 波次 | 页面 |
|---|---|
| Wave 0 | 契约、兼容层、迁移器、共享组件骨架 |
| Wave 1 | 应用壳、首页、总管、任务详情 |
| Wave 2 | 选题、素材、创作、做视频、后期 |
| Wave 3 | 发布、运营、账号中心 |
| Wave 4 | 设置、自动任务、技能库、管家团队、设计系统 |

完整矩阵见 `全站迁移矩阵.md`。

## 产品负责人需要确认的规则

1. 首页发送 = 新会话；
2. 派活 = 显式任务卡确认；
3. 纯聊天不启动浏览器；
4. 任务详情独立于聊天；
5. 自动任务与派活共用任务台账；
6. 行业由 BrandProfile 提供，不写死；
7. 发布/删除/支付永远人工确认；
8. 细节按 D0–D4 验收。

## Phase 1 施工顺序（Wave 1）

1. Domain 类型 + TaskStateMachine + 单元测试；
2. JsonStore + 迁移 + 测试；
3. IPC + preload + 契约测试；
4. HarnessPool + PromptBuilder + 工具白名单；
5. Message 组件 + 视觉基准；
6. 首页新会话 + 聊天视图；
7. 任务卡 + 任务详情 + Approval；
8. Automation 统一台账；
9. E2E + 安装版 + 真实内核冒烟；
10. 产品负责人验收。
