# M11 验收用例（先写会失败的测试）

- 日期：2026-10-17
- 状态：设计冻结中
- 规则：每条用例必须有 Given / When / Then、证据类型、失败时的用户可见结果。

## 一、会话

### C-01 首页发送创建新会话

- Given：用户打开首页，没有正在进行的会话；
- When：输入“你好”并发送；
- Then：
  - 创建一个新会话；
  - 进入聊天视图；
  - 消息从上往下显示；
  - 不创建 Task；
  - 不启动 BrowserSession；
  - 不打开系统浏览器。

证据：E2E + 截图 + 事件断言。

### C-02 第二个会话独立

- Given：已有会话 A；
- When：点击“新会话”，发送“第二个会话”；
- Then：
  - 出现会话 B；
  - A 的内容不变；
  - 切回 A 能看到原消息；
  - 切回 B 能看到新消息；
  - 不出现多个空会话。

证据：E2E + localStorage/store 断言。

### C-03 历史消息完整

- Given：助手返回一条超过 5000 字的回答；
- When：刷新应用并重新打开会话；
- Then：
  - 消息内容与首次显示一致；
  - 不被 2000 字截断；
  - Markdown 段落、列表、代码块仍正确。

证据：单元测试 + E2E + 文本快照。

### C-04 消息顺序与输入框

- Given：会话有 20 条消息；
- When：打开会话；
- Then：
  - 第一条消息在顶部，最新消息在底部；
  - 输入框固定在页面底部；
  - 滚动到底部后输入框不漂移；
  - 1280×800 和 1440×900 都不溢出。

证据：几何断言 + 视觉回归。

### C-05 历史操作

- Given：存在一个历史会话；
- When：打开会话 `⋯` 菜单；
- Then：
  - 重命名后标题持久化；
  - 分享复制完整纯文本；
  - 删除需要二次确认；
  - 删除当前会话后回到可用会话；
  - 不删除由该会话创建的任务。

证据：E2E + store 断言。

## 二、任务

### T-01 聊天中提出任务卡

- Given：用户在会话中描述“把这条视频发到抖音”；
- When：AI 回复；
- Then：
  - AI 可以提出任务卡；
  - 任务卡包含目标、输入、产出、约束、审批点；
  - 用户确认前不创建 Task；
  - 用户确认后创建 Task；
  - 不直接启动浏览器。

证据：E2E + mock harness 事件。

### T-02 任务详情独立

- Given：存在一个 Task；
- When：点击左侧任务；
- Then：
  - 进入任务详情页；
  - 显示状态、目标、输入、产出、时间线、产物、审批；
  - 不把任务消息塞进聊天流；
  - 点击对话能回到会话。

证据：E2E + 视觉回归。

### T-03 状态机

- Given：Task 在 `pending_confirm`；
- When：依次执行 confirm / start / complete；
- Then：
  - 状态只能按合法边迁移；
  - 非法迁移返回 `INVALID_STATE`；
  - 每次迁移写 TaskEvent。

证据：单元测试。

### T-04 取消

- Given：Task 在 `running`；
- When：用户取消；
- Then：
  - 状态变为 `cancelled`；
  - 不再产生新的工具调用；
  - 已产生的产物保留；
  - 写入 TaskEvent。

证据：集成测试 + 事件断言。

### T-05 失败重试

- Given：TaskRun 失败；
- When：用户点重试；
- Then：
  - 创建新的 TaskRun；
  - 旧 Run 和错误保留；
  - 不覆盖历史；
  - 审批策略仍然有效。

证据：集成测试。

### T-06 审批门

- Given：发布任务到达“准备点发布”；
- When：AI 请求继续；
- Then：
  - 任务进入 `waiting_user`；
  - 创建 `publish` Approval；
  - AI 不能自己批准；
  - 用户批准后才继续；
  - 用户拒绝后任务取消。

证据：集成测试 + 工具白名单测试。

## 三、自动任务

### A-01 到点创建同一种任务

- Given：Automation 计划时间已到；
- When：调度器 tick；
- Then：
  - 创建一个 Task；
  - 出现在总管任务区；
  - 使用同一 TaskService；
  - 不写第二套 auto-run 台账。

证据：集成测试 + store 断言。

### A-02 马上跑

- Given：Automation 存在；
- When：点击“马上跑”；
- Then：
  - 创建 Task；
  - 返回 taskId；
  - 与到点执行同一状态机；
  - 同一 Automation 防重入。

证据：E2E + 集成测试。

## 四、提示词与工具

### P-01 系统提示词不含行业

- Given：BrandProfile 为空；
- When：构建 ChatPrompt；
- Then：
  - 不出现“成人学历”“招生”等默认身份；
  - 默认是通用自媒体助手；
  - 行业由 BrandProfile 提供。

证据：单元测试 + `check:no-hardcoded-industry`。

### P-02 Chat 无浏览器工具

- Given：构建 chat profile；
- When：生成工具白名单；
- Then：
  - 不包含 `jco_open_page`、`jco_snapshot`、`jco_click`、`jco_upload_file`；
  - 不包含 ffmpeg 工具；
  - 不包含 shell/文件写入工具。

证据：契约测试。

### P-03 Publisher 工具正确

- Given：构建 `task:publisher` profile；
- When：生成工具白名单；
- Then：
  - 包含浏览器工具；
  - 不包含 shell/任意文件工具；
  - 发布动作必须经过 Approval。

证据：契约测试 + 对抗审查。

### P-04 不再拼系统提示词

- Given：调用 kernel；
- When：构造输入；
- Then：
  - 用户消息只包含用户内容；
  - 系统提示词通过 profile/patch 注入；
  - 不出现 `system + '\n\n' + text` 形式的拼接。

证据：单元测试 + 源码检查。

## 五、细节与视觉

### D-01 聊天消息视觉基准

- Given：固定窗口 1440×900、固定数据；
- When：渲染用户消息、AI 消息、长文本、列表、代码块；
- Then：
  - 视觉回归通过；
  - AI 消息不是 84% 宽大卡片；
  - 阅读宽度、字号、行高符合规格；
  - 1280×800 不溢出。

证据：Playwright 视觉回归。

### D-02 状态齐全

- Given：消息组件；
- When：切换空态、加载、错误、长文本、深色；
- Then：
  - 每个状态都有明确视觉；
  - 不出现空白、文字溢出、按钮错位；
  - 截图齐全。

证据：视觉回归 + 截图。

### D-03 键盘与焦点

- Given：聊天页/任务详情；
- When：只用键盘操作；
- Then：
  - Tab 顺序合理；
  - 焦点可见；
  - Enter 发送；
  - Shift+Enter 换行；
  - Esc 关闭弹层。

证据：Playwright 键盘测试。

### D-04 可访问性

- Given：聊天页/任务详情；
- When：运行 axe / 键盘检查；
- Then：
  - 无严重/致命可访问性问题；
  - 对比度、标签、按钮名称、焦点顺序合格。

证据：axe 报告 + 人工走查。

## 六、安装版与真实内核

### R-01 安装版入口

- Given：安装版启动；
- When：应用加载；
- Then：
  - 入口为应用壳；
  - 首页、聊天、任务视图可用；
  - 测试窗口不抢桌面。

证据：安装版冒烟 + 截图。

### R-02 真实内核

- Given：干净环境，无 `NODE_PATH`；
- When：发送一条消息；
- Then：
  - 内核 `ready: true`；
  - 返回真实文本；
  - 不误开浏览器；
  - 错误可读。

证据：真实内核冒烟。

### R-03 浏览器只在任务中启动

- Given：纯聊天；
- When：发送“你好”或“帮我写个标题”；
- Then：
  - 不启动 BrowserSession；
  - 不出现系统浏览器；
  - 任务型“发布”请求才启动。

证据：E2E + 进程/端口断言。

## 七、全站兼容与跨页回归

### X-01 旧数据迁移

- Given：本机存在旧 `jco-chats-v1`、`jco-drafts-v1`、`task-sessions/*.json`；
- When：启动新版本；
- Then：
  - 会话、草稿、任务迁移到新 store；
  - 所有页面读同一份数据；
  - 不重复、不丢消息、不覆盖旧备份。

证据：迁移单元测试 + E2E + 数据对比。

### X-02 旧 API 兼容

- Given：尚未迁移的旧页面仍调用 `window.jco.kernel.ask` / `tasks.dispatch`；
- When：打开旧页面执行操作；
- Then：
  - 兼容层不报错；
  - 写操作只写新 store；
  - 不产生第二套任务台账；
  - 不启动不该启动的浏览器。

证据：契约测试 + 跨页 E2E。

### X-03 全站 BrandProfile

- Given：修改 BrandProfile 的行业/受众/语气；
- When：打开选题、创作、做视频、发布；
- Then：
  - 提示词读取新 BrandProfile；
  - 不出现旧行业写死内容；
  - 各页结果风格一致。

证据：单元测试 + `check:no-hardcoded-industry`。

### X-04 跨页任务台账

- Given：从发布页创建一个任务；
- When：打开总管任务区、团队页、通知；
- Then：
  - 三处看到同一个 taskId/状态；
  - 任务详情一致；
  - 不出现第二套记录。

证据：跨页 E2E + store 断言。

### X-05 内容生产链

- Given：从选题页选一个题；
- When：进入创作写稿 → 做视频 → 后期；
- Then：
  - 主题/稿件/成片/产物链不断；
  - 每一步都能回到对应任务/产物；
  - 不丢数据、不出现旧格式。

证据：跨页 E2E。

### X-06 发布链

- Given：账号中心登记登录；
- When：发布页创建发布任务 → 任务详情 → 审批；
- Then：
  - 账号状态读取同一登记；
  - 发布任务进入统一台账；
  - AI 不会自动点发布；
  - 用户确认后才完成。

证据：跨页 E2E + 工具白名单测试。

### X-07 禁止业务页直写旧 localStorage

- Given：全站扫描；
- When：检查 `jco-chats-v1`、`jco-tasks-v1`、`jco-drafts-v1` 等业务 key；
- Then：
  - 业务页面不再写旧 key；
  - 旧 key 只读兼容；
  - 新写入全部走 store。

证据：`check:no-direct-business-localstorage`。

### X-08 16 个现有页面 + 新任务详情视觉与功能巡检

- Given：16 个现有页面 + 新任务详情；
- When：逐页加载并跑关键操作；
- Then：
  - 0 JS 错误；
  - 侧栏/输入台/助手球一致；
  - 关键状态视觉回归通过；
  - 不存在“新页面 + 旧样式”混用。

证据：全站审计 + 视觉回归 + 安装版巡检。
