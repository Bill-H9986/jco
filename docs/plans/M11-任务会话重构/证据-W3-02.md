# W3-02 证据：运营页战报/评论迁移

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标 E2E

```powershell
cd app
npx playwright test tests/e2e/m11-ops-store.spec.mjs
```

结果：`1 passed`。

覆盖：

- 战报和评论从统一 `ops.json` 读取；
- 页面不再显示演示评论；
- 修改评论回复草稿会写入统一层；
- “不用回”会把评论状态写成 `skipped`；
- “提交审批”会创建 operate Task，任务进入 `waiting_user`，评论标记 `pending_approval`；
- 拒绝审批后任务取消、评论标记 `rejected`，不会发送；
- 任务目标明确限制只回复指定评论，不得点赞/删除/发布其他内容。

## 2. 实现

- 主进程新增 `ops.json`：战报 + 评论数组 + 评论状态；
- `ops:get/save/update-comment` IPC 与 preload 受控 API；
- 读取时合并旧的 `report-latest.json` / `comments-latest.json`，旧数据不丢；
- 评论草稿编辑 600ms 防抖写入统一层；
- 运营页“马上跑 / 取评论”改走 `tasks.propose` + `tasks.confirm`；
- 只读的取战报/取评论任务不设审批，确认后直接执行；
- 评论回复任务使用 `type=operate` + `requireFinalApproval`，审批前不运行；
- `runWorkTask` 完成后把对应评论标记 `sent`/`failed`；
- 运营页首次进入显示空态，不再渲染旧演示评论；
- 扫描基线收紧到 1 条旧 `tasks.dispatch`。

## 4. 已知边界（不虚报）

- E2E 只验证审批和拒绝，不真实打开平台抓评论或发送回复；
- 取战报/取评论任务没有做真实浏览器/真实模型冒烟，属于 W3-04 平台适配范围；
- 旧的 `COMMENTS` / `LEADS` 演示数组仍留在页面源码中，但不再参与渲染，后续清理；
- 评论发送完成后目前只通过任务执行回写 `sent`/`failed`，没有平台回执校验；
- 账号中心登录登记仍使用本机 `jco-login-v1`，迁统一 store 属于 W3-03。
