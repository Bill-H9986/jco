# 证据：系统开关测试隔离（0.6.0-beta.36）

> 日期：2026-10-21
> 范围：开机启动、托盘开关在 `--jco-test` 下的真实系统副作用与跨重启状态。

## 一、风险与先红

此前 E2E 使用 `--jco-test` 和临时 userData，但开机启动与托盘 IPC 仍会执行生产逻辑：

- 开机会写真实 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`；
- 托班会创建真实系统托盘；
- 托盘开启后，生产代码会拦截窗口关闭，导致自动化进程无法可靠退出。

这会让测试污染用户系统，也可能让测试进程挂起。M26 初始运行因此卡在关闭窗口阶段。

## 二、修复

- 测试模式下 `sys:login` 只写临时 profile 的 `__testLoginEnabled`，`sys:login:get` 只读该内存状态；
- 测试模式下 `sys:tray` 只保存测试状态，不调用 `createTray()`；
- 应用重启后恢复测试开机启动状态；
- 测试模式即使托盘为开，也不拦截窗口关闭，不阻止 `window-all-closed` 退出。

## 三、验证

M26 使用同一临时 profile 启动两次真实 Electron 主进程：

1. 初始两个开关均为关；
2. 点击后均为开，并通过 IPC getter 读回；
3. 关闭主进程并重启，两个开关仍为开；
4. 再关闭两个开关，getter 均返回 false；
5. 测试前、首次关闭后、第二次关闭后，真实 `J.Co` Run 值快照完全一致。

## 四、边界

- 自动测试证明测试模式不写真实 Run 值、不创建生产托盘、状态契约可跨重启恢复。
- 非测试模式下真实开机启动和托盘仍需真机人工冒烟；自动测试不替代 Windows 登录后的真实启动验证。
