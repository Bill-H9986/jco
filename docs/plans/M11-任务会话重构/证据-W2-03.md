## 1. 目标 E2E

```powershell

npx playwright test tests/e2e/m11-scripts-store.spec.mjs
```

结果：`1 passed`。

覆盖：

- 旧 `jco-script-v1` 首次进入时迁移到统一 `scripts.json`；
- 手工编辑稿子后，输入事件经 700ms 防抖写入统一层；
- 旧 localStorage 不再新增双写，仍保留迁移来源数据；
- `scripts.json` 同时保留当前稿与稿件 Artifact 记录；

- 做视频页“手头素材”读取同一份稿件，显示主题与句数。

## 2. 兼容修复

回归时发现：旧版本在迁移后继续写 `jco-script-v1`，新版不能拿旧 store 覆盖它。

当前策略：

- 旧 key 的 `t` 比统一层 `updatedAt` 新时，保留旧稿并作为新 Artifact 迁入；
- 旧 key 更旧时只读兼容，不覆盖统一层；
- 该场景已被 `m8-topics` 提词器用例和 `m9-video` 手头素材行用例覆盖。

## 3. 实现

- 主进程新增 `scripts.json`：`current` + `artifacts`，字段规范化、原子写；
- `scripts:get/save/migrate` IPC 与 preload 受控 API；
- 创作页启动先渲染旧稿，再异步 hydrate 统一数据层；
- 手工改稿、生成稿、按用户意见改稿都落统一层；
- 修复“按我说的改”改完不保存的问题；
- “开始做视频”等待保存完成后再跳转，避免最后一笔改动丢失；
- 写稿提示词接入 `brand:get` 返回的 BrandProfile；
- 做视频页“手头素材”优先读取统一稿件，旧 localStorage 仅作首屏降级；
- E2E 数据护栏扩展到 `scripts.json`。

## 5. 已知边界（不虚报）

- 手工保存有 700ms 防抖；应用在这 700ms 内崩溃，最后一次输入可能丢失；
- Artifact 目前是稿件记录（current + artifacts），还没有“稿件版本历史”浏览界面；
- 创作页仍是旧 iframe 结构，组件级原生化留到后续；
- 稿件尚未绑定 Task/Artifact 全链路，X-05“每一步能回到对应任务/产物”留到后续单元。
