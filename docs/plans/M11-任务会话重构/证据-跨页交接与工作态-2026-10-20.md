# 证据：跨页交接与缓存工作态（0.6.0-beta.30）

> 日期：2026-10-20
> 范围：选题 → 文案/创作、创作 → 发布，以及主要页面的统一壳内导航。

## 一、先红后绿

新增 `tests/e2e/m19-cross-page-handoff.spec.mjs`，全部通过真实应用壳执行。

### 1. 选题 → 做视频

1. 打开做视频页，输入「旧工作态」；
2. 切到选题页；
3. 调用选题页真实的 `goMake('跨页交接主题')`；
4. 切到首页，再通过壳回到做视频。

第一次运行失败：回到做视频后，输入框仍是「旧工作态」，新主题被旧缓存页覆盖。

根因：

- 选题 iframe 直接 `location.href` 到做视频，产生第二份做视频页实例；
- 应用壳缓存里的 `做视频` key 仍指向旧实例；
- 再次点击创作时，壳激活旧实例，新交接内容丢失。

### 2. 选题 → 文案

同一测试继续验证「跨页文案主题」。旧实现切页回来后同样会回到旧缓存文案页。

### 3. 做视频 → 发布

1. 造一条已出片的视频草稿；
2. 在做视频页第一次点「这版可以了」，第二次点「去发布」；
3. 发布页标题正确带入「跨页发布标题」；
4. 切到首页，再通过壳回到发布页。

第一次运行失败：切回发布页后标题为空。旧实现由做视频 iframe 自己跳到发布页，`jco-publish-draft` 被临时实例消费；壳后来加载的是另一份发布页。

## 二、修复

- `jco-shell.js` 新增统一导航出口 `window.jcoGo(target, handoff)`。
- 嵌入壳时调用父级 `__jcoGo`，浏览器直开时才 `location.href`。
- 应用壳 `loadFrame` 在缓存命中、已有实例和新建实例三条路径都发送 `__jcoHandoff`。
- 文案页把主题消费提取为 `consumeTopicHandoff()`；做视频页提取 `consumeMakeTopicHandoff()`；发布页提取 `consumePublishDraftHandoff()`。
- 三个目标页都监听 `__jcoHandoff`，缓存页无需重载即可消费新交接。
- 选题、文案、做视频、发布、后期、设置、首页、总管的主要跨页入口改为 `jcoGo()`。

## 四、边界

- 页面内隐藏的旧侧栏仍保留少量 `location.href` 降级路径；嵌入应用壳时不可见，实际导航由壳承担。
- 本轮解决的是“切换页面后交接状态被旧缓存覆盖”，不宣称所有外部平台、模型非确定性和应用重启恢复都已穷尽。
- 下一轮继续审计：草稿/素材选择在应用重启后的恢复，以及动态弹层、详情面板的工作态。
