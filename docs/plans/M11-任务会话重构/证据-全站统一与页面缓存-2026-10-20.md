# 证据：全站统一与页面缓存（0.6.0-beta.26）

> 日期：2026-10-20
> 范围：用户本轮提出的页头固定、参数单行、开关统一、焦点收敛、全站工作态、切页卡顿，以及上一轮遗留的开关文字按钮规格不一致。

## 一、根因

| 问题 | 根因 | 修改位置 |
|---|---|---|
| 页头随内容滚走 | `.page-head` 是普通文档流元素，没有 sticky 定位 | `设计原型/assets/jco-ui.css` |
| 创作参数占两行 | `.left` 的素材/引用在 `.ask-bar`，五个参数在独立的 `.ask-params` | `设计原型/J.Co工作台-做视频.html` |
| 开关有三套视觉 | 设置/自动任务用 `.tg`，技能库用文字按钮 `.sk-toggle`，知识库用文字按钮 `.kb-mini` | `jco-ui.css`、技能库、设置 |
| 焦点外圈上下过大 | 全站主要用 `outline: 2px`，侧栏部分外扩 2px | `jco-ui.css` 公共焦点规则 |
| 切页卡顿 | 应用壳每次直接修改 `iframe.src`，整份文档、字体、脚本和 DOM 重新加载 | `J.Co应用壳.html` |
| 切页后工作态消失 | iframe 重建后页面内 DOM 和未落盘输入全部销毁 | 应用壳缓存 + `jco-shell.js` 草稿层 |
| 总管每次切会话重载 | `?new=1` / `?chat=` 作为 src 查询参数触发整页文档加载 | 总管 `postMessage` 页内导航 |

## 二、整体修改

### 1. 页面缓存

- 缓存键为页面文件名，最多 16 份，覆盖当前 15 个稳定页面。
- 非活动页面使用 `visibility: hidden`，保留 DOM、输入、滚动位置和页面内事件。
- 活动 iframe 动态持有唯一 `id="jcoFrame"`；原有 `frameLocator('#jcoFrame')` 和壳内路由继续可用。
- 首次访问显示加载遮罩；复访命中缓存，不修改 src，不重新加载文档。
- `m15` 实测缓存复访切换 `lastSwitchMs=2.4ms`，并断言 `loads=1`、`cacheHits>0`。

### 2. 总管页内导航

- 总管 iframe 只加载 `J.Co总管.html` 基础页。
- 首页发送、`#/chat/:id`、新会话通过 `__jcoShellChat` / `__jcoShellStartChat` 消息调用已有 `newChat()` / `switchChat()`。
- 会话哈希仍由总管页的 `notifyShellChat()` 回写，地址栏和刷新恢复不变。

### 3. 页头

- `.page > .page-head` 与 `.wrap > .page-head` 统一 sticky 到滚动区顶部。
- 负外边距抵消页面顶部 36px，标题初始坐标保持 `x=32, y=36`。
- `::after` 用 20px 背景补住原外边距，滚动时正文不会从页头缝隙透出，同时不改变页面初始总高度。

### 4. 开关与焦点

- `.tg` 成为唯一开关标准：44×26，圆钮 22px，位移 18px。
- 设置、自动任务、技能库、知识库全部使用 `.tg`。
- 共享脚本自动补 `role="switch"`、`aria-checked`，动态生成的开关同样生效。
- 开关圆钮阴影缩小为 `0 1px 2px rgba(0,0,0,.18)`，去掉 14px 大范围浮动阴影。
- 全站按钮焦点宽度统一为 1.5px；侧栏整行控件使用内缩焦点圈。

### 5. 全站工作态

- 页面切换：由 iframe 缓存保留完整 DOM 状态。
- 页面重载：`jco-shell.js` 自动保存普通文本输入和当前滚动容器位置，7 天过期，最多 200KB。
- 排除密码、文件、隐藏、只读、禁用字段，避免保存 API Key 等敏感内容。
- 后台生成：继续使用 `0.6.0-beta.25` 的主进程 `media-jobs`，页面缓存不是长任务唯一保障。

## 五、边界

- 页面缓存上限为 16 份，正常覆盖当前全部稳定页面；超过后淘汰最久未使用的非首页、非总管页面。
- 页面内直接调用的短 AI 请求在切换页面时由缓存保持；如果整个渲染进程重载或应用重启，仍会中断。图片/视频等长任务继续由主进程任务承担。
- 本轮没有修改发布溯源 tag、远程 Release 或 feed；该问题仍按产品负责人要求只记录，后续单独处理。
