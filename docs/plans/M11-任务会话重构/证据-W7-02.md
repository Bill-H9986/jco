# W7-02 证据：应用自动更新

- 日期：2026-10-19
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified（自动检查、后台下载、校验、退出安装和重启链路已在安装版真机跑通）**

## 1. 实现

- 接入 `electron-updater 6.8.9`，只由主进程持有更新器。
- 启动 15 秒后自动检查，之后按配置周期检查（默认 4 小时）。
- 设置页“关于”新增：
  - 当前 J.Co 版本；
  - 当前 DSH 版本；
  - 自动更新状态；
  - 手动检查更新 / 下载中 / 重启并更新。
- 更新源：
  - 生产只接受 HTTPS；
  - 本机联调只有显式 `JCO_UPDATE_ALLOW_INSECURE=1` 才允许 localhost HTTP；
  - 预发布版本固定使用 `alpha/beta/rc/next` 通道，不会误请求稳定版 `latest.yml`。
- 打包：
  - `npm run release:package` 生成 NSIS、blockmap、通道 yml 和 `release/feed`；
  - 包内 `app-update.yml` 固化更新源与通道。
- 静默安装：
  - `quitAndInstall(true, true)`；
  - 退出时自动安装，不需要用户再次点安装器。

## 2. 真机升级验证

### 2.1 发现问题并修正

第一条真机链路从 `0.6.0-beta.2` 检查更新时，`setFeedURL` 覆盖了包内 beta 通道，导致请求 `latest.yml` 404。

修正：

- 从版本号推导 `alpha/beta/rc/next`；
- 同时设置 `autoUpdater.channel` 与 feed channel；
- 重打修复合集。

第二条真机链路又发现安装器以交互模式停留。修正为：

- `quitAndInstall(true, true)` 静默安装并重启。

## 4. 关于 DSH

- 当前 npm `latest`：`@deepseek-ai/dsh 0.2.0-rc.2`，与包内版本一致。
- `next` 预发布：`0.2.1-rc.2`。
- 直接依赖中的 `@deepseek-ai/dsh-subagent-in-process-driver` 在 `0.2.1-rc.2` 没有发布版本，不能全量机械升级。
- 因此本轮没有把 DSH 的未完成预发布混入正式包。以后 DSH 升级必须整套版本对齐、跑内核/E2E/安装门禁，再通过本自动更新链路发布，不再由用户手动发安装包。

## 5. 边界

- 当前安装包和本地测试 feed 使用 `http://127.0.0.1:8787/updates`，只用于链路验证，生产不能使用。
- 生产需要提供稳定 HTTPS 静态更新地址；打包时设置 `JCO_UPDATE_FEED_URL`，然后把 `release/feed` 中的通道 yml、安装包和 blockmap 上传。
- 旧版 `beta.1` 不包含更新器，所以更新器启用前必须做一次引导安装；从 `beta.2` 起才可自动升级。
- 安装包仍未签名。electron-updater 会校验 yml 中的 SHA-512，但正式对外分发仍建议 Authenticode 签名。
