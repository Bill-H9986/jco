## 一、一句话目标

把 J.Co 从“页面按钮 + 多条 prompt 混在一起”改成**会话与任务分离、任务有明确状态和台账、AI 只在任务中执行副作用**的任务型 AI 工作台。

## 二、为什么现在做

当前已确认的结构性问题：

- 首页发送直接创建任务，聊天变成派活；
- 总管、派活、自动任务共用同一套系统提示词和工具面；
- 系统提示词写死行业；
- 聊天消息被截断、排版差、历史操作不完整；
- 自动任务和派活是两套台账；
- 浏览器工具对聊天也开放。

继续按页面补丁推进，会继续产生“首页像聊天、任务像聊天、聊天像发布助手”的边界问题。

## 三、范围

### 3.1 做

1. **会话**
   - 首页发送 = 新建独立会话；
   - 会话列表、切换、重命名、分享、删除；
   - 消息完整存储、完整历史、从上到下；
   - 消息组件按细节门禁重做。
2. **任务**
   - 任务卡：目标、输入、产出、约束、负责人角色、审批点；
   - 独立任务详情页；
   - 任务状态机与时间线；
   - 任务创建：用户在聊天中确认任务卡，或从页面显式创建。
3. **自动任务**
   - 只负责按计划创建同一种 Task；
   - 到点执行和“马上跑”都进入统一任务台账；
   - 总管任务区可见。
4. **AI 角色与工具**
   - 聊天提示词与员工提示词分离；
   - 纯聊天不挂浏览器/文件写入工具；
   - 发布、运营、后期各自按角色挂工具；
   - 发布、删除、支付永远人工确认。
5. **通用化**
   - 最小 BrandProfile：行业、受众、语气、平台、目标、禁用表达；
   - 系统提示词不再写死行业，默认中性；
   - 页面示例先改中性，Phase 2 再清理所有页面。
6. **数据**
   - Repository 接口；
   - v1 用主进程单一 JSON 存储，schemaVersion + 原子写入；
   - 统一 conversations / messages / tasks / task_runs / task_events / automations / artifacts / approvals。
7. **质量**
   - D0–D4 细节门禁；
   - 单元 / 契约 / 集成 / E2E / 视觉回归 / 安装版冒烟。
8. **全站迁移**
   - 不是只做首页/聊天/任务；
   - 16 个现有页面 + 新任务详情全部进入迁移矩阵；
   - 旧业务 localStorage 只读兼容，所有写操作迁到统一 store；
   - 所有页面统一组件、提示词、任务入口；
   - 详细见 `全站迁移矩阵.md`。

### 3.2 不做

- 不做一次性全站 React 重写；
- 不做所有平台发布适配；
- 不做多 Agent 并行；
- 不做自动登录探测；
- 不做复杂的视频时间轴；
- 不在 Phase 1 完成全部自媒体工作流；
- 不让 AI 自动发布、删除、支付。

## 四、目标用户旅程

### 旅程 A：首页聊天

1. 用户在首页输入一句话；
2. 系统进入一个独立新会话；
3. AI 回复/澄清，不启动浏览器；
4. 用户可继续聊，也可点“派活”。

### 旅程 B：聊天转任务

1. 用户在会话中描述一件事；
2. AI 生成任务卡，列出目标/输入/产出/约束/审批点；
3. 用户确认；
4. 进入任务详情页；
5. 任务执行，需要浏览器时申请；
6. 到审批点停下；
7. 用户确认后完成，产物入任务。

### 旅程 C：自动任务

1. 用户在自动任务页创建计划；
2. 到点创建 Task；
3. 总管任务区出现同一条任务；
4. 完成后通知，失败可重试。

### 旅程 D：历史会话操作

1. 用户打开历史会话；
2. 可重命名、分享、删除；
3. 长会话不卡、不截断；
4. 切换会话不丢任务视图。

## 五、验收标准

### 5.1 功能

- 首页发送后出现新会话，URL/状态可恢复；
- 纯聊天不启动任何浏览器；
- 聊天中 AI 可提出任务卡，但必须用户确认才创建 Task；
- 任务详情页可看目标、状态、时间线、产物、审批；
- 自动任务和派活出现在同一任务列表；
- 历史消息完整，无 2000 字截断；
- 重命名/分享/删除在真实壳内可用；
- 切换会话/任务不卡死；
- 系统提示词不出现“成人学历”默认身份；
- BrandProfile 修改后，聊天/任务上下文跟着变。
- 全站迁移矩阵中所有页面状态为 `verified`，不存在“新页面 + 旧数据”混用。

### 5.2 细节

- 消息组件按《细节任务卡-聊天消息》验收；
- 页面在 1280×800 / 1440×900 不溢出；
- 深浅色一致；
- 键盘可操作、焦点可见；
- 空态、加载、错误、长文本都有截图或测试；
- 视觉回归通过；
- 安装版冒烟通过。

### 5.3 证据

- 单元/契约/集成/E2E/视觉回归结果；
- 关键截图/录屏；
- 安装版和真实内核冒烟；
- 已知问题与未解决项；
- 产品负责人普通用户视角验收。

## 六、红线

- 首页发送不得直接创建任务；
- 纯聊天不得启动浏览器；
- 不得把系统提示词拼进用户消息；
- 不得写死行业；
- 不得自动发布/删除/支付；
- 不得恢复第二套任务台账；
- 不得用结构断言冒充细节验收；
- 不得在测试时抢用户桌面。

## 七、阶段

### Phase 0（本文件夹）

- 立项单；
- 领域模型与交互冻结；
- 技术方案；
- 接口契约；
- 验收用例；
- ADR；
- 聊天消息细节任务卡。

出口：设计冻结，产品负责人确认交互规则。

### Phase 1 / Wave 1（下一步施工）

- 数据层与状态机；
- 会话/任务 IPC；
- 首页新会话；
- 聊天消息组件；
- 任务卡与任务详情；
- 提示词/工具分离；
- 测试与安装版验收。

出口：旅程 A–D 全部通过，产品负责人验收。

### Wave 2：内容生产链

- 选题、素材、创作、做视频、后期；
- 数据、提示词、产物、任务入口统一；
- 跨页旅程：选题 → 创作 → 做视频 → 后期。

### Wave 3：发布与运营链

- 发布、运营、账号中心；
- 发布走 Task + Approval；
- 账号状态与登录登记统一；
- 跨页旅程：账号中心 → 发布 → 审批。

### Wave 4：系统与支撑页

- 设置、自动任务、技能库、管家团队、设计系统；
- 自动任务统一台账；
- BrandProfile 全站生效；
- 员工状态来自统一 TaskEvent。

### Wave 5：全站验收

- 16 个现有页面 + 新任务详情的迁移矩阵全部 `verified`；
- 跨页 E2E；
- 16 个现有页面 + 新任务详情的视觉回归；
- 安装版 + 真实内核/浏览器/ffmpeg 冒烟；
- 产品负责人普通用户视角验收。
