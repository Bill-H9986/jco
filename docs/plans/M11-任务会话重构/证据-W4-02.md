# W4-02 证据：自动任务页迁移

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标测试

```powershell
cd app
npx playwright test tests/e2e/m6-auto.spec.mjs tests/e2e/m11-auto-task-unified.spec.mjs
```

结果：`5 passed`。

覆盖：

- 旧 `jco-tasks-v1` 在首次进入时迁移到主进程 `auto-tasks.json`；
- 新建自动任务只写统一任务表，不再双写旧 localStorage；
- 任务卡仍显示具体时间、启停状态、上次执行 ✓/✗；
- 「马上跑」继续进入统一 work-task 台账；
- 到点执行与手动执行共用同一调度/执行管道。

## 2. 实现

- 主进程新增 `tasks:get` / `tasks:save`，自动任务定义统一读写 `auto-tasks.json`；
- `tasks:sync` 保留为旧调用兼容，内部复用同一规范化写入；
- 自动任务规范化保留 `when` 展示字段，并从 schedule 派生缺失值；
- 自动任务页启动先读旧 localStorage，再 hydrate 主进程任务表；
- 桌面应用不再写 `jco-tasks-v1`，旧 key 只做迁移来源/浏览器降级；
- 执行记录仍以 `work-tasks` 为唯一事实源，`auto-runs.json` 只做历史兼容；
- 任务启停、新建、马上跑全部走主进程任务表和统一执行管道。

## 4. 已知边界（不虚报）

- 旧 `auto-runs.json` 仍作为历史执行记录读取，不再新增写入；
- 自动任务的模型真实执行没有在本轮重新烧额度跑，执行链路由既有 W1-04/W1-05 覆盖；
- 自动任务页仍是 iframe 页面，组件级原生化留到后续；
- 任务定义与执行台账仍是两个语义层（定义在 auto-tasks.json，执行在 work-tasks/）。
