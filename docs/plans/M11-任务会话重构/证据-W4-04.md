# W4-04 证据：管家团队页迁移

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified（结构化 Task 状态驱动员工卡；TaskEvent 时间线后续细化）**

## 1. 目标测试

```powershell
cd app
npx playwright test tests/e2e/m11-team-task-state.spec.mjs tests/e2e/m5-staff.spec.mjs --reporter=line
```

结果：`3 passed`。

覆盖：

- 结构化 Task 的 `running` 状态把对应员工卡切到「在忙」，显示当前任务名；
- 结构化 Task 的 `waiting_user` 状态把对应员工卡切到「在等你」；
- `writer` / `editor` / `operator` / `publisher` 角色分别映射到文案、后期、运营、发布页员工卡；
- 右上角员工统计跟随真实卡片状态显示「1 在忙」「1 在等你」；
- 取消任务后，员工卡恢复原始状态；
- 原有基于内核实时工具事件的员工状态回归继续通过；
- 页面无 JS 错误。

## 2. 实现

- 团队页读取 `window.jco.tasks.sessions()`，只消费带 `structured: true` 的统一任务台账记录；
- 只把 `running` / `waiting_user` 两类活动任务映射到员工卡，不把旧任务或已完成任务冒充为忙碌；
- 订阅 `window.jco.kernel.onTask`，任务状态变化时立即刷新，并保留 3 秒轮询兜底；
- 任务取消或离开活动状态后，恢复页面原有的徽章、类名和活动文案；
- 既有 `kernel.onActivity` 实时工具事件逻辑保留，未阻断 M5 员工动作回归。

## 4. 已知边界（不虚报）

- 员工卡当前由结构化 Task 状态和 `kernel.onTask` 刷新驱动，尚未渲染完整 TaskEvent 时间线；
- 轮询是事件丢失或遗漏时的兜底，不等同于持久化事件订阅；
- 旧的非结构化页面派活仍只保留原有活动事件显示，不在本轮冒充结构化任务；
- 团队页仍是 iframe 页面，组件级原生化与任务详情直达留到 Wave 5 全站巡检。
