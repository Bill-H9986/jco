# W1-03 证据：任务卡 + 独立任务详情 + Approval

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标 E2E

```powershell
cd app
npx playwright test tests/e2e/m11-task-card.spec.mjs
```

结果：`1 passed`。

覆盖：

- 首页发送“帮我把这条视频发到抖音”后，AI 回复旁出现任务卡草稿；
- 任务卡出现时，Task 数量不变；
- 任务卡明确写着“确认前不会创建 Task”，草稿可编辑；
- 点击“确认派活”后进入壳内独立任务详情 `#/task/<id>`；
- 详情显示目标、输入、约束、交付物、任务时间线；
- 发布任务进入“等你确认”，审批原因和“确认继续 / 拒绝并取消”可见；
- 用户确认后状态变为“执行中”，审批项消失；
- 返回对话回到来源会话；
- 任务详情不是聊天流中的一条消息。

## 2. 实现

- `main.js` 新增加结构化任务台账 `kernel/work-tasks/`；
- 新增 `tasks:propose` / `tasks:confirm` / `tasks:approval` / `tasks:cancel` IPC；
- `preload.cjs` 暴露对应受控 API；
- 总管页新增任务卡草稿、自动意图提示、手动“派活”按钮；
- 应用壳新增原生任务详情视图，不再把任务塞进聊天 iframe；
- 任务卡确认前不创建 Task、不启动浏览器；发布类任务确认后进入审批门；
- E2E 数据护栏扩展到 `work-tasks/`，测试创建的临时任务在用例结束后清理。

## 5. 已知边界（不虚报）

- W1-03 的任务卡/详情/审批是结构化闭环；真正的发布浏览器执行要等 W3-01/W3-04，批准后状态为“执行中”，不会假装已经点了发布；
- 任务卡自动提案目前是本地意图识别，不依赖模型额外返回结构化协议；W1-05 接真实内核时再收口到统一 TaskCard 事件；
- 任务详情目前是应用壳原生视图，未做完整视觉基准（W5-02 补）；
- T-03 状态机单元和 T-06 审批门由现有状态机/IPC 测试与本 E2E 共同覆盖；T-05 失败重试验证仍归后续任务执行单元。
