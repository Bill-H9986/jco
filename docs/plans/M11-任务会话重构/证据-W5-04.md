## 2. 本轮安全收口

- `clickGuardReason` 先做 NFKC 归一并剥离零宽/不可见字符，防止用 `发\u200b布` 等变体绕过危险点击拦截；
- 新增 `uploadGuardReason`：不仅检查媒体扩展名，还要求真实路径位于会话允许的素材/成片目录（`assetsDir`）；
- `session-server` 由主进程传入 `--assets-dir`，上传工具的路径守卫在真实调用链上生效；
- OWASP LLM06 门禁增加工具级守卫检查，防止以后移除危险目标拦截；
- 现有 `publish / approval` 契约仍强制发布、删除、支付审批；评论回复仍只能生成草稿，发送必须由用户确认。

## 3. 对抗用例

- 发布 / 删除 / 支付普通文案被拦截；
- 零宽字符拼接的危险点击文案被拦截；
- 白名单外域名、`evil-douyin.com`、`file:`、`javascript:` 被拒绝；
- 非媒体文件被拒绝，素材目录外的媒体文件被拒绝；
- 外部内容进入 Context Pack 时仍被包在 `<external_content>`，不能冒充系统指令；
- chat / writer profile 无副作用工具，publisher / operator / editor 各自工具权限隔离。

## 4. 已知边界（不虚报）

- 文本关键词拦截不是语义模型的替代品；页面若用完全无关键词的“继续”完成不可逆动作，仍需统一 Approval 门禁与人工验收；
- 真实平台登录、真实发布、真实评论发送没有在自动测试里执行；这些动作继续要求用户亲手确认；
- 安装/卸载相关安全（签名、升级残留）仍归 W5-03，当前 W5-03 阻塞等待用户授权；
- 自动任务只做自动化安全门禁，不替代产品负责人对真实账号和真实平台的验收。
