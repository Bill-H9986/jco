# W3-01 证据：发布页任务化 + Approval

- 日期：2026-10-18
- 环境：Windows · `work/jco-beta` · `beta/0.6.0`
- 结论：**verified**

## 1. 目标 E2E

```powershell
cd app
npx playwright test tests/e2e/m11-publish-task.spec.mjs
```

结果：`1 passed`。

覆盖：

- 发布页从统一 `drafts.json` 找到已落盘成片；
- 点击“开始准备发布”后，经 `tasks.propose` + `tasks.confirm` 创建 publish 任务；
- 任务进入 `waiting_user`，存在 `type=publish` 的待审批项；
- 任务目标包含平台、视频路径和“绝对不要点发布”；
- 拒绝审批后任务变为 `cancelled`，不会启动真实发布会话；
- 不再写入假的 `jco-publish-v1` 预演记录。

## 2. 实现

- 删除发布页的模拟进度和“预演完成”记录；
- 主按钮改为“开始准备发布”，AI 入口改为“让 AI 准备「平台」发布”；
- 发布页通过 `tasks.propose` + `tasks.confirm` 创建任务，再跳到独立任务详情；
- 多平台一次选择会为每个平台创建一个 publish 任务；
- 发布任务审批通过后，`runWorkTask` 先确保对应发布会话就绪，再交给 publisher；
- publisher 完成后任务进入 `waiting_user`，事件明确写“请你在浏览器里亲手点发布”；
- 发布页读取成片改为统一 `drafts.json`，AI 配标题/话题也读统一草稿；
- 既有 `clickGuardReason` 继续在工具层拦截“发布/删除/支付”类点击，安全不只靠提示词。

## 3. 门禁

```text
npm run gate: 164 unit / 43 E2E / 2 visual baselines / 15 页审计 / OWASP / Agent Eval 全绿
```

## 4. 已知边界（不虚报）

- E2E 走到审批并拒绝，没有真实启动平台浏览器或模型发布；
- 任务准备完成后会停在 `waiting_user`，用户手动点发布后还没有“标记已发布”的回写动作；
- 账号中心登记仍是 `jco-login-v1`，迁统一 store 属于 W3-03；
- 平台适配层和真实浏览器发布属于 W3-04；
- 多平台会生成多个任务，当前只自动打开第一个任务详情。
