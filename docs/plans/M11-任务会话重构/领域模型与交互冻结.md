# M11 领域模型与交互冻结

- 日期：2026-10-17
- 状态：待产品负责人确认后冻结
- 关联：`立项单.md`、`技术方案.md`、`接口契约.md`、`验收用例.md`

## 一、设计原则

1. **会话只负责对话，任务只负责执行。**
2. **自动任务是计划，不是第二套执行系统。**
3. **员工角色负责“怎么干”，任务卡负责“干什么”。**
4. **浏览器是任务资源，不是聊天默认动作。**
5. **所有副作用必须可追踪、可停止、可恢复。**
6. **行业、平台、语气从配置读取，不写死在代码里。**
7. **细节必须可验证，不靠人眼兜底。**

## 二、统一语言

| 术语 | 含义 | 不要混用 |
|---|---|---|
| 会话 / Conversation | 用户与助手的对话线程 | 不是任务 |
| 消息 / Message | 会话中的一条用户或助手消息 | 不是任务事件 |
| 任务 / Task | 一张可执行工作单 | 不是聊天记录 |
| 执行 / TaskRun | 任务的一次实际运行 | 不是任务本身 |
| 任务事件 / TaskEvent | 执行过程中的状态、工具、审批、产物事件 | 不是聊天消息 |
| 自动任务 / Automation | 按计划创建任务的模板 | 不是第二套任务 |
| 员工角色 / AgentRole | 一类岗位的职责、技能、工具和提示词 | 不是聊天人格 |
| 浏览器会话 / BrowserSession | 平台浏览器的可复用资源 | 不是任务 |
| 产物 / Artifact | 文件、草稿、报告、封面等结果 | 不是日志 |
| 审批 / Approval | 需要用户拍板的检查点 | 不是普通提示 |

## 三、核心对象

### 3.1 Conversation

```ts
type Conversation = {
  id: string
  title: string
  messages: Message[]
  model: string
  createdAt: number
  updatedAt: number
  archivedAt?: number
}
```

不变量：

- 一个会话至少有一条消息，或是当前唯一允许存在的空会话；
- 消息按时间正序保存、正序渲染；
- 消息内容不截断；
- 会话不持有浏览器会话、任务执行状态；
- 删除会话不删除由它创建的任务，只解除 `sourceConversationId` 的展示关联。

### 3.2 Message

```ts
type Message = {
  id: string
  conversationId: string
  role: 'user' | 'assistant' | 'system'
  content: string
  format: 'plain' | 'markdown'
  createdAt: number
  status: 'complete' | 'streaming' | 'failed'
  error?: string
  model?: string
  usage?: { inputTokens?: number; outputTokens?: number }
}
```

不变量：

- 用户消息和助手消息分开存；
- 流式消息完成后必须落最终文本；
- 失败消息保留错误摘要和重试入口；
- 不允许用 2000 字硬截断；
- `system` 只用于调试/审计，不显示在普通聊天流里。

### 3.3 Task

```ts
type Task = {
  id: string
  title: string
  goal: string
  type: 'content' | 'publish' | 'operate' | 'edit' | 'research' | 'custom'
  ownerRole: string
  status: TaskStatus
  inputs: TaskInput[]
  constraints: string[]
  deliverables: string[]
  approvalPolicy: ApprovalPolicy
  sourceConversationId?: string
  sourceAutomationId?: string
  parentTaskId?: string
  createdAt: number
  updatedAt: number
}
```

不变量：

- 没有目标、产出和审批策略，不允许进入 `queued`；
- 任务不是消息容器；任务详情通过 `TaskEvent` 展示过程；
- 一个任务可以有多次 `TaskRun`；
- 任务标题可以编辑，但不会改变历史事件；
- 任务完成必须有产物或明确的“无需产物”结果。

### 3.4 TaskRun

```ts
type TaskRun = {
  id: string
  taskId: string
  status: 'queued' | 'running' | 'waiting_user' | 'done' | 'failed' | 'cancelled'
  startedAt?: number
  endedAt?: number
  error?: TaskError
  attempt: number
}
```

不变量：

- 同一任务同一时刻最多一个 running 的 TaskRun；
- 重试创建新的 TaskRun，不覆盖旧的；
- 取消后不再产生新的副作用；
- 失败必须记录失败步骤和下一步建议。

### 3.5 TaskEvent

```ts
type TaskEvent = {
  id: string
  taskId: string
  runId: string
  type:
    | 'state_changed'
    | 'plan_ready'
    | 'tool_call'
    | 'tool_result'
    | 'approval_requested'
    | 'approval_resolved'
    | 'artifact_created'
    | 'note'
    | 'error'
  at: number
  summary: string
  data?: Record<string, unknown>
}
```

不变量：

- 事件只追加，不修改历史；
- 不把完整工具参数、密钥、登录态写进事件；
- 用户能看懂 `summary`，技术细节放 `data` 供诊断；
- 任务详情按事件时间线展示。

### 3.6 Automation

```ts
type Automation = {
  id: string
  name: string
  enabled: boolean
  schedule: { kind: 'daily' | 'weekly'; time: string; weekday?: number }
  taskTemplate: {
    title: string
    goal: string
    type: Task['type']
    ownerRole: string
    inputs: TaskInput[]
    constraints: string[]
    deliverables: string[]
    approvalPolicy: ApprovalPolicy
  }
  lastRunAt?: number
}
```

不变量：

- Automation 只创建 Task，不直接执行；
- 同一计划时刻只创建一个任务实例；
- “马上跑”也创建一个 Task，走同一台账；
- 自动任务产生的 Task 必须出现在总管任务区。

### 3.7 AgentRole

```ts
type AgentRole = {
  id: string
  name: string
  description: string
  skills: string[]
  allowedTools: string[]
  promptProfile: 'publisher' | 'editor' | 'writer' | 'researcher' | 'operator'
}
```

不变量：

- 聊天助手不是 AgentRole；
- 发布角色不能拿文件写入/shell 工具；
- 后期角色不能拿发布浏览器工具；
- 角色提示词由任务卡 + 技能 + 平台规则组成，不写死行业。

### 3.8 BrowserSession

```ts
type BrowserSession = {
  id: string
  platform: string
  profile: string
  endpoint: string
  token: string
  status: 'starting' | 'ready' | 'busy' | 'stopped' | 'failed'
}
```

不变量：

- 只能由 Application 层在任务需要时申请；
- 纯聊天不能直接访问；
- 同一平台同一 profile 同时最多一个活跃会话；
- token 只在本机内存/受控文件里，不进日志、不进任务事件。

### 3.9 Artifact

```ts
type Artifact = {
  id: string
  taskId?: string
  conversationId?: string
  kind: 'text' | 'image' | 'video' | 'audio' | 'file' | 'report'
  path?: string
  content?: string
  mime?: string
  createdAt: number
}
```

不变量：

- 文件产物必须落在受控目录；
- 产物必须可预览/可定位；
- 不覆盖原文件；
- 产物和任务/会话解除关联后不自动删除文件。

### 3.10 Approval

```ts
type Approval = {
  id: string
  taskId: string
  runId: string
  type: 'publish' | 'delete' | 'payment' | 'login' | 'choose' | 'confirm'
  reason: string
  options: Array<{ id: string; label: string; danger?: boolean }>
  status: 'pending' | 'approved' | 'rejected' | 'expired'
  createdAt: number
  resolvedAt?: number
}
```

不变量：

- 发布、删除、支付必须创建 Approval；
- Approval 未解决时任务只能是 `waiting_user`；
- 过期/取消后任务不能继续执行危险步骤；
- 审批结果进入 TaskEvent。

## 四、任务状态机

```text
draft
  └─ submit → pending_confirm
        ├─ reject → cancelled
        └─ approve → queued
              └─ start → running
                    ├─ request approval → waiting_user
                    │       ├─ approve → running
                    │       └─ reject → cancelled
                    ├─ complete → done
                    ├─ fail → failed
                    └─ cancel → cancelled
```

状态定义：

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `draft` | 任务卡草稿 | 编辑、删除、提交确认 |
| `pending_confirm` | 等用户确认任务卡 | 确认、拒绝、修改 |
| `queued` | 已确认，等待执行 | 取消、查看 |
| `running` | 正在执行 | 取消、查看过程 |
| `waiting_user` | 等审批/登录/选择 | 批准、拒绝、补充信息 |
| `done` | 完成 | 查看产物、复制、再开一个 |
| `failed` | 失败 | 查看错误、重试、取消 |
| `cancelled` | 已取消 | 查看历史、复制重开 |

## 五、领域事件

```text
ConversationCreated
MessageAppended
MessageCompleted
MessageFailed
TaskDraftCreated
TaskSubmitted
TaskConfirmed
TaskQueued
TaskStarted
TaskWaitingForUser
TaskApproved
TaskRejected
TaskCompleted
TaskFailed
TaskCancelled
TaskRetried
ArtifactCreated
AutomationTriggered
AutomationTaskCreated
```

用途：

- 事件用于任务时间线、通知、审计和测试；
- 领域事件不是聊天消息，不进入会话上下文；
- 事件必须可重放，重放不能重复产生副作用。

## 六、交互冻结

### 6.1 首页

```text
┌──────────────────────────────────────────────┐
│ J.Co 首页                                    │
│ 今天想做什么？                               │
│ ┌──────────────────────────────────────────┐ │
│ │ 说一句话，开始一个新会话……               │ │
│ └──────────────────────────────────────────┘ │
│ [发送]  [派活]                               │
│                                              │
│ 快捷：做一条视频 / 写一篇文案 / 看数据       │
└──────────────────────────────────────────────┘
```

规则：

- `发送` = 创建新会话并发送；
- `派活` = 打开任务卡草稿，不直接执行；
- 快捷卡片只填充输入或打开页面，不直接产生副作用；
- 首页不启动浏览器。

### 6.2 聊天页

```text
┌──────────────┬───────────────────────────────┐
│ 侧栏          │ 会话标题          [⋯]        │
│ 对话          │                               │
│ · 会话 A      │ 用户消息（右）               │
│ · 会话 B      │                               │
│ 任务          │ AI 消息（左，平坦正文）       │
│ · 任务 1      │                               │
│               │ [复制] [引用] [派活]          │
│               ├───────────────────────────────┤
│               │ 输入框（固定底部）            │
└──────────────┴───────────────────────────────┘
```

规则：

- 消息从上往下；
- 输入框固定底部；
- 任务不出现在聊天消息流里；
- “派活”会生成任务卡，不直接执行；
- 历史操作在标题 `⋯` 菜单。

### 6.3 任务卡

```text
┌──────────────────────────────────────────────┐
│ 任务卡：给这条视频写发布文案                 │
│ 目标：写 3 版标题 + 话题 + 封面建议          │
│ 输入：视频文件 / 账号定位 / 平台             │
│ 产出：标题 3 版、话题、封面建议              │
│ 约束：不夸大承诺；不自动发布                 │
│ 审批：发布前必须我确认                       │
│ [确认派活] [修改] [取消]                     │
└──────────────────────────────────────────────┘
```

规则：

- 任务卡是任务创建的唯一入口；
- 用户确认后才创建 Task；
- 任务卡字段可以编辑；
- 缺少目标/产出/审批策略时不能提交。

### 6.4 任务详情页

```text
┌──────────────────────────────────────────────┐
│ 任务标题                    [状态徽标]       │
│ 负责人：发布员工    创建：10:32    来源：会话│
├──────────────────────────────────────────────┤
│ 目标 / 输入 / 约束 / 产出要求                │
├──────────────────────────────────────────────┤
│ 时间线                                       │
│ 10:32 任务已确认                             │
│ 10:33 正在打开平台页面                       │
│ 10:35 标题和话题已填好                       │
│ 10:36 等你确认发布                           │
├──────────────────────────────────────────────┤
│ 产物：封面.png / 标题.txt                    │
│ [确认发布] [取消任务] [重试]                 │
└──────────────────────────────────────────────┘
```

规则：

- 任务详情独立页面，不塞进聊天流；
- 状态、时间线、产物、审批按钮始终可见；
- 过程行用人话，不展示密钥和完整工具参数；
- 失败时有错误摘要和下一步。

### 6.5 侧栏

```text
对话
  · 会话标题           最后更新
任务
  · 任务标题   [执行中]
  · 任务标题   [等你确认]
  · 任务标题   [完成]
```

规则：

- 对话和任务视觉上分开；
- 任务项显示状态徽标；
- 点击对话进会话，点击任务进任务详情；
- 自动任务产生的任务也在这里。

## 七、消息组件冻结

详见 `细节任务卡-聊天消息.md`，核心规则：

- AI 消息左对齐、平坦正文、头像 + 名字；
- 用户消息右对齐气泡；
- 阅读宽度 720–760px；
- 字号 14.5px、行高 1.7；
- 段落、列表、引用、代码块、链接完整渲染；
- 消息完整保存，不截断；
- 复制/引用/派活/删除可用；
- 空态、加载、错误、长文本、深浅色、1280/1440 都要验。

## 八、冻结结论

本文件确认后，以下规则不再在施工中临时更改：

1. 首页发送 = 新会话；
2. 派活 = 显式任务卡确认；
3. 纯聊天不启动浏览器；
4. 任务详情独立于聊天；
5. 自动任务与派活共用任务台账；
6. 行业由 BrandProfile 提供，不写死；
7. 发布/删除/支付永远人工确认；
8. 细节按 D0–D4 验收。

需要变更以上任一条，走变更单，不在施工中直接改。
