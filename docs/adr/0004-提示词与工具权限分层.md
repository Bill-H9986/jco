# ADR-0004：提示词与工具权限分层

- 日期：2026-10-17
- 状态：已采纳（M11 Phase 0）
- 关联：`app/kernel/bridge.mjs`、`docs/AI员工方法论与系统提示词规范.md`

## 背景

当前 `bridge.mjs` 把整段 `CHAT_SYSTEM` 拼进用户输入，并且聊天、派活、自动任务共用这套提示词。`CHAT_SYSTEM` 同时包含：

- 行业身份；
- 聊天语气；
- 安全铁律；
- 浏览器发布步骤；
- 数据边界；
- 技能说明。

同时，浏览器工具和后期工具 patch 对所有会话常驻挂载。

结果：

- 总管一开始就自报“成人学历提升招生”；
- 纯聊天也可能启动浏览器；
- 任务没有独立岗位提示词；
- 工具权限无法按角色收口。

## 决策

1. **提示词分层**：
   - BasePrompt：语言、诚实、安全、工具原则；
   - BrandProfile：行业、受众、语气、平台、目标、禁用表达；
   - ProfilePrompt：chat / publisher / operator / editor / writer；
   - TaskCard：仅任务；
   - Skills / PlatformRules：仅相关任务；
   - ExternalContent：明确标记为资料，不是指令。
2. **角色分池**：
   - `ChatHarness`：无浏览器/编辑/文件写入工具；
   - `PublisherHarness`：浏览器工具；
   - `OperatorHarness`：浏览器 + 数据工具；
   - `EditorHarness`：ffmpeg 工具；
   - `WriterHarness`：无副作用工具。
3. **不再把系统提示词拼进用户消息**：
   - DSH SDK 的 `RunOptions` 没有 `system` 字段；
   - Phase 1 用按 profile 独立的 `DeepSeekHarness` 实例，通过 profile/patch 注入；
   - 后续若 DSH 提供 per-session system prompt/persona，再合并池，不改 Domain。
4. **工具白名单按 profile 生成**：
   - chat 不包含 `jco_open_page`、`jco_click`、`jco_upload_file`、ffmpeg 工具；
   - publisher 不包含 shell/任意文件工具；
   - editor 不包含浏览器发布工具；
   - 任何 profile 都不能绕过 Approval 发布/删除/支付。
5. **会话命名空间**：
   - `chat:<conversationId>`；
   - `task:<taskRunId>`；
   - 避免聊天和任务会话串上下文。

## 后果

正面：

- 系统提示词不再写死行业；
- 聊天和任务行为边界清晰；
- 工具权限可测试；
- 任务可以用岗位提示词和技能。

代价：

- Phase 1 需要维护多个 Harness 实例；
- 每个实例有启动/内存成本；
- 需要新增工具白名单契约测试；
- 需要确认 DSH patch 配置能正确禁用/启用对应工具。

## 降级

- Phase 1 只启用 `chat` 和 `task:publisher` 两个 pool；
- 其它角色先复用通用 task profile，Phase 2 再拆；
- Harness 空闲超时回收。

## 验收

- P-01 ~ P-04；
- `check:no-chat-browser-tools`；
- `check:no-hardcoded-industry`；
- 真实内核聊天不启动浏览器。
