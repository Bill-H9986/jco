# ADR-0005：统一任务台账与状态机

- 日期：2026-10-17
- 状态：已采纳（M11 Phase 0）
- 关联：`docs/plans/M11-任务会话重构/领域模型与交互冻结.md`

## 背景

当前存在两套执行记录：

- 自动任务：`runAutoTask()` → `auto-runs.json`；
- 页面派活：`runDispatchedTask()` → `task-sessions/*.json`。

后果：

- 自动任务不出现在总管任务区；
- 同一件事在不同页面状态不一致；
- 通知、重试、取消、审批各写一套；
- 测试无法覆盖统一生命周期。

## 决策

1. 引入统一 `Task`、`TaskRun`、`TaskEvent`。
2. `Automation` 只保存计划模板，到点创建 `Task`。
3. 页面派活、聊天任务卡确认、自动任务、马上跑，全部走同一 `TaskService`。
4. 任务状态机：

```text
draft → pending_confirm → queued → running
  → waiting_user → running → done
  → failed → (retry: new TaskRun)
  → cancelled
```

5. 所有过程写 `TaskEvent`，只追加，不覆盖历史。
6. 任务详情从统一台账读取，不再从聊天消息流或 `auto-runs.json` 拼接。
7. 发布/删除/支付进入 `Approval`，任务在 `waiting_user` 等待。

## 后果

正面：

- 自动任务和派活状态一致；
- 通知、重试、取消、审批只实现一次；
- 任务详情、侧栏、团队页、通知共享同一事实源；
- 测试可以用同一组状态机用例覆盖所有入口。

代价：

- 需要迁移旧 `auto-runs.json` / `task-sessions/*.json`；
- 需要重写自动任务和派活的执行入口；
- 需要新增 TaskService / TaskRunner / ApprovalService。

## 不采用的方案

- 保留两套台账，只在 UI 合并：状态仍会分叉。
- 让自动任务直接写 `task-sessions`：只是把分叉换个文件，生命周期仍不统一。
- 继续把任务视图塞进聊天：无法表达状态机、审批和产物。

## 验收

- T-03、T-04、T-05、T-06、A-01、A-02；
- 自动任务与派活同列表；
- 重试创建新 TaskRun；
- 任务事件只追加。
