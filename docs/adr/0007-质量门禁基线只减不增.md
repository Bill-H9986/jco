# ADR-0007：质量门禁基线只减不增

- 日期：2026-10-18
- 状态：已采纳（M11 W0-06）
- 关联：`app/scripts/check-all.mjs`、`app/scripts/checks/`、`docs/plans/M11-任务会话重构/证据-W0-06.md`

## 背景

M11 的 6 个 `no-*` 扫描门禁面对的是历史欠账：旧 `jco-*` localStorage 147 处、行业写死 83 处、直派活 6 处、重复侧栏 15 处、长文本截断 4 处。

如果一开始就 `--strict`，`npm run gate` 会长期红，后续每个工作单元都无法通过门禁；如果完全不接门禁，新违规又会被无声放过。

## 决策

1. 建立 `app/scripts/checks/baseline.json`，只记录**当前存量**违规。
2. 违规指纹 = 规则 + 文件 + 违规文本；不含行号，移动代码不会让基线失效。
3. `npm run gate` 使用 `--baseline`：存量放行并打印数量，新增违规退出 1。
4. `--strict` 忽略基线，要求全部清零；Wave 5 最终验收必须用 `--strict`。
5. `--update-baseline` 默认拒绝吸收新增违规；只有显式 `--force` 才允许扩大基线。
6. 修完旧违规后，用 `--update-baseline` 删除对应条目，基线只减不增。
7. 迁移进度、视觉基准在非严格模式下只报告；W5 分别用 `check:all-pages-migrated --strict`、`check:full-project-layers --strict`、`check:visual-regression-all --strict` 验收。

## 后果

正面：

- gate 从第一天起就能抓住新增问题；
- 存量欠账透明、可复核、可逐条删除；
- 不会为了“先让门禁绿”而假装修完。

代价：

- 基线文件需要随修复更新；
- W5 前必须专门做一轮清账；
- 基线数量本身不能当作完成度，只能当作欠账清单。

## 验收

- `npm run gate` 通过；
- 新违规会让 gate 退出 1；
- `--strict` 在存量未清零时失败；
- W5 时基线为空。
