# J.Co 会话交接协议

> 文档角色：**会话交接 / 上下文恢复协议**，不是开发流程。开发流程以《J.Co 软件开发工作流标准》v1.6 为准。

> 最后更新：2026-10-17
>
> 适用：新会话开工、长任务中途换人 / 换 Agent、上下文被压缩、用户问“我们做到哪了”。
> 目标：不依赖上一轮对话摘要中的“已完成”，每次都用当前仓库事实重新建立任务上下文。

---

## 一、新会话开工（固定顺序）

1. 读 `AGENTS.md`（编码与安全约束）。
2. 读 `docs/项目现状与风险清单.md`（版本、安装态、风险、当前事实）。
3. 读 `docs/项目认知索引.md`（模块 / 页面 / 数据的全局语义地图）。
4. 读 `README.md` 与 `docs/J.Co软件开发工作流标准.md`（历史与流程）。
5. 读当前里程碑设计包 / 变更单 / 台账。

然后核对：

```text
git log -1
git status --short
app/package.json 的 version
桌面安装版 exe 的 FileVersion
release 里最新安装包
```

**不要**跳过这些核对直接说“已经完成”“已经装机”“已经全真”。

---

## 二、上下文压缩后的恢复规则

当系统提示上下文已压缩，或你发现当前上下文缺少关键事实：

1. 把压缩摘要里的“已完成 / 全真 / 唯一 / 已修复”视为**未经证实**。
2. 重新读：
   - `AGENTS.md`
   - `docs/项目现状与风险清单.md`
   - `docs/项目认知索引.md`
   - 当前任务相关的源码 / 测试 / 设计冻结包
3. 重新核对 `git log -1`、`git status`、版本号和安装态。
4. 用当前代码和测试重新判断任务状态；不要沿用摘要中的结论。
5. 如果当前任务跨了阶段（例如从“实现”进入“封版”），重新确认验收标准与门禁。

对应 AOCI 的做法：上下文压缩后不把摘要索引当可靠认知，必须重新拉取完整 Overview 并确认交付；J.Co 当前用这套人工协议替代。

## 三、每次改动的固定闭环

```text
复述目标 + 假设 + 不做什么
  → 查先例 / 设计冻结（结构改动）
  → 先写会失败的测试（能写的话）
  → 实现
  → typecheck / unit / audit / E2E（按改动范围）
  → 更新项目现状与认知索引
  → 约定式提交
  → 打包 / 装机（交付批次）
  → 汇报“代码 / 安装版 / release / 计划”四个状态
```

结构改动必须先看 `AGENTS.md` 的全站一体、单一来源、产物隔离和交付五件事。

## 四、状态汇报模板

每次汇报至少分开写：

| 状态 | 含义 |
|---|---|
| 源码 | 当前 HEAD 里有什么 |
| 安装版 | 用户桌面打开的是哪个版本 |
| release | 哪个安装包已经构建、是否签名 |
| 计划 | 还没做 / 待拍板 / 下一批 |

示例：

```text
源码：0.4.17 + M10 壳（HEAD 4e6a01d）
安装版：0.4.16
release：0.4.17 已构建、未安装、未签名
计划：先修 P0 安全，再给发布页接真
```

---

## 五、当前已知的“容易跑偏点”

1. **README 不等于现状**：README 里有历史里程碑和旧承诺；以《项目现状与风险清单》和代码为准。
2. **“工具白名单”不等于“目标白名单”**：`jco_click` 仍能点发布按钮，详见 P0 风险。
3. **发布页账号状态是静态的**：不要根据发布页的“已登录”判断真实登录态。
4. **自动任务与派活不是同一套记录**：总管任务区目前只覆盖派活。
5. **设置项不都接线**：素材目录、发布前确认、任务通知仍有缺口。
6. **M10 壳是第一步**：首页入口、任务/对话刷新、通知跳转尚未闭环。
7. **安装版落后**：0.4.16 不等于 0.4.17 + M10。

---

## 六、何时升级为 AOCI 正式接入

只有试点证明以下四点后，才把 AOCI 写进正式工作流：

1. 新会话读索引能显著减少阅读和试错；
2. 源码变化后能稳定发现认知漂移；
3. 许可证、二进制分发、升级回滚可接受；
4. 不会与现有单一来源、台账、AGENTS/CLAUDE 规则产生第二事实源。

在那之前，保持：

- 《项目现状与风险清单》= 当前事实；
- 《项目认知索引》= 人类可读语义地图；
- 本协议 = 会话恢复步骤；
- AOCI = 在 `work/` 副本里试点，不进入用户端。
