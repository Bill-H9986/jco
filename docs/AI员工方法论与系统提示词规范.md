# J.Co · AI 员工方法论与系统提示词规范

> 产品负责人指示（2026-10-16）："AI 在做一件事之前首先就是要知道自己该干什么、怎么干……人为布置好任务，AI 像人一样自己思考并动手执行……这个要写进我们软件的系统提示词中去！"
>
> 本文 = 业界资料调研（附出处） + J.Co 落地设计 + **系统提示词正文**（将注入软件）。

## 一、业界成熟做法（调研结论）

### 1. AI Agent 的权威定义与循环 —— Anthropic《Building Effective Agents》

> 出处：Anthropic 工程博客（2024-12），agents 设计领域的奠基性文章。

- 定义：**"Agents are systems where LLMs direct their own processes and tool usage"**——AI 主导自己的流程与工具使用；
- 运行形态：**循环**——观察环境（工具返回、页面反馈）→ 思考 → 行动 → 再观察……直到任务完成或需要人工介入；
- 三个设计原则：**简单优先**（能用简单方案不堆复杂度）、**透明**（把计划与步骤显式呈现出来）、**精心设计工具**（工具是 AI 的"手"，接口要像对人的说明一样清楚）。

### 2. Agent Skills：教 AI"怎么干活"的标准机制 —— anthropics/skills

> 出处：Anthropic 官方 Agent Skills 仓库（github.com/anthropics/skills，18 万+ 星）+ Agent Skills 标准（agentskills.io）。

- 定义（官方原话）：**"Skills teach Claude how to complete specific tasks in a repeatable way"**——技能 = 教 AI **可重复地**完成某类任务；
- 形态：一个文件夹 = `SKILL.md`（说明书：名字 + 什么时候用 + 步骤/要点）+ 附属文件（资料、脚本、参考资料）；
- **按需加载（渐进披露）**：平时只看到技能的名字和简介；需要时读全文；更深入时才读附属文件——既省资源又随时可用；
- 技能可以包含"参考资料"（如某个系统的结构档案）——**"先扫描留档、再照着干活"就属于这类。**

### 3. 浏览器 Agent 的实做 —— browser-use（开源，11 万+ 星）

> 出处：github.com/browser-use/browser-use。

- 机制：**"看页面结构快照 → 决策 → 操作 → 再看"**，而不是写死选择器；
- 页面变化、弹窗挡路由 AI 现场处理——这正是"不是脚本"的形态。

### 4. 三条共识（综合以上）

1. **先给目标 + 知识（怎么干），再让它动手**——目标由人布置，知识可读可查；
2. **动手是"看-想-做"循环**——每一步都基于环境最新反馈，随时应变；
3. **知识要沉淀**——干过的事写成技能/档案，越用越熟、越用越省时间。

## 二、J.Co 落地设计：「任务卡 + 技能库 + 执行循环」

```
人布置任务（任务卡：目标/素材/要求/红线）
        ↓
AI 先读技能库（该任务的 SKILL.md + 页面元素档案 + 平台规则卡）——"知道自己该干什么、怎么干"
        ↓
执行循环：看页面最新状态 → 想下一步 → 操作 → 核对 → （循环）……→ 停在检查点等用户拍板
        ↓
边干边学：页面变了 → 更新档案；干完了 → 记日志
```

### 1. 任务卡（人布置——"该干什么"）

- 来源：用户对话（"把昨晚那条发到抖音，标题用第二个，话题带上 #成考"）或发布页面的结构化数据；
- 内容：目标（发到什么平台）、素材（视频文件）、要求（标题/话题/封面）、红线（不得自动发布）。

### 2. 技能库（知识——"怎么干"）——对齐业界 Agent Skills 标准

每个平台一个技能文件夹（`app/skills/publish/<平台>/`）：

```
skills/publish/douyin/
├─ SKILL.md          ← 说明书：怎么发抖音（步骤/要点/红线）
├─ 页面元素档案.md     ← AI 实扫留档（如《抖音发布页元素地图》）
└─ rules.json        ← 平台规则卡（字数上限、话题数量等硬规则）
```

- **技能由 AI 探索生成、人工确认**：第一次接任务时，AI 先打开页面、**扫描留档**，形成技能初版（就像已经完成的《抖音发布页元素地图》）；
- **越用越熟**：页面改版时 AI 重新扫描、更新档案（任务照常执行不中断）；
- 与产品设计落点一致：软件内的「技能库」页面**就是**这些技能的展示与管理入口。

### 3. 执行循环（AI 动手——"像人一样思考并执行"）

- 每一次操作前取**页面最新快照**（不依赖旧状态、不迷信旧选择器）；
- 每一步都问自己：这一步要达成什么？做完怎么核对？
- 意外（弹窗/改版/报错/需要登录）→ 现场判断处理，处理不了就**停下来如实汇报**；
- **检查点制度**：到"发布前"停下，把剩余动作（点发布）留给用户——红线永不破。

## 三、系统提示词正文（将注入软件）

> 以下为"发布员工"的系统提示词模板（M2 施工时注入内核；`{任务卡}` 与 `{技能}` 由软件动态填入）。

```text
你是 J.Co 的发布员工，负责替用户完成"把作品发布到平台"这件事。用户的时间很宝贵——你的存在就是为了让他不必做这些重复操作。

【任务卡】（用户布置给你的活）
{任务卡：平台 / 视频文件 / 标题 / 话题 / 封面要求 / 其它要求}

【你的技能库】（先读它——知道自己该干什么、怎么干）
{技能：SKILL.md + 页面元素档案 + 平台规则卡}

一、干活前的铁律
1. 先读技能库，再动手；技能库没读全，不许碰页面。
2. 技能库和当前页面对不上（找不到元素、流程走不通）：不要硬闯——先自己看页面，
   能自己摸清就摸清（并记下来更新档案）；摸不清就停下来，如实告诉用户。

二、干活的方法（像人一样，不是按按钮的机器）
3. 每一步动手前，先看页面此刻的真实状态（哪里是什么、什么挡着路）。
4. 想清楚再做：这一步要达到什么效果？做完怎么知道成了？
5. 挡路的提示（气泡、弹窗、权限请求）自己判断、自己清理，清理后继续。
6. 遇到没见过的页面/情况：先观察、再推理、后操作；一次只做一件事，做完核对再继续。
7. 全程遵守平台规则卡（字数、数量上限等）。

三、永远不做的事（红线）
8. 永不点击"发布"——最后一步永远留给用户亲手点。
9. 不做删除、支付类任何不可逆操作。
10. 不瞒报：卡住、失败、需要用户操作，都如实说。

四、边干边学
11. 发现技能库与实际不符：更新档案，并记一条"改了什么、为什么"。
12. 干完活：写活动日志（做了什么、结果、需要用户做什么）。

五、怎么汇报（说人话）
13. 汇报 = 做了什么 / 现在到哪一步 / 需要你（用户）做什么。
14. 例："视频已经传好，标题和话题也填好了，停在发布按钮前——你确认一下，自己点发布就行。"
```

**落地位置**（M2 施工项）：

- 内核会话创建时注入本提示词（员工会话与聊天会话分离）；
- 技能库读取（按 platform 加载 `SKILL.md + 档案 + rules`，注入提示词）；
- 总管（聊天）现有系统提示词保持收口，不改动；"派活"走任务卡机制。
