## 4. 安装、升级、卸载、回滚

当前 W5-03 标记为 `blocked`：真实安装/卸载会修改当前 Windows 用户的安装目录和注册表，尚未获得用户明确授权。

已确认的旧状态：

- 注册表卸载项：`J.Co 0.6.0-beta.1`；
- 登记的卸载器路径：`C:\Users\Jay\AppData\Local\Programs\J.Co\Uninstall J.Co.exe /currentuser`；
- 安装目录不存在；
- 用户数据目录 `C:\Users\Jay\AppData\Roaming\J.Co` 存在。

得到授权后按以下顺序执行，并在每一步记录版本、路径、进程、注册表和用户数据：

1. 备份 `C:\Users\Jay\AppData\Roaming\J.Co` 到独立目录；
2. 安装当前 NSIS 包，启动安装版，验证应用壳、首页、侧栏、真实内核；
3. 用 `0.5.0-beta.1` 与当前包做升级，验证版本、用户数据和卸载器；
4. 卸载，检查安装目录、注册表项、卸载器和用户数据保留策略；
5. 恢复备份，重新安装或回滚，确认数据可读。

未得到授权时，不运行安装器、不强制卸载、不清理注册表、不删除 `%APPDATA%\J.Co`。

1. W5-03 安装/升级/卸载/回滚仍未完成，受本机安装授权阻塞；不能把“打包冒烟通过”写成“安装版交付通过”。

3. 页面/视图矩阵仍为 `12/17 verified`；应用壳、首页、总管、任务详情、后期等仍有后续迁移项，不能宣称全站迁移完成。
4. 真实扫码登录必须用户亲手完成；目前只有抖音适配包，其他平台的真实发布适配仍需逐个实测。
5. 真实发布、评论发送、删除、支付、登录等不可逆动作仍走统一 Approval / 人工确认；自动测试不替代真实账号验收。
6. 视觉回归目前是 1440×900 浅色 17 张；深色、窄窗口、长文本和错误态视觉矩阵仍需扩展。
7. 浏览器点击拦截是关键词 + 可访问名称守卫，不是页面语义模型；语义伪装仍必须依赖审批和人工验收。

## 8. 故障排查顺序

1. 先看 `git log -1`、`app/package.json` 和 `npm run gate`，区分源码、打包版和安装版；
2. 运行 `npm run check:all` 看迁移基线和视觉基准是否漂移；
3. UI/E2E 失败时先看对应证据文件和 `test-results`，不要用修改基线掩盖失败；
4. 内核问题检查模型配置和真实内核 smoke；浏览器问题检查会话文件和白名单；后期问题检查 ffmpeg 和成片目录；
5. 需要安装/卸载、真实平台登录、真实发布或删除数据时，停下并写 `outputs\需要你处理.md`。
